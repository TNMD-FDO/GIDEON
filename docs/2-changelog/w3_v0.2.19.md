## Changes

This release implements general-turn ticket 05 under the plan `docs/1-plans/harness-service-door.plan.md`, spec §18.1, §18.5, §19.4 and §1.7, ADR-0045, and `docs/frontend-contract.md` §2 rows 4–6. The turn harness had two drivers and both read a stored chat through a signed-in frontend session, so nothing could run a case against a GIDEON service. It has a third now, and the release's real work is that a row means the same thing whichever door produced it.

- **The service door** (`--service`): one flag posts each case's tagged prompt to `gideon-api`'s `POST /v1/chat/completions` under the connection's key and the eval identity's forwarded headers, reads the whole body or the stream itself, and hands the text to the same classifier the two frontend modes use. Rows are `preconditions` → `door` → one per case → `summary` → `record`. No sign-in, no chat, no cleanup.
- **The transport is an exec into the service's own container**, `engine.call_engine`'s shape rather than a new one: `docker compose exec -T gideon-api` runs a fixed client under the image's interpreter, the client reads the key from the container's own secret mount, and the headers and body arrive on stdin. Neither service publishes a port, so a host process could not have reached either without one; more to the point, the key never enters the harness's process, an argument, a row, or a record (ARCHI §16). No rendered file changes and nothing is recreated.
- **The in-container client is a module, not a string constant** (`tools/turns/doorclient.py`, new, 329 lines): only `gideon/api` is mounted in the container, so it stands on the standard library alone — no `gideon`, no `tools`, no `yaml` — and the driver passes its source text to the interpreter as `-c`, the way `call_engine` passes `ENGINE_CURL_SCRIPT` to `sh -c`. Being a module, it is linted, typed, and unit-tested over a loopback fake service rather than being reviewed as a quoted blob. It trims the key file's line ending (a generated secret is written newline-terminated), refuses a missing or empty file with its own exit code, enforces its own deadline by socket timeout and overall bound so a harness-side timeout never abandons a client inside the container, and writes a line-delimited JSON envelope: a head line, the body or one line per `data:` payload with its offset, and a last line carrying the elapsed seconds or the failure named **by its exception class alone**. It never prints the key, and no failure line carries request or response text.
- **The host side** (`tools/turns/door.py`, new, 482 lines): the exec, the envelope's parse into a reply value, the identity headers, the request body, the mapping into the stored-message shape the classifier reads, and `probe()`. A non-zero exit, an unparsable envelope, a non-200 status, and a stream that ends without its marker are each a `Problem` with a content-free detail and a fix. `probe()` reads the models route through the same exec, so one failure up front — a down service, a rotated key — replaces N failed case rows.
- **The `withheld` check means the same thing through the door.** The mapping emits a reasoning `output` item exactly when the wire carried non-empty reasoning text — the whole message's reasoning field, or any reasoning delta — so a door row's `withheld` is true under the same condition as a stored chat's: no reasoning text reached the caller. That is what lets the door be the thing tickets 06–08 prove against.
- **General's instruction rides by default, and one flag drops it.** Every existing mode posts `GENERAL_PRESET_ID` and the frontend injects the preset's `params.system`; a direct caller gets the raw model (contract §1). The harness is the adapter (contract §2 row 4), so the door and the moved `--unfiltered` both send General's rendered instruction as the system message and the generator's served name as the model id. `--no-instruction` sends the user message alone, and is refused outside the two direct modes, where the frontend does the injecting.
- **The identity is the three headers the release's constants can fill**: `X-OpenWebUI-User-Name` (URL-quoted), `-Email`, and `-Role` from `EVAL_IDENTITY`, in contract §2 row 5's plain form. `-User-Id` and `-Chat-Id` are values only the frontend's database holds, and learning them would need the sign-in this door exists to remove. The relay forwards no caller header to the engine, so the engine never receives them; `--unfiltered` sends none.
- **A chat-less driver needed the run loop to stop assuming a session.** `TurnDriver` now declares two facts — the opening row's name and whether its turns keep chats — and `_run_cases` reads them: a chat-less run opens with a `door` row in place of `signin` and emits no `cleanup` row, because no chat can exist to clean up. `client` leaves the base protocol for the two frontend drivers, the only ones that hold one. `RunSpec` gains `service` and `instruction`, both recorded in `run.json`.
- **`--stream` changes the delivery, not the count.** `--service --stream` makes the case's one call streamed, every released prefix judged for a leak by `classify.stream_verdict` with the `leak@` suffix and `STREAM_LEAK_FAILS` exactly as `_replay`'s, and the final text classified. The guard counts cases × repeat × concurrent either way. `complete()` refuses a response whose media type does not match the requested mode **in either direction** — a code-review finding: a streamed request answered with a whole JSON body would otherwise have reached `stream_verdict` with no deltas and been reported stream-clean without a prefix ever being examined.
- **`--unfiltered` moves off the frontend onto the engine.** From the cutover the frontend's completion path is the service's, which judges every completion, so an unfiltered turn posted through the frontend would stop being unfiltered. `UnfilteredTurnDriver` stops subclassing `ApiTurnDriver` and calls `engine.call_engine` directly with the engine's key: no sign-in, no chat listing, no watch, no deletion. Its case rows, summary, offline judgement, and record's judgement are unchanged; it loses the `signin` row for `door`, the `cleanup` row, and the record's `watch` and `deletions`, and `UnfilteredTurn.watch` and `TurnRow.stored_deleted`/`stored_not_deleted` go with the mechanism. One behaviour ends with the move: the live outlet no longer sees an unfiltered turn, so it writes no `eval`-source `guardrail_trips` row — `on-box-proofs.md` §3's sentence saying it does is corrected here.
- **The delta parse gets one home.** `session.raw_stream` read the delta's reasoning and content fields inline; the payload-to-`(kind, text)` step is now one function `raw_stream` and the door's parse both call, so the field names the pinned engine uses are written once. `post_unfiltered` and `watch_chats` were orphaned by the move and are gone.
- **Every refusal is before the first exec.** `_service_refusal` beside `_unfiltered_refusal` turns away `--browser`, `--probe-inlet`, `--trust-ca`, and `--unfiltered`, each with its own fix line; a selected case the door cannot judge — a searched case, a case with a `sources` expectation, both of which read the frontend's own record — is refused before the first engine call, as `--unfiltered` already refuses a searched case. The direct modes' preconditions are root, the site file, no no-GPU marker, the rendered tree, `models.lock` for the served name, and, unless `--no-instruction`, the render inputs and General's rendered instruction. The eval password is not read in these modes. Case-level door failures now carry `Problem.fix` rather than a generic instruction to read a record that may not exist — the review's Minor finding.
- **Tests** (`tests/test_turns_door.py`, new, 953 lines; 24 new): the client over a loopback fake service on an ephemeral port, every wait bounded — whole and streamed, the bearer read from a planted newline-terminated key file and sent without the newline, the content type and the three headers as sent, the envelope's lines and offsets, a missing key file's exit, a refused connection and a deadline named by class alone. The driver over a fake `Host` computing the envelope from the request — streamed and whole rows and classes, a prefix-then-refusal classed `replaced` as the stored shape is, a leak failing the row, reasoning on the wire failing `withheld`, the exec argv carrying the key's *path* and never a value, a planted key and the three header values absent from every row, record, and `run.json`, the `door` row's failures, the absent `signin` and `cleanup` rows, the guard's count with and without `--stream`, every refusal before the first exec, and `--no-instruction`'s body. An AST tripwire holds `doorclient.py` to the standard library with a planted violation. In `tests/test_turns.py` the eleven `test_unfiltered_*` methods moved from the `Frontend` fake to a fake engine exec with their case rows held byte for byte, and **three chat-watch tests were retired with the mechanism they held** — `…sentinel_cleanup_and_foreign_chat`, `…partial_cleanup_names_undeleted_chat`, `…watch_failures_keep_completion_and_judgement` — a removal by the ticket's ruling, named here because a retired test should never be a silent one.
