**Code review**: `docs/3-code-review/CR_w1_v0.0.17.md` (Codex loop, 2 rounds -> APPROVED)

## Changes

- **Why a built image, and why now** (slice-0 ticket 16, filed while planning ticket 06): Postgres runs `archive_command` and, on a point-in-time restore, `restore_command` inside its own container, and the stock `postgres:18` image carries no pgBackRest — so §19.1's "installed in GIDEON's image, a separate service" cannot archive one WAL segment (spec bug (v), recorded on the ticket). The `postgres` service now runs a GIDEON-built derivative: `images/postgres/Dockerfile` is `ARG BASE` / `FROM ${BASE}` / one `apt-get install pgbackrest=${PGBACKREST_VERSION}` over the PGDG source the official image leaves in place; every version reaches it as a build argument, so the file embeds no pin. Backups themselves (the stanza, WAL archiving, `backup run`) stay ticket 06, which this release unblocks.
- **The built pin kind** (`gideon/host/images.py`): `images.lock` pins are now `MirroredImagePin` (`source` + `digest`, unchanged) or `BuiltImagePin` (`build`, `base`, `base_digest`, `build_args`, `watch`, `inputs_digest`, `digest`), one collect-all validator for every malformed shape (mixed shapes, an escaping `build` path, a bad `ARG` name, a secret-like name — a build argument becomes an image label, never a secret — an orphan `watch`, a non-https apt index, a multi-line value). `inputs_digest` is a sha256 over the base digest, the sorted build arguments, and the Dockerfile bytes; the hosted committed-lock contract recomputes it, so a lock whose inputs moved without a rebuild goes red on the hosted checks. A pin whose `digest` and `inputs_digest` are both `unbuilt` loads but renders, applies, and mirrors nowhere (each names the tool); the same contract refuses the sentinel in the committed lock, so it lives only in a working tree between writing the entry and the first build. `reference()` stays name + digest, so render, apply, and the contract stack took the built pin through unchanged code.
- **`python3 -m tools.imagebuild <name> [--to] [--check] [--dry-run]`** (`tools/imagebuild/`, a repository tool like the pin watch, stdlib + `yaml`, every `docker` call through the `Host` seam): probes the egress allowlist's new `image-build` group (`apt.postgresql.org`, `deb.debian.org` — probed by the tool, never by preflight, through the same proxy the build will use), builds from the release registry's mirrored base by digest with `--provenance=false --sbom=false`, OCI base labels and one `gideon.build-arg.<ARG>` label per input, runs the image's smoke command (`pgbackrest version` must print the pinned upstream version) *before* pushing, pushes, reads the pushed digest from `RepoDigests`, patches the lock's two digest paths value-only through the pin watch's patcher (reloaded by the product loader), regenerates the render fixtures, and restores file ownership after `sudo`. Proxy values reach the build only through the child's environment (`--build-arg NAME` with no value; Docker keeps those out of history), so a credential is never in argv or the dry-run row. `--check` proves the registry's image against the lock (digest present, labels equal the inputs, smoke passes); `tests/contract/built_images.py` runs it in the self-hosted `mirror-images` job after the mirror.
- **`registry mirror`** keeps a built pin's base in the same repository under its own tag (row `postgres/base: mirrored|present`, ensured even for an unbuilt pin so a first build on an empty registry can start), then reports the built digest `present` or `failed` naming the build; `apply`'s registry and pull stages verify it by digest as before.
- **The pin watch** watches a built pin twice, both as proposals it cannot complete: `images.postgres` (the base's newest same-shape tag and index digest) and `images.postgres.build_args.PGBACKREST_VERSION` (the newest `pgbackrest` stanza in the lock-declared PGDG `Packages` index, under Debian version ordering — the dpkg algorithm in `sources.py`). The state table gains `completed`: a branch that still carries exactly the proposal's values plus a human's rebuilt `digest`/`inputs_digest` is left alone, whatever `main` did since (the rebase is the human's at merge time); a completion for a superseded bump is `updated` with its old head named in the row so nothing is lost silently.
- **Live on the box** (`.scratch/slice-0/assets/16-apply-built-image.txt`): built, pushed, and recorded in one run; `--check` ok; mirror rows `postgres/base: present`, `postgres: present`; `apply` clean (Compose recreated the store tier from its own config diff — the recreate rule sees no owner for `compose.yaml`, a pre-existing shape noted on the ticket); `pgbackrest version` inside the running container prints 2.59.1; preflight 26 pass / 3 inert; a bare reconcile with no corrections. The pin watch's dry run reads `origin/main`, so its built-pin rows follow the push.
