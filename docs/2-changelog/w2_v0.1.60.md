## Changes

Inside a cycle's worktree the harness refuses any construct it cannot read as a plain command, so a `TRIP-3-release` session ran `git add -A`, the commit, and `git rebase main` as three commands, a `TRIP-1-plan` claim ran `git worktree add`, the `.venv` link, and `EnterWorktree` as three steps, and the first audit counted about ten refused-and-reissued turns per session, unchanged at the second (`assets/27-trip-delta-audit-and-phase-routing.md` §3, `assets/30-second-trip-audit.md` finding 6). The tracker carried two recorded debts beside it: `python3 -m tools.tracker` wrote the board and the page before printing a finding whatever the flags, so a gate run in a worktree regenerated `.scratch/BOARD.md` there and the release diff carried it until a restore (the `v0.1.48` observation), and both renderers built one five-cell row for every section, so the Frontier repeated the effort tables' status and blockers columns with every cell `ready-for-agent` and `none` (workflow ticket 19's triage observation). This release lands three small mechanisms in one cycle (workflow ticket 32, rulings a–f): two fixed scripts under `bin/`, the launcher's home and an excluded export prefix, in `bin/trip`'s idiom; the tracker's check mode and the Frontier's column set; and the documents pointing at the commands. No product code; nothing applies on the box.

- **The release's git tail** (`bin/release-git <message file>`): one argument, the commit message file CLAUDE.md's commit rule has the session write; the four refusals — the file missing, unreadable, or with an empty first line; a directory outside a work tree; the branch `main`; a rebase in progress — each `release-git: <problem>. Fix: <fix>` on stderr and exit 1 before any git command changes the tree, the last one mattering because `git add -A` during a conflict would mark every conflicted file resolved; the decision printed as one line — an amend when HEAD is not reachable from `main` and its subject starts with the file's type prefix (the first line up to and including its first colon), a commit from the file otherwise, so a `docs:` research-note commit on the branch gets the release commit on top and a renumbered subject still amends; then `git add -A`, `git commit -F <file>` or `git commit --amend --no-edit`, and `git rebase main`, each printed as `+ <argv>` before it runs, the script stopping at the first non-zero exit with that code and git's own text, a rebase conflict left in progress for `worktrees.md` §8's resolution. The branched part of the merge — the merge-base check, the renumber, a minor tag's evidence-commit reset — stays the session's; no flag (ruling b). This release's own commit is the script's first use.
