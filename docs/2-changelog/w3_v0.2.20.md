# Changelog - Week 3, 20-09-2026, V. 0.2.20

**Release Date**: Week 3, 20-09-2026 at 08:44
**Version**: 0.2.20 (previously 0.2.19)
**Object**: hotfix: v0.2.20 — the served name off the box's site file

## Changes

- **Issue**: `v0.2.19`'s CI run on `main` was red. Fourteen of that release's tests — thirteen in `tests/test_turns_door.py`, one in `tests/test_turns.py` — fail on any tree that does not have the box's `/etc/gideon/site.yaml`, which no runner, no clean clone, and no export archive has. CI stops after one failure, so its log named one of the fourteen.
- **Fix**: the generator's served name is derived from the committed `config/site.example.yaml` instead. That file is the text these modules' fakes already serve at `SITE_PATH`, so the assertion now reads the same site the run under test used — a correction, not a weakening. Three reads were involved: `_served_name()` in `tests/test_turns_door.py`, an inline copy of it in `test_whole_rows_body_and_classes_use_the_tagged_user_message` (now calling the helper), and the equivalent block in `tests/test_turns.py::test_unfiltered_posts_exact_body_and_records_the_whole_completion`. `SITE_PATH` stays what it is — the path the fakes serve at — and is not the path anything now loads from.
- **Root Cause**: `v0.2.19` needed the served name in an assertion for the first time, because the door and the moved `--unfiltered` send the model id in the request body where the frontend modes never did. Every other site read in these modules goes through the fake `Host`, which serves the committed example; the new assertions ran outside the fake and reached the real filesystem. It passed the release's gate because the box, where the gate ran, is the one machine that has the file.

**Reproduced and verified on the record.** The failure needs a tree without the box's site file, so it was reproduced in a private mount namespace with an empty tmpfs over `/etc/gideon` — nothing outside the namespace touched. Before the fix, in that namespace: 14 failed across the three turn modules. After it: the three modules green, and the **whole suite** green in the same namespace — `2056 passed, 6073 subtests passed`, exit 0 — so no other test in the tree depends on the box's site file either. The gate on the box: `green in 278.7s (ruff, mypy, pytest; all cases)`.

**Window**: none. No rendered file, pin, Compose block, or secret moves; the change is in two test modules. Nothing is applied and nothing users see is recreated.

**Release note**: `docs/release-notes/v0.2.20.md`. Nothing user-visible — a test-only fix.

**The human read** (ADR-0036, ADR-0044): does not apply. This is a patch tag before go-live, and the diff touches no path carrying user text or a refusal.

**Lesson, folded where it belongs**: `docs/archi/tools.md`'s line for `test_turns_door.py` now says the module derives the served name from the committed example, so the next assertion that needs a site fact has the rule beside the test it would otherwise copy.
