# Changelog - Week 1, 02-09-2026, V. 0.0.13

**Release Date**: Week 1, 02-09-2026 at 05:39
**Version**: 0.0.13 (previously 0.0.12)
**Object**: the pin watch: tools/pinwatch opens one pull request per lock-file bump from a weekly hosted workflow under an org GitHub App, a CI contract that no rendered service checks for its own updates, timeless lock comments (slice-0 ticket 10)
**Code review**: `docs/3-code-review/CR_w1_v0.0.13.md` (Codex loop, 2 rounds -> APPROVED)

## Changes

- **The pin watch** (ADR-0031; slice-0 ticket 10): `tools/pinwatch/` is a repository tool beside the product package — stdlib + `yaml`, importing the product's lock loaders and its `Host` seam — that resolves every `images.lock` and `host.lock` pin against upstream and keeps **one pull request per pin** open. Images resolve through the registry v2 API (anonymous bearer challenge, `Link` pagination, the OCI index digest by `HEAD`) to the newest same-shape tag (`2.11` → `2.12`, never `2.12.0-beta.1`; `18` never `19beta1`; `v0.11.0` → `v0.11.3`); the registry image the same way; the runner from GitHub's latest release with its sha256 read from the release-notes marker; Docker/Compose majors, the toolkit version, and the NVIDIA driver branch (from the CUDA apt `Packages` index) as **proposals** — `driver.tested` never moves; the acceptance-VM image from the Ubuntu cloud-image listing with its `SHA256SUMS` checksum. ADR-0031's named fallback (a scheduled workflow) was chosen over Renovate because three of these pins and slice 1's `models.lock` do not fit Renovate's managers.
- **A six-row state table, mechanical and tested**: every run makes exactly two read-only calls (one `git fetch` with the `pin-watch/*` refspec, one `gh pr list --state all`) and then judges each pin `current` / `opened` / `updated` / `unchanged` / `declined` / `closed`. A human closing a PR unmerged declines that exact bump until upstream moves again; a PR the watch closes itself is marked `[withdrawn]` so a withdrawn-then-republished release reopens; `unchanged` requires identical content, the current `main` parent, and an equal title, so a close that failed after its title edit self-repairs. A bump branch carries the lock patched value-only (quoting and comments preserved, reloaded by the product loader, refused unless only the bump's key paths changed) **and the render fixtures regenerated**, because the byte-stable fixtures embed both locks; a leading-component image change (Postgres `18` → `19`, whose `PGDATA` the Compose model pins) is a proposal that needs an upgrade plan and a product major (§2.1). Rows to stdout, a resolver or git/gh failure is one `failed` row with its fix and the run continues, exit 0 iff none failed; `--dry-run` makes the same reads and writes nothing.
- **`.github/workflows/pin-watch.yml`**: Monday 06:17 CST on `ubuntu-latest`, an installation token minted per run by `actions/create-github-app-token@v3` from an org-owned App (repository variable `PIN_WATCH_APP_CLIENT_ID`, secret `PIN_WATCH_APP_PRIVATE_KEY`; scoped to this repository, narrowed to contents + pull-requests write), the checkout authenticated with it, the App's bot as the git identity, `workflow_dispatch` with a `dry_run` input. The App is what makes bump PRs run the hosted checks (PRs from `GITHUB_TOKEN` never trigger CI); a merge runs the existing push-only `mirror-images` → `frontend-contract` chain, the §17.5 gate on every frontend pin bump; a human tags. The one-time App setup and the Monday review line are `.scratch/slice-0/assets/10-pin-watch-app-setup.md`.
- **No component checks for its own updates** (criterion 4): `tests/test_no_self_update.py` walks both rendered fixture projects and requires every service to have a registry entry with its switches off (`open-webui: ENABLE_VERSION_UPDATE_CHECK=false`; Caddy and PostgreSQL recorded as having none); an unregistered service fails, so vLLM, Qdrant, Grafana, and Loki must declare theirs before they render.
- **Lock files and loaders**: `images.lock`'s and `host.lock`'s comments no longer carry resolution dates or sub-tag claims (values byte-identical; both render manifests' `host_lock_sha256` regenerated); `gideon/host/images.py` and `gideon/host/lock.py` gain `parse_*`/`load_*_text` (the watch loads `origin/main`'s text, so a bump is patched onto the tip it is proposed against) and export `DIGEST`/`SOURCE_REFERENCE` so the watch reuses the product's grammar. CI's typecheck covers `tools`.
- **Records**: spec bug (u) on the ticket — §19.6's calendar gains "weekly: review open bump pull requests" and §2.2 names no watch; a follow-up for the GitHub runner, which `GhRunnerStep` registers without `--disableupdate` and which therefore updates itself against ADR-0031's "on the box" clause; `models.lock` and the release-note line deferred to slice 1 by the ticket's wording.
- **Live**: `python3 -m tools.pinwatch --dry-run` from the dev seat against the real upstreams (`.scratch/slice-0/assets/10-pin-watch-dry-run.txt`): 20 s, exit 0, `images.open-webui: would opened — v0.11.0 → v0.11.3`, `host.driver.branch: would opened — 595 → 610 (proposal)`, every other pin `current`. The dispatched run, the first PRs, and the frontend bump's merge follow on `main` (GitHub dispatches only a workflow that exists on the default branch) and are recorded on the ticket as CI evidence.
- **Tests**: 36 new (403 total, 112 subtests) — `test_pinwatch.py` (33) and `test_no_self_update.py` (3). Codex code review: 2 rounds; round 1's two Major findings (a truncated upstream body crashed the run; an empty NVIDIA index read as "current") and one Minor (command diagnostics) fixed with tests.
