## Changes

- **`gideon host provision` is real** (spec §1.5; slice-0 ticket 02): sixteen ordered check/apply step classes under `gideon/host/steps/` — `platform`, `egress-proxy`, `service-user`, `csa-accounts`, `disk-layout`, `nvidia-driver`, `nvidia-toolkit`, `docker-engine`, `firewall`, `time-sync`, `unattended-upgrades`, `secrets-dirs`, `backup-keypair`, `kvm`, `registry`, `gh-runner` — walked by a disposition-aware runner (`gideon/host/provision.py`): outcomes `ok/applied/would-apply/blocked/reboot-required/skipped/failed`, apply only on drift with re-check, declared prerequisite edges, `halts_run` on an unsupported platform, `--dry-run`/`--only` (check-only prerequisite closure)/`--list`, exit 0 iff nothing failed. Two-phase convergence: with no `/etc/gideon/site.yaml`, site-dependent steps report `blocked` with the fix; a present-but-invalid file refuses the run.
- **`host.lock` introduced** (repo root) with its loader/validator `gideon/host/lock.py`: OS pin, driver branch/repo (nullable `tested`), Docker/Compose/toolkit minimums, registry image digest, GH-runner release sha256, dated acceptance-VM image URL+sha256, and the [36] reference-host controller/VD facts. Every pin verified against its upstream at implementation time.
- **System-I/O seam** `gideon/host/sysio.py`: all host reads/mutations behind one injectable `Host` (subprocess, atomic writes, 127-on-absent-binary semantics); `site.py`/`site_schema.py` read through it.
- **Safety posture**: disk mutation only on a wipefs-confirmed blank or exactly-GIDEON device, positively identified (single candidate, WWN required, size class) and mutated via `/dev/disk/by-id/wwn-*`; sshd/ufw lockout guards; keypair never regenerated; keyring downloads atomic via `.partial`; provision-owned config in marker blocks or wholly-owned files.
- **Spec bugs recorded on the ticket** (never improvised around): (a) the host-provisioning egress-allowlist group omits docker.io and cloud-images.ubuntu.com; (b) §1.7's blanket 0440 breaks `backup_ssh_key` (0400 with a per-file mode table); (c) §1.2's R580 pin is uninstallable from the ubuntu2604 CUDA repo (starts at 595, verified live) — `host.lock` pins branch 595 via `nvidia-driver-pinning-595` + held `nvidia-open`.
- **Tests**: 51 new (73 total, 73 subtests) — runner semantics over fake steps, per-step truth tables, the disk-safety matrix with zero-mutation assertions, `host.lock` contracts, and ticket 28's post-reinstall baseline replayed as committed fixtures (`tests/fixtures/host/baseline-post-reinstall/`) asserting every step's recorded first-pass disposition.
- **Deferred**: the on-box converge (evidence for acceptance criteria 1–5 on the live box, `driver.tested` fill) follows post-release; recorded on the ticket.
