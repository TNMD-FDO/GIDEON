## Changes

This release implements general-turn ticket 03 under the plan `docs/1-plans/judge-as-the-shared-module.plan.md`, ADR-0045's ruling (b), the effort's prefactor. The arithmetic guardrail's judge leaves the Function's file for a `gideon` module that General's service and `/turn` can import. Nothing is applied on the box, and the running Filter is byte-for-byte what it was.

- **The module** (`gideon/guardrail.py`, new): the Function's top-level statements, in the Function's order, less the Function-only set, under the module's own docstring, with nothing renamed, retyped, or reordered. It carries the pattern families and their helpers, the judge's entries over a text, a rendered message, and a floor, `StreamState` and the lag window's check, the three family refusals with `REASONING_PLACEHOLDER`, `REFUSAL_SEPARATOR`, and `ERROR_PATTERN_ID`, and the trip's row with its writer. Imports at module level are standard library only; the Postgres driver stays imported inside `write_trip_row`. `pyproject.toml` exempts the module from the same three lint codes as the Function, until ticket 09.
- **The Function's file is untouched**: the Filter, its inlet's two gate texts, the stream hook, the outlet, and the task cancel stay in `compose/open-webui/functions/arithmetic_guardrail.py`, which remains the running mechanism until ticket 09. The render fixtures did not move.
- **The equality test** (`tests/test_guardrail_equality.py`, new, deleted with the Function at ticket 09): it parses both files as syntax trees without importing either, and holds that the module's statement sequence equals the Function's less the named Function-only set, statement by statement. It also holds that the Function's remaining names are exactly that set and that no name is bound twice in either file. A fourth test holds the list of files under `tools/`, `tests/`, and `gideon/` that name the Function's path, so a new by-path loader has to be a deliberate edit.
- **`engine verify`** imports the module. `_load_filter`, `_FILTER_FIX`, and the `module` parameter leave, and the `preconditions` ok row no longer names the guardrail Filter. The loader's two guards, a positive lag and a non-empty refusal tuple, are now assertions in `tests/test_guardrail.py`. The loader's own test left with it.
- **The turn harness** (`tools/turns/`): `cli.py` imports the module and threads it where the loaded Function went. `load_guardrail`, `_FILTER_RELATIVE_PATH`, and the load-failure `preconditions` row leave, and their test went with them. `_FIX` names `gideon/guardrail.py`. A gate-text loader over the kept `_load_function` reads `SESSION_REFUSAL` and `BRANCH_REFUSAL` from the Function's file only under `--probe-inlet`, and its failure is a `preconditions` row naming that file. `own_length` finds the stamp's file from the checkout root, not from `guardrail.__file__`.
- **The judge's tests** split by one rule: a test that drives the `Filter`'s hooks stays in `tests/test_arithmetic_guardrail.py` (61 tests), and every other test moves to `tests/test_guardrail.py` (67) with its assertions unchanged. That is 128 across the two files, against 126 before.
- **The bare-host boundary** (`tests/test_host_import_boundary.py`): a third named set holds `gideon/guardrail.py` to the entry chain's rule, standard library only at module level.
- **On the box** (`.scratch/general-turn/assets/03-on-box.txt`): the journal read found no other run. `sudo python3 -B -m gideon engine verify` from the worktree exited 0 with every row ok. The handful ran as one positive and one control of each family (deadline, Guidelines range, sentence credit) and every row was green: each positive declined, and the streams were clean with no leak. The sentence-credit control `rate-01` was the model's own decline, which is recorded, counted, and never gated.
