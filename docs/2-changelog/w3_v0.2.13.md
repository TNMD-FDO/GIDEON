## Changes

This release implements slice-1 ticket 86 under the plan `docs/1-plans/public-tree-never-names-the-development-repository.plan.md`. Ticket 79 (`v0.1.74`) took the files that only matter while GIDEON is being built out of the public export, but reworded each kept document that named a leaving file as a pointer at the place they went — so the export named it, 81 times across 26 files. This release removes every one of those outside six allowlisted changelogs, lets three build-time documents leave by the boundary, splits the front page into a public half and a private one, and lands a tripwire so the cleanup holds. Nothing the product runs changes; no site key and no `/etc/gideon` contract moves, so spec §2.1 asks for no minor.

- **The boundary gains five paths** (`tools/exportboundary.py`, `.gitattributes`, mirrored line for line as the attributes rule requires): `docs/archi/workflow-tools.md` and `docs/runbooks/pin-watch-app-setup.md`, which have no reader in the public tree; `docs/runbooks/ci-runner.md`, new; `tests/test_export_names.py`, excluded under ruling (e) because it names what it forbids; and `README.dev.md`, new, the maintainer's decision at the claim. The module's docstring now says the listed paths are omitted from the archive.
- **The runner runbook** (`docs/runbooks/ci-runner.md`, new): `office-services-setup.md` §6 moves whole — registration and its token, automatic updates off, the upgrade path and its deadline, the acceptance harness's one sudoers line, tag protection — and that file keeps §7's number, since its numbers are names and the README, `observability.md`, and the product's fix texts cite §3 and §7. Ruling (f): the hardening sentence's trigger is no longer a public flip ADR-0031 never named but the real one — the organisation's runner group admitting a public repository, which the default group refuses today, so the public repository never reaches the runner. `install-upgrade.md` §6 keeps the sudoers facts against the `gh-runner` provision step, says who may create a `v*` tag and that a ruleset guards the tags an office clones, and carries the CI record's two run ids as plain text; `pin-watch-app-setup.md` §5's one backlink and `tools/pinwatch/pr.py`'s citation follow the section. The pin watch's pull-request bodies keep naming both excluded runbooks — they are read where those files exist, so the strings are functional, not documentary (`tests/test_pinwatch.py` moved with one of them).
- **The map stops indexing a leaf the export omits** (`tests/test_archi_budget.py`, `docs/ARCHI.md`, `docs/ARCHI-rules.md`): `rule_index` splits the leaves by the boundary — a kept leaf is judged as before, an excluded one must have no §2 row and must be the resolved target of at least one inline link in `CONTEXT.md`, and a §2 row indexing an excluded leaf is a finding on the map. Where `CONTEXT.md` is absent — an export tree, which has no excluded leaf either — the rule has nothing to judge. The rules file states the contract once: a kept leaf is indexed from §2 and, when it owns commands, named in §8's table; an excluded leaf has neither row and is routed by the glossary's `_Leaf_` links. The excluded leaf stays budgeted and link-checked here.
- **One home per pointer** (`README.md`, `README.dev.md`, `tests/test_export_boundary.py`): a pointer lives in `README.md` only if the export carries its target, and otherwise in `README.dev.md` — never both, so nothing is written twice and the front page restates no absence. Nine rows and the omitted halves of two more move across as the same two-column table; the boundary test's text rule gains `README.md` as a root, which holds the rule mechanically rather than by review. Outside the README a row or clause pointing at a leaving file is deleted, and the few facts a reader still needs are restated in the idiom the tree already uses ("which the export omits"), true read from either checkout.
- **The contribution surface** (ruling (a): the README's `## Contributing`, `CONTRIBUTING.md`, `SECURITY.md`, the three issue forms, the pull-request template): this repository receives one commit per release, so a pull request here is not merged; contribution is by invitation, asked for through the form, a CSA deciding each request under `CONTRIBUTING.md`'s dedication. The bug and enhancement forms say the CSAs triage the report and answer on the issue; `SECURITY.md` says a report is tracked privately under the advisory's identifier. `access-request.yml` becomes "Contribution request" with its filename and `[Access]:` prefix kept, so the three links to it stand, and its required checkbox still dedicates the work under ADR-0004 — only the scope clause is reworded.
- **The tripwire** (`tests/test_export_names.py`, new): one pure function over a root returning findings in the repository's shape — path, line, problem, and a fix naming the export idiom and the one-home rule. Membership is git's own listing of tracked and untracked-unignored files, less the excluded paths and less the allowlist; the pattern is one case-insensitive expression matching the hyphenated name or the two words with any run of whitespace between them, a line wrap included. The allowlist is six changelog paths, each required to still match, so a stale entry is a finding and slice-1 ticket 87's cycle deletes the list whole. It reads files as they stand on disk rather than `HEAD`'s archive — `TRIP-2-implement` stages and never commits, and its membership equals the archive's because the boundary test already holds list, attributes, and archive equal.
