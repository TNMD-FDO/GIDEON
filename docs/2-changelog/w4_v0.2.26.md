## Changes

This release implements workflow ticket 54 under the plan `docs/1-plans/the-gates-greenness-depends-on-the-shared-venv.plan.md`, spec §2.1, §2.6, and §1.5's refusal rule, the map's §3 and §6, and triage rulings (b)–(f). Until now the gate's verdict was a property of whatever was installed in the `.venv` it found, and the primary and every worktree share one through a link: on 2026-09-20 at 21:11 general-turn ticket 07's `pip install psycopg` landed in every tree at once, and `v0.2.24`'s export was refused with four `mypy` errors in a file unchanged since `v0.2.8`. The development tree stayed green on a stale `.mypy_cache`; the export's fresh archive was the first place it showed. Nothing of the product's surface moves here — no module under `gideon/`, no site key, nothing applied on the box.

- **The comparison is a module of its own** (`tools/environment.py`, new, kept by the export): the running interpreter's installed distributions through `importlib.metadata` against the working directory's `requirements-dev.txt`. Equal when every pin is installed at its pinned version, every installed distribution is a pin, a member of the pins' requirement closure, or one of the installer's own (`pip`, `setuptools`, `wheel`), and the environment's own `-m pip check` is clean. Standard library alone, no sibling import, held to it by an AST case as the gate and the mask are.
- **It is run by the interpreter being judged**, as the main script by path under `-P` — the mask's precedent. An answer computed from outside is a guess about paths; what the judged interpreter can import is what `mypy` and `pytest` will answer to a moment later. `-P` also keeps the working directory and `tools/` off `sys.path`, so a stray `*.egg-info` in a checkout is never read as a distribution.
- **Two reds, because they have two fixes.** Exit 1 is an environment that differs: one stderr line per finding, each naming its package — a distribution no pin requires, a pin absent, a pin at another version, a name installed twice, a requirement `pip check` reports broken — collected whole before anything is printed. Exit 2 is a pin file that cannot be read as exact pins (absent, a line of another shape, a name pinned twice), reported with each line's number under a fix that repairs `requirements-dev.txt` and never a rebuild, **the environment never read**, since there is nothing to compare it with.
- **The printed fix is chosen by where the reader stands.** Through a link the naive advice — `python3 -m venv --clear .venv` — would clear the primary's directory, so the module reads whether the interpreter's prefix is a symlink and the through-a-link text never prints that command. `bin/venv-build` removes a link *as a link*; its target is never opened, listed, or written.
- **The closure over-approximates, and says so.** Evaluating `platform_system == "Linux"` needs a marker parser the standard library lacks, so the walk follows requirement names to a fixed point, never follows a requirement conditioned on an extra (no pin names one), and follows every other marker unevaluated: a distribution that is the pins' on another platform is tolerated. What the name walk cannot decide is handed to the environment's own installer, `-P -m pip check`, which evaluates markers with pip's parser and catches a transitive removed or moved by hand; it reads no network and took a tenth of a second on the primary's venv. **An environment without pip is not asked**, and the equal line says the check did not run — the mask's `no listed path on this host` precedent, observed rather than claimed, because refusing an environment that is exactly the pins for lacking a tool would be the wrong red.
- **The gate runs it first** (`tools/gate.py`), before the mask's first trial and before `ruff`, with `ROOT` as its working directory so the pins are the gate's own tree's. It resolves the three tools, insists they share one parent directory, and takes the interpreter beside them; two directories, a bare name, or no interpreter is a refusal of the gate's own with its fix. A red is `gate: red at environment (exit N)` with the module's code passed through and nothing else run. **No flag skips it**: the verdict is the tree's pins' or there is none. The green summary's list leads with `environment`.
- **The export check compares the archive with the invoking tree's copy** (`bin/export-tree-check`), unmasked — it reads the interpreter's own metadata and the archive's pin file, nothing of the box — so an archive older than this release is compared exactly as `HEAD` is, needing no cooperation from the old tree. The module's exit 1 becomes the script's own **exit 3**, keeping and naming the directory, with the fix by tree form: `bin/venv-build` or the rebase for `HEAD` and `staged`, `EXPORT_TREE_CHECK_PYTHON` for a named commit-ish, which is that override's recorded purpose. The module's exit 2 goes through today's red-tree branch at exit 1, where a rebuild is never suggested, because none would cure it. A missing `tools/environment.py` joins the pre-directory refusals.
- **`bin/release-export` stops giving the wrong advice.** Exit 3 now has its own refusal — the primary's `.venv` is not that tag's pins, fixed by `bin/venv-build` from the primary — where every other non-zero exit keeps its `TRIP-hotfix` fix, a hotfix being what a red tree needs and what a stale venv does not. Exit 1 either way, before any public write.
- **One command builds a tree's environment** (`bin/venv-build`, new, excluded from the export): run as the copy in the tree it builds for, and unlike the claim and the removal it never refuses a worktree copy, a worktree's own venv being the point. A symlink `.venv` removed as a link or a directory rebuilt whole, `venv --clear`, the new interpreter's `pip install -r requirements-dev.txt`, the tree's `.mypy_cache` cleared, then the comparison as its last line and exit. Every refusal comes before any write — **a pin file `tools/environment.py --pins-only` cannot read among them**, so a malformed pin file never removes a link, clears a directory, or reaches `pip`, and is never answered with "run it again", which is printed only for a `pip` that failed over pins already judged readable. Other registered worktrees linking to this tree's `.venv` are named in one line first: their gates refuse by name for the minute it takes.
- **The rule has one home**, `docs/agents/worktrees.md` §9: a tree is checked in an environment built from its own `requirements-dev.txt`; nothing is ever installed through a link; a cycle that moves the pin file runs `bin/venv-build` in its worktree before its first install; its release runs it in the primary after the fast-forward; a linked cycle whose gate refuses after `main`'s pins moved rebases (§4). §8 keeps every step number — `bin/worktree-remove`'s refusals and the skills cite steps 7 to 10 — with step 4 gaining ruling (e) and step 7 ruling (d). `TRIP-2-implement` Step 0 points at the rule, `TRIP-3-release` carries it at Steps 12, 13, and 14, and `TRIP-hotfix` Step 7 stops saying "link".
