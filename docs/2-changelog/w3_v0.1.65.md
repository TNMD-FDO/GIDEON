## Changes

Until now, each backup set's secrets tarball was sealed to one age recipient: the office's, whose identity lives only in the office password manager. Nothing on the box could open its own sets, so ticket 20's unattended clean-VM full restore would have needed a person to hand it that identity. This release seals every set to a second recipient too: the box's own. Its identity is root-only host state that never enters a set. Root on the box already reads the plaintext secrets, so the new key exposes nothing, and a set that leaves the box still opens only with the office identity (slice-0 ticket 23; spec §19.1, §19.2, §1.7; ADR-0042, ADR-0035, ADR-0005). The plan is `docs/1-plans/box-recipient.plan.md`.

- **The provision step** (`gideon/host/steps/site_dirs.py`, registered after `age-recipient`): `age-identity` mints the identity once through the seam and keeps the `AGE-SECRET-KEY-1…` line alone at `/etc/gideon/backup_age_identity`, mode 0400, root-owned.
  - A later run reports the identity current and never re-mints it.
  - A wrong mode or owner is drift, repaired in place.
  - Unreadable or malformed content is `unfixable`. Its fix says to delete the file and keep no copy under `/etc/gideon`: only the exact path is excluded from a set, so a copy moved aside would be backed up (Codex code review round 1, the one finding).
  - No public half is kept as a file, and nothing is printed.
  - The new `AGE_IDENTITY` grammar uses the uppercase Bech32 alphabet of a real key.
- **The exclusion** (`gideon/host/backupset.py`): the identity's path joins the no-GPU marker's in `etc_gideon_exclusions()`. No set carries it, and a restore in place never touches the live one.
- **The manifest**: `Manifest.recipients` (the office's first) replaces the single field. `to_json` writes `recipients` and still writes `recipient`, so a previous-release tree still reads this release's sets after a rollback across the tag. The parser reads a manifest without `recipients` as a one-recipient set, and refuses an empty or mistyped list or one whose first item differs from `recipient`. The manifest stays at version 1.
- **`backup run`** (`gideon/host/backup.py`):
  - The preconditions derive the box recipient with `age-keygen -y <path>`. The identity reaches the child by path only, its streams are never echoed, and the output is checked against the recipient grammar.
  - The run refuses before any stage in three cases: the identity is missing or not root-only (the fix names `host provision --only age-identity`), or it cannot be decoded (the fix names delete-and-remint).
  - The secrets stage passes one quoted `-r` per recipient, and its row names the recipient count.
- **`backup drill`** (`gideon/host/drill.py`): `parse_age_header(data, recipients)` requires exactly as many X25519 stanzas as the manifest names.
- **`upgrade --rollback`** (`gideon/host/upgrade.py`): a new `identity` stage runs between `stop` and `checkout`. When the selected set names one recipient, the tree being restored cannot exclude the identity, so the stage removes the file. With two recipients, the file stays.
