## Changes

ADR-0045's supersession of ADR-0039, on the service's side: a trip in General's service now writes the content-free `guardrail_trips` row — branch, family, pattern id, `source` — through the shared module's writer under the audit role, as the Filter does from inside the frontend today. Since ticket 06 the service had called `guardrail.record_trip` on every trip and every one of those writes died in silence, by three causes; this release removes all three. The frontend keeps its mount and the Filter keeps writing until ticket 09, and no user's turn passes through the service before then.

- **The driver, one pin for two wheels** (`images/gideon/Dockerfile`, `images.lock`, `requirements-dev.txt`). `write_trip_row` imports `psycopg` inside the function and the image held ten HTTP packages and no driver, so the import failed and the writer's own `except` dropped it. `psycopg` and `psycopg-binary` now install on the Dockerfile's existing `pip install --no-deps --only-binary=:all:` line, **both at one new build argument**, `PSYCOPG_VERSION` (3.3.6), watched at the PyPI project `psycopg`. The two projects release in lockstep at one version, `psycopg-binary` declares no dependency, and `pip check` passes on the pair. One argument makes a half-bump impossible by construction — which matters here more than anywhere else in the lock, because a mismatched or unloadable pair would be the worst failure this design has: the writer silent, the turn fine, nothing red.
- **The build proves the driver where a failure is loud** (`tools/imagebuild/build.py`). `_GIDEON_SMOKE_SCRIPT` imports the driver, refuses unless `psycopg.pq.__impl__` reads `binary`, refuses unless the two distributions report the same version, and prints all twelve package versions; `SMOKE["gideon"].version_args` gains `PSYCOPG_VERSION`. The smoke runs **before the push**, so a driver that cannot load pushes nothing, and again under `--check`, which `tests/contract/built_images.py` calls on the box's runner. It is also what closed the one boundary the research note left untraced — the real `python:3.14-slim-trixie` container was never pulled when the note was written, and the smoke passed inside the built image on the box before anything was pushed.
- **`source` from one header, by two rendered settings** (`gideon/api/settings.py`, `gideon/api/judged.py`, `gideon/api/relay.py`, `gideon/api/app.py`). `Settings` gains `source_header` and `eval_identity`, read from `GIDEON_SOURCE_HEADER` and `GIDEON_EVAL_IDENTITY`, a missing or empty one refusing startup like the others; `CompletionRelay` is constructed with the two, takes every value under the configured header from the request, and hands the decided word to `stream_state_from_body`, which passes it to every `StreamState` it builds, the strict empty-stash ones included. The word is decided once per request, before the engine is called, by a pure function: **exactly one** value under the configured header, equal to the configured value after trimming and case-folding, is `eval`; absent, empty, repeated, or another's is `user`.
- **The email is the one of the three headers that can decide.** The door sends `X-OpenWebUI-User-Name`, `X-OpenWebUI-User-Email`, and `X-OpenWebUI-User-Role` (ticket 05). The eval identity's role is `user` like every seat's and its name is a display string, while its address sits under `.invalid`, which no directory identity can hold (ADR-0030) — so contract §2 row 5 gains that narrowing here. **The header is a label under the connection's bearer key, never an authorization**: whoever holds the key can name any identity, and what they buy is a word on a statistics row. The value enters no log line, no exception text, no repr, no response, and no upstream request (§19.4); `EngineClient.completion` still sends the body, the content type, and the engine's key alone.
- **One row per request, on both paths** (`gideon/api/judged.py`). `_record_trip` takes the stream path's guard: once the state holds a trip, nothing is recorded again. A whole body whose two choices both trip writes one row, the first trip's; a trip followed by an unjudgeable choice writes one row and still answers the unjudged 502, and `_record_error_trip` clears the held content before recording either way. Each tripped choice still carries its own family's refusal, computed from the judge's result and never from the state. A row means one request's answer was refused, streamed or whole.
- **The render mounts the secret and nothing else moves** (`gideon/host/render/api.py`, `gideon/host/render/compose.py`, `gideon/host/secrets.py`). `api_service`'s `environment` gains the two settings, from the new `API_SOURCE_HEADER` constant and `render/owui.py`'s `EVAL_IDENTITY.email`, and its `secrets` list gains `postgres_gideon_audit_password`. **The top-level `secrets` map does not move** — it already holds the audit secret on every host — which is what keeps this change from recreating every service, the engine included, as the ledger's entries of 2026-09-09 and 2026-09-19 record such a move costing. The Compose secret's name equals the writer's constant path's last segment, so mounting the same secret puts the file where the writer already looks; the service reads it nowhere else and checks nothing at startup, since Compose itself refuses a service whose secret source is absent and a turn must never depend on the record. The consumer map derives the service as a mount consumer with no edit of its own, and the registry's consumer text now names all three consumers until ticket 09 removes the frontend's.
- **The service import tripwire's allowance is empty** (`tests/test_service_import_boundary.py`, `gideon/guardrail.py`). The driver's root joins `ALLOWED_DEPENDENCIES`, read from `guardrail.TRIP_DRIVER_MODULE`; `DEFERRED_ONLY_MODULES` and the branch that read it are gone, and the two tests that policed the deferred-only allowance are replaced by one that the driver is an ordinary image dependency. `gideon/guardrail.py` loses its now-unused `import-not-found` ignore, which mypy's `warn_unused_ignores` would otherwise fail; a comment is not a statement, so the Function's copy and `tests/test_guardrail_equality.py` are untouched. The host boundary's third rule still keeps the import inside `write_trip_row`.
- **Tests**: one row per trip on both paths with the row's four values asserted, one row for two tripping choices and for a trip then an unjudgeable choice, `source` `eval` through its case and padding variants and `user` when the header is absent, empty, repeated, another's, or differently named, a connect that raises and a connect held on an event the test owns with the response complete and byte-equal while the connect is still held, and all five forwarded headers sent with sentinel values over clean, tripped, unjudged, and upstream-failed requests with the sentinels absent from every captured log record, from the row, from the response, and from what the stub engine received. On the render side: the block's `secrets` and `environment` on a GPU host and absent under the no-GPU marker, the top-level map equal before and after, the settings recreating `gideon-api`'s block alone, and the consumer map and registry text. The gate: `ruff` and `mypy` clean over 290 source files, 2166 passed with 7095 subtests.
