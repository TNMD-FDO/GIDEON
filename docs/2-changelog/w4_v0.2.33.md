## Changes

This release implements general-turn ticket 14 under the plan `docs/1-plans/the-waiting-connect-tests-one-second-bound-is-a-flake.plan.md`, rulings (a) to (c); ruling (d) closed at triage. `test_writer_failure_or_waiting_connect_never_changes_the_answer` failed intermittently at its `started.wait` line (3 of 30 fresh runs at triage, twice at `v0.2.29`'s gate). No bound fixed it: in every failing run the waiting connect was never entered. The raising leg's writer thread could still be running after its fixture's patches had been removed. It then ran the real `import psycopg`, which failed without libpq, and the failed import's cleanup deleted the next leg's fake driver from `sys.modules`.

- **The fixture owns its threads** (`tests/test_api_completions.py`). `trip_driver` now patches `guardrail.Thread` with `RecordingThread`, a `threading.Thread` subclass that records itself on `start` into a list owned by that one fixture entry. The real `dispatch_trip_row` runs unchanged. Before its patches are removed, the fixture joins every recorded thread with a timeout of `_ASGI_WAIT_SECONDS`. If a thread is still alive and the body exited cleanly, the fixture raises an `AssertionError` naming the count and the bound. If the body itself raised, the fixture still joins but raises nothing new, so the body's failure is the one reported. A new self-test, `test_trip_driver_fails_when_writer_outlives_fixture`, holds that failure.
- **The waiting leg proves the answer never waits.** `waiting_connect` takes a third event, `finished`, which it sets when its block ends. The block now waits up to `_WRITER_BLOCK_SECONDS`, a new constant set to ten times `_ASGI_WAIT_SECONDS`, so it outlasts the response's own bounds. The bound is finite because a synchronous dispatch would freeze the event loop for the whole block. The leg asserts `finished` is unset once the response is in hand. That replaces the old `released.is_set()` check, which was always true because only the test sets `released`. The release in the `finally` now runs inside the fixture, so the writer ends before the join.
- **Unchanged:** `_ASGI_WAIT_SECONDS`, the `started.wait` bound, `signal_dispatch`, and every `row_written.wait` (ruling a). No file under `gideon/` changes apart from the version.
- **The proof** (`.scratch/general-turn/assets/14-fresh-runs.txt`): a temporary `write_trip_row` widening made the test red over the unfixed fixture, at the ticket's line, and green over the fixed one. A temporary synchronous dispatch made the waiting leg red on `finished` in 20 s without hanging. The test alone passed 100 of 100 fresh-process runs, and the module passed the masked gate.
- **Architecture**: Step 7: no structural change — no command, module, release constant, or test module added, removed, or renamed. `docs/archi/api.md`'s `test_api_completions.py` bullet now says the waiting connect signals its block's end and the fixture joins its writers.
