This release implements slice-2 ticket 07 under the plan `docs/1-plans/judgments-the-queries-file.plan.md`. - **The queries** (`eval/sets/eval-v1/judgments/queries.jsonl`): thirty-eight cases of the `judgments` suite, `judgments-001` … `judgments-038`, one per harvest record that carries a legal research question. `HARV-014` and `HARV-017` carry none, and the maintainer ruled at the claim that they yield no query; ticket 21's target is therefore forty-eight. Nineteen queries are verbatim and nineteen are minimal standalone rewrites. By `query_type` there are 17 doctrinal, 13 statute, 6 case-specific, and 2 other. Ten carry a `jurisdiction` stated in their own text (`-011`, `-015`, `-016`, `-018`, `-020`, `-023`, `-024`, `-036`, `-037`, `-038`), none carries a `reference_date`, and the flagger raised no soft kind. The thirty-eight fall into 32 chat clusters (§18.5). Each carries the `review` of the maintainer's read, `CSA-1` on 2026-09-19.
- **The shape**: [21] item 16's sketch less `expected`, `gold`, `history`, and `kb_ids`, plus `review` (role id, date, accepted soft kinds) and `supersedes`. A query is never edited: a correction is a new id that supersedes the old one.
- **The README** (`eval/sets/eval-v1/judgments/README.md`, kept in the export): what a query is, the never-edit rule, the shape, the wording rule and the two excluded ids, where grades come from (ticket 08's kit), and the CSA's intake procedure.
- **The intake** (`python3 -m tools.judgments.intake <questions file> [--dry-run]`, `tools/judgments/`): takes a UTF-8 file kept outside the checkout, with a `# reviewed <role id> <date> [accept=…]` marker above each question. It loads the frozen harvest flagger by path and reads kinds and severities only. A hard kind always refuses; a soft kind refuses unless the marker accepts it; duplicates refuse. The run is all or nothing. The file is appended by temporary file and rename, so existing bytes are never re-serialized. Output is ids, ordinals, and kinds, never text. After a successful append it prints the `PINNED_PREFIXES` pair to add.
- **The tests**: `tests/test_judgments_queries.py` (kept; skips by `absent_from_export`) pins every committed line's bytes by prefix, `(38, 0fba5d51…9b8b40)`, and holds the ids, the exact key set, and agreement with the harvest and the flagger. A sentinel case proves that no assertion can print a question. `tests/test_judgments_intake.py` (excluded) drives the intake over invented fixtures.
- **The export boundary**: `tools/exportboundary.py` and `.gitattributes` gain the queries file, `tools/judgments`, and `tests/test_judgments_intake.py`. The implement session checked the staged tree's archive: the README and the kept test are present, the three paths are absent, and the kept test ran 7 skipped and 1 passed.
