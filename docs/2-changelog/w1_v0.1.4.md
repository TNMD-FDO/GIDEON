## Changes

- **The hardware-profile check goes live** (`gideon/host/checks/artifacts.py`; spec §1.1, §1.5; ADR-0035): after `select_profile` (an unknown `hardware_profile` still refuses on every host before any probe) and the no-GPU skip, the check reads four host facts through the `Host` seam — `uname -m`, `nvidia-smi --query-gpu=name,compute_cap,memory.total` (VRAM as `<n> MiB`, a value without that unit unreadable), `nvidia-smi -q` for the `Product Architecture` line per GPU (the driver's own word; the box prints `Blackwell`, the lock's spelling, so no capability-to-architecture table lives in the product), and `/proc/meminfo`'s `MemTotal` — and holds them to `profile.requires`: platform, GPU architecture, compute capability, model, and count exact (the profile is the layout; a different layout is a different profile, §2.1), per-GPU VRAM and DRAM as minimums in the lock's decimal gigabytes (`models.GIGABYTE`) against MiB × 2²⁰ and kB × 1024. Every shortfall lands in one refuse row (`GPU count is 2, profile requires 3; GPU 1 VRAM is 97887 MiB (102.6 GB), profile requires 200 GB; DRAM is 259309184 kB (265.5 GB), profile requires 1000 GB`), the raw native-unit figure beside the rounded one so a value one unit under a floor is visibly under it (the plan review's one finding), with a fix naming both ways out: provide the hardware, or set `hardware_profile` in `/etc/gideon/site.yaml` to a profile the host satisfies. A missing or failing `nvidia-smi` refuses with `nogpu.GPU_DRIVER_FIX`, the wording render's fact gathering already uses; an unreadable `uname` or `/proc/meminfo` names those. A non-reference profile that satisfies its requirements warns as before, its matched facts in the row. The module-local `GpuRequirements`, the constructor seam, and the inert wording are gone.
- **The free-space check becomes the data-volume check** (`gideon/host/checks/capacity.py`, `checks/__init__.py`; §1.1, §1.4, §1.5, ADR-0017): `DataVolumeCheck` (row `data-volume`, the eighth in `CHECKS`) measures `df -B1 --output=size,avail /data` in one call and holds the **size** to `requires.data_volume_gb` — §1.1's "minimum data-volume size", the same judgment at install and at every later upgrade's preflight whatever the product has stored, where a free-bytes floor would have refused a healthy 4.5 TB box's upgrade once it held 0.5 TB of data (discovery ruling 1). Free bytes stay in the row for information; the refusal prints the raw byte count beside the rounded gigabytes and a fix naming the floor and the `hardware_profile` way out; an unmeasurable `/data` refuses on every host. §1.5's "low-but-sufficient disk" warn is deferred to §7.6's self-scaling reserve rule (1.25× the live generation's measured bytes), which arrives with slice 3's `index build` — the only figure that defines *low*, so nothing is invented. The `need`/`reserve` seam is gone.
- **No-GPU hosts skip visibly** (ADR-0035; discovery ruling 3): both rows are `pass — skipped: no-GPU host; …` naming what was not judged (`platform, GPU facts, and DRAM`; the measured size and free bytes with `data-volume floor is not judged`), the shape Phase A's gpu-only steps and `driver-tested` already use; `Severity.INERT` is now documented as a judgment whose data has not shipped (`jurisdiction` until slices 2–3). The acceptance VM's data disk is 2 TB (`tools/acceptance/image.py`), below the 4 TB floor, which is why the floor is skipped rather than judged there.
- **The unit and the formatter** (`gideon/host/models.py`, `gideon/host/checks/__init__.py`): `GIGABYTE` (10⁹ bytes) is the lock's unit, stated once beside the loader; `format_gb` renders a byte count as decimal gigabytes with one decimal for every row, and its test records why refusals also print the raw figure: `4 000 GB − 1 byte` renders as `4000.0 GB`.
- **Tests** (`tests/test_preflight_checks.py`, `tests/test_preflight.py`; thirteen new): the `HardwareProfile` truth table over fakes derived from the committed lock — the pass row's facts, each shortfall alone (count, model, capability, architecture, VRAM one MiB under, DRAM one kB under, platform) with the raw figure asserted, two shortfalls in one row, `nvidia-smi` absent (127) and failing, an architecture line count disagreeing with the query, a VRAM value without `MiB`, a missing `MemTotal`, non-reference warn, no-GPU with no probe run, unknown profile with no probe run; `DataVolume` one byte under and at the floor, unknown profile before `df`, unmeasurable on both host kinds, the no-GPU skip after measuring; `FormatGb`; the registry's row names; and a runner-level no-GPU run over the real `CHECKS` counting the two skipped rows as passes. Every expectation derives from the loaded lock or a `dataclasses.replace` over it; no pin value is restated.
