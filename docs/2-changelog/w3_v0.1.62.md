## Changes

`gideon-data-volume-low` stood alone among the filesystem rules: `/data` under 15 % free paged, while the root filesystem and the Docker volume — the operating system, the journal, the checkouts, the runner's work, the acceptance harness's disks, and since `v0.1.61` the shared image store — paged on nothing. On 2026-09-09 the root filesystem filled and no email reached anyone (slice-1 ticket 74; §19.5, §7.6, ADR-0034, ADR-0040). This release gives those two filesystems the data volume's line. No Python changes: the rules file carries no code and the board is a verbatim artifact. The plan is `docs/1-plans/host-filesystems-page-when-low.plan.md`.

- **The rule** (`compose/grafana/provisioning/alerting/rules.yaml.tmpl`): one static page-class rule, uid `gideon-host-filesystem-low`, in the `metrics` group after the data volume's — the same percent-free expression with a `mountpoint` regex matcher over `/` and `/var/lib/docker` on both the avail and the size series, instant; a threshold condition `lt` 15; `for: 0s`; `noDataState` and `execErrState` OK, so a filesystem a host does not have is one instance fewer and never a page. **One rule, one alert instance per filesystem**: unified alerting makes an instance per label set the query returns, and the policy's `group_by: [alertname]` folds both into one email when both cross, each summary naming its own mountpoint. The summary carries Grafana's own label reference, whose dollar the template doubles because `substitute_template` fills the file with a strict `string.Template` — the render test pins the *rendered* text, so the escape is proven through the render and not just in the template. No template slot and no marker: both filesystems exist on every host the runbook's §1.4 lays out, and the `no-gpu` fixture renders the rule identically. The threshold is the data rule's literal restated, ADR-0017 `exempt`; no site key, a per-site or bytes threshold having been declined at triage (ADR-0028).
- **The board** (`compose/grafana/dashboards/overview.json`): the "Data free" panel becomes **"Filesystems free"** with two targets appended, legends `/` and `/var/lib/docker`; its percent unit and green step at 15 already applied to every series, so the board's line and the rule's line stay one figure — a new test reads the step from the panel and the threshold from the rule and holds them equal.
- **Tests** (`tests/test_render_grafana.py`): the uid set and the OK-state list gain the rule; the Overview title set swaps "Data free" for "Filesystems free"; two new tests over both sites and the no-GPU render — the rule's group, period, states, class, and runbook annotation, its matcher naming *exactly* the two mountpoints on both series (a third path or a dropped one fails), its evaluator's parameter read from the data rule rather than restated, and the rendered summary's single dollar; and the panel's four targets with their legends and per-target mountpoints. The three render fixtures were regenerated: exactly nine files moved — the rules file, the board, and the manifest's two digests in each of `example`, `second-office`, and `no-gpu`.
- **The runbook** (`docs/runbooks/observability.md`): §3's Overview bullet names the four filesystems; §4's preamble cites the rules file at its real path (it had lost `provisioning/`) and gains the *host filesystem low* row with its `df` checks and its levers — on the Docker volume the shared image store (`docker system df`, `docker buildx du`, the box ledger's §5 rules), on the root filesystem the journal's 50 GB cap, the acceptance harness's run directory, the checkouts and their worktrees, a review tool's thread store, with the ledger's §6 rule making a growing `/` a thing that should not be there; §7 gains the drill item as item 6, the later items renumbered (a grep first confirmed no citation anywhere names an item by number).
