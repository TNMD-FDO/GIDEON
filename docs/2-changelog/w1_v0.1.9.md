## Changes

- **The text, one release file** (`compose/open-webui/general.yaml`; §15, [06] items 4–5, §16, ADR-0028): General's display name, description, and system prompt are product text beside the permission set, with `$office_name` the one placeholder — filled by `string.Template` after the file is parsed, leaf by leaf, so an office name carrying YAML punctuation cannot break the document; a literal dollar sign is written `$$`, and the frontend's own `{{VARIABLE}}` syntax is never used (the pinned frontend substitutes nine browser-supplied tokens and twelve server-computed ones into a system prompt and leaves anything else verbatim). The prompt says what §15 and [06] item 5 require — a general assistant, no case-matter access, no knowledge of the corpus, cannot verify citations and Research exists for anything the user will rely on — and §16's tier-2 instruction over the whole of its list (deadline computation, Guidelines ranges, sentence credit, generic arithmetic; confirming a supplied date is computing it); it makes no claim about the system. The description's last sentence is the privilege reminder's own. The texts were approved with the plan; changing them is an edit to this file, the two GPU fixtures regenerated, and a release.
- **The record, rendered** (`gideon/host/render/owui.py`; §3.5, §15, ADR-0009, ADR-0017, ADR-0035): `general_preset_record` builds the manifest's second model on a GPU host — `id` `gideon-general` (`GENERAL_PRESET_ID`, effectively permanent: chat rows, URLs, ticket 08's default-model value, and the Filters of 09 and 14 name it; prefixed like the engine's service name), `base_model_id` the profile's served name through the shared generator lookup, `name` from the template, `params` = the system prompt and `function_calling: legacy` (`GENERAL_FUNCTION_CALLING`) and nothing else, `meta` = the description and `GENERAL_CAPABILITIES` (the base set with `web_search` alone true — offered but off per chat with no `defaultFeatureIds`; memory off on the record, the one lever that forces it off for every user; `terminal` off beside `builtin_tools`), the public-read grant `{user, "*", read}` with the four placeholder fields the sync form requires (`public_read_grant`, `MODEL_GRANT_*`), `is_active` true, and the row placeholders both records now share (`MODEL_ROW_USER_ID`, `MODEL_ROW_CREATED_AT`, `MODEL_ROW_UPDATED_AT`, renamed from `BASE_MODEL_*`). `general_texts` loads the template through `template_paths`, refuses a missing or malformed file naming it and the leaf, and refuses a placeholder other than `$office_name` or an unescaped dollar sign with the fix in the message. `web_search` is true for every office: the office's kill switch is the frontend-wide flag and the service (ticket 15), and a capability without the feature is inert, so the second office's record differs from the first only in the office's name.
- **`function_calling: legacy` — the one parameter** (a ruling made on the researcher's finding past the discovery ceiling, recorded on the plan and approved with it): on the pinned frontend the per-chat search toggle runs the non-tool path §15 designs (queries from the task model, SearXNG, pages whole into context) only when the record's `params.function_calling` is `legacy`; under the default `native` it expects the `search_web` built-in tool, which `builtin_tools: false` suppresses, so the toggle would do nothing, silently, with no status event. The mode also stops the built-in tools being added at all and opens nothing else (the other paths it gates sit behind capabilities that are off). Not a sampling override ([10] item 15 stands); a third item for ticket 29's ruling.
- **The base model's record changed on the box** (the plan's Implementation Notes; `BASE_MODEL_HIDDEN`): a users-group member saw General in the selector and got "Model not found" on the first message, and the eval identity's API turn reproduced it (`400`). The pinned frontend's chat route checks the selected record's grant and then walks its `base_model_id` chain, requiring a read grant or ownership at every hop and treating a base with no row as admin-only ("a shared preset cannot be used to reach a base model the caller could not use directly") — so `v0.1.8`'s empty grant list on the base made every preset over it unusable for a `user`-role account, and so would no row at all. The base model's record now carries the public-read grant too and `meta.hidden: true`, the pinned frontend's selector switch: the selector drops it, the chat's available and default ids exclude it, the editor's base picker hides it from non-admins — client-side, so `/api/models` still lists it to a signed-in user, who cannot mint an API key under §4.2's set. Ticket 08's "the base model is withheld" is this flag; its comment says so. Pushed by a further apply; the eval identity's probe then answered `200` with the reply from `gideon-generator` after the id swap.
