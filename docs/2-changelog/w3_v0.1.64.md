## Changes

Three callers used to find a managed turn's chat by the listing difference alone: the chats new in `gideon-eval`'s listing since the turn. The eval identity is one account for every session on the box, so when two sessions were signed in at once, each saw the other's chat as new. The turn harness's API driver then refused unless exactly one chat was new. It trusted that chat at the read-back, and its cleanup deleted every new chat, another session's included. `engine verify`'s frontend case took the first new chat carrying its minted ids, and it raised a 401 from a candidate another session had just deleted as the check's own failure. The search-sentinel contract repeated the harness's rule. `v0.1.34`'s proof (`assets/11-on-box.txt` §5.1, §8) and ticket 59's triage both lost turns this way (slice-1 ticket 68; §18, §4's identity rule, §6.7, §19.4; ADR-0001, ADR-0006, ADR-0035). The plan is `docs/1-plans/harness-turn-finds-its-chat-by-minted-ids.plan.md`.

- **One finder** (`gideon/host/owuiturn.py`): `find_turn_chat(client, *, ids_before, user_id, assistant_id)` returns a `TurnChat` in `StoredTurn`'s shape: the chat id, its `StoredTurn`, the count of chats new since the turn, and a `Problem` when none or several match.
  - The listing difference stays the candidate filter, because the pinned frontend has no route by message id. The read by id is the proof: a candidate matches when its `history.messages` holds both minted ids.
  - Every candidate is read, so several matches are a refusal, not the first one taken.
  - A read answering 401 or 404 (the pinned route's not-found shape, the note's §3.1) is a skipped candidate, counted as vanished. Any other failure raises `OwuiError` as before.
  - An unfinished or errored placeholder still identifies its chat, and its `StoredTurn.problem` says so.
  - `_FIND_FIX` is the module's fix text, and each caller substitutes its own. `stored_messages` is retired, and its test is folded into the finder's. The docstring names the three callers.
- **The harness** (`tools/turns/run.py`):
  - `ApiTurnDriver.turn` runs the finder whatever the managed turn answered, so a refused or failed turn's chat is identified and deleted too.
  - A finder that raises is run once more. The first failure is kept as the row's problem, and a second one propagates. This keeps the contract that one failed listing never leaves a chat behind.
  - `TurnOutcome` gains `candidates` and `unidentified`, and `TurnDriver.turn` drops `list_chats`.
  - `_run_cases` loses its own after-listing and new-chat branches. A finder refusal is a failed row carrying the finder's counts, with `_unverified_fix`.
  - The cleanup follows one rule for both drivers: delete the chat the driver identified, and report a turn with none identified as unverified. No chat outside a match is ever deleted.
  - The `--out` record's `new_chat_ids` becomes `candidates`, a count, so another session's chat id is never written. `_chat_fix` is retired. The browser driver loses only the `list_chats` parameter, and `_run_probe` is untouched.
- **`engine verify`** (`gideon/host/engine.py`): `_frontend_case` replaces its candidate loop with one finder call, made after a refused turn too. `chats_created` is now the candidate count in every case. A finder refusal is `_frontend_failure` with the finder's text and the frontend fix. The `finally` still deletes the identified chat alone. The figure keys are unchanged.
- **The search-sentinel contract** (`tests/contract/search_sentinel.py`): `managed_turn` goes through the finder. A refusal is an `AssertionError` naming its text, and the `finally` deletes the found chat alone.
- **The fakes and tests**:
  - `tests/test_turns.py` and `tests/test_engine_verify.py`: an unknown chat id now answers `401 {"detail": "Not found"}`. The fakes gain three foreign-chat behaviours: a chat that stands, a chat that vanishes before its read, and a foreign chat alone. `test_engine_verify.py` also gains a two-matches behaviour.
  - The old two-chat harness test is rewritten to the refusals. New tests cover a standing and a vanished foreign chat, a foreign-only listing, and two interleaved runs over one fake account.
  - The gate's boundaries test gains `foreign only` and `two matches` subtests.
  - `tests/test_owuiturn.py` gains `FinderTests`: match, skip, none, several, raise, two id pairs, the placeholder shapes, and no credential in any problem text.
  - The browser tests pass unchanged.
