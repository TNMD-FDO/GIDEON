## Changes

- **`models.lock`** (spec §1.1, §2.1–2.2, §2.4, §5; ADR-0009, ADR-0031): the third committed lock, `version: 1`, `reference: 2x96v-256d`, one profile under `profiles`. The profile's `requires` block states the minimums preflight will check (slice-1 ticket 02): `platform: x86_64`, the GPU's architecture, compute capability (a quoted `major.minor`), model as `nvidia-smi` spells it, count, and per-GPU VRAM, then DRAM and the data-volume floor — the memory figures in decimal gigabytes compared with the kernel's `MemTotal` and `nvidia-smi`'s `memory.total` as bytes, so the reference box (about 265 GB and 102.6 GB reported) clears `256` and `96` where binary gibibytes (247 GiB, 95.6 GiB) would fail; the data floor is 4 TB, a capacity starting value under ADR-0017. The `generator` model pins `Qwen/Qwen3.8-27B-FP8` at its revision commit with every regular file's `sha256` and `size` (80 files, 30.9 GB; `.gitattributes` the one exclusion), `gpu: 0`, and a `serve` block carrying §5.3's baseline verbatim — `served_name: gideon-generator`, the three env facts, the nine flags as vLLM's names without their `--` (`true` a bare flag) — with the not-set decisions (E39, E40, E44), the E46 starting values, and the SM120 DeepGEMM rule as comments that stay true for any value. The memory table (§7.6) and chunk guards (§7.7) arrive with their consumers (slice 3), recorded in the lock's own comment.
- **The loader** (`gideon/host/models.py`, stdlib + `yaml`): frozen, slotted dataclasses (`ModelsLock`, `HardwareProfile`, `ProfileRequirements`, `GpuRequirements`, `ModelPin`, `ServeBaseline`, `PinnedFile`); a duplicate-key-refusing SafeLoader; collect-all `ModelsLockError`s each ending in the one fix; unknown keys refused with the nearest valid key; the exported grammars `PROFILE_NAME` (§1.1's `<count>x<vram>v-<dram>d` / `<n>u`), `ROLE_NAME` and `FLAG_NAME` (the pin watch's key grammar: no dot, no slash, no leading hyphen), `PLATFORM`, `COMPUTE_CAPABILITY`, `HF_REPO`, `REVISION`, `FILE_PATH` (relative POSIX, no dot-files), `ENV_NAME` (never secret-like), and `images.DIGEST` for file digests; `files` refused unless non-empty and in sorted path order; a model's `gpu` refused at or above the profile's count; `reference` refused unless it names a profile; the `read_`/`parse_`/`load_…_text` split the pin watch loads `origin/main`'s text through. `select_profile(lock, name)` is the one selection rule: the profile, or a `report.Problem` naming the profiles the lock holds and the site key to set.
- **Two addressing tiers for the pin watch** (ADR-0031, slice-0 ticket 14): every scalar above a model's `files` sits alone on a `key: value` line under dot-free, slash-free keys, so `revision` and any requirement or serve value is value-only patchable by `replace_scalar`; `files` — keyed by repo paths, which may carry dots and slashes the patcher cannot address — is the last key of a model entry and a block the `ModelPin` patcher regenerates whole from the Hub listing, an added or removed file still a bump. Ticket 14 carries the notes (`LockName`, `_load`, `PRODUCT_LOCKS`, the record patcher, the recorded Hub excerpt for its fake fetcher).
- **Preflight** (`preflight.py`, `checks/__init__.py`, `checks/artifacts.py`; §3.4, §1.5): `models.lock` is loaded pre-run beside `host.lock` and the egress allowlist — missing or malformed is a stderr refusal ending in the fix, exit 1, no row printed — and carried on `PreflightContext.models`; `HardwareProfileCheck` selects the site's profile first: unknown refuses on every host, GPU or not, naming the profiles the lock holds and `hardware_profile`; non-reference warns, the reference read from the lock (the hard-coded constant gone); the GPU-facts path and the free-space need stay inert, the inert row now `profile <name> is in models.lock; its requirements are not yet checked`.
- **Render** (`render/__init__.py`, `render/command.py`, `apply.py`, `drill.py`; §3.5): `RenderInputs.profile` is a required `HardwareProfile`; `_load_inputs` loads and selects, an unknown profile refusing with the same problem and fix and writing nothing; the manifest's `inputs` block gains `models_lock_sha256` and `hardware_profile` after `host_lock_sha256`, so `applied.yaml` says which lock and profile rendered the stack; `render`, `apply`, and `backup drill` gain the `models_path` seam the other locks have. The three fixture manifests are regenerated by exactly those two lines; the 25 artifacts are byte-identical (`git diff --stat` and `render --diff` on the box: `25 unchanged`).
- **Tests and tripwires**: `tests/test_models_lock.py` — the committed lock's stable release facts (one profile, one model `generator` on GPU 0, the served name, env, nine flag values, every `requires` value) asserted exactly, the movable pins (repo, revision, digests) held to grammar and derived, every refusal shape over fictitious lock text; `tests/test_lock_coupling.py` scans the third lock's repo, revision, and bare file digests (sizes deliberately not scanned — a small integer is a whole token any test may carry, and a stale size is caught by the bump that moves the digest beside it); the preflight, render, apply, and drill tests carry the committed lock in their fake checkouts; TESTING.md's "Lock files in tests" names the third lock and the exact-assertion exception for release decisions the pin watch never moves. 21 new tests (837 total).
- **Records**: the pin provenance (`assets/01-hf-model-info.json`, the Hub's `?blobs=true` response; LFS digests from their object ids, the fourteen non-LFS files downloaded and hashed), the on-box demonstration (`assets/01-on-box.txt`: preflight 29 pass, 3 inert; `render --diff` 25 unchanged), the four discovery rulings and the two review-driven shape decisions on ticket 01; the "piece 1 unblocked" comment with the patcher notes on slice-0 ticket 14; README's table row; CONTEXT.md's **Models lock** entry and the sharpened **Hardware profile**; ARCHI.md §2, §4, §7, §8, §12–15.
