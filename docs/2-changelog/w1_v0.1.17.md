## Changes

- **One identity, two more clients** (`gideon/host/render/engine.py`; §20.1, ADR-0009): the module that already gives the Compose service and the frontend's connection the engine's service name, port, and secret name gains the scrape job's name (`ENGINE_JOB_NAME`, `engine`) and the metrics target (`engine_metrics_target()`, host and port), so Prometheus's configuration and Grafana's rule name the engine through the same constants; a later engine adds a job by the same route.
- **The scrape job, on a GPU host only** (`compose/prometheus/prometheus.yml.tmpl`, `gideon/host/render/prometheus.py`; §19.5, [22] item 16, ADR-0035): the template's `$dcgm_job` becomes `$gpu_jobs`, one block carrying the DCGM job and the engine's `/metrics` after it — a static target, the default path, the global fifteen-second interval, no key, because vLLM's authentication middleware guards only `/v1`, `/v2`, `/inference`, and `/cohere` (`docs/research/vllm-engine-service.md` §1). A no-GPU host renders the block as today's one blank line, so `no-gpu/prometheus/prometheus.yml` is byte-identical. The engine publishes no port; nothing new is reachable from the LAN.
- **"Engine down", the sixteenth rule** (`compose/grafana/provisioning/alerting/engine-down-rule.yaml.tmpl` new, `rules.yaml.tmpl`, `gideon/host/render/grafana.py`; §19.5, ADR-0034, ADR-0028, ADR-0017): its own template in the drift rule's shape — uid `gideon-engine-down`, the instant query `up{job="engine"} == bool 0` (the `bool` modifier turns a down target into the 1 the shared threshold reads; a plain comparison would keep the zero-valued sample and never fire), `for` five minutes, `noDataState` and `execErrState` OK (silence is Target down's page), the `page` class, the runbook annotation, the summary "The engine is down, so General cannot answer". The rules template's `$driver_drift_rule` becomes `$gpu_rules`: the engine rule on every GPU host, the drift rule only with a tested driver, the empty string under the marker. "Target down"'s expression excludes the engine job (`up{job!="engine"}`, substituted from the same constant) on every host, so the engine's outage is one page with its own name; the no-GPU rules file moves by that one line. The pending period is the release constant `ENGINE_PENDING_PERIOD` with the two measurements from ticket 06 and the rule that sets it in its comment: clear a plain restart (57 s) and a cold recreate (185 s) so a deliberate stop/start or an apply's recreate never pages, and stay below the core-service rules' ten minutes because the frontend shows nothing while the engine is away — tagged `exempt: set from the two restart timings measured on ticket 06`. Grafana's file provisioning deletes no rule without an explicit `deleteRules` entry, so a rollback to `v0.1.16` leaves the rule provisioned, reading no data and Normal, inert in Grafana's derived state (the drift rule's property since `v0.0.22`).
- **The board** (`compose/grafana/dashboards/gpu.json`; §19.5, [22] item 16): a third row of two time-series panels on the Prometheus datasource — **KV-cache usage** (`vllm:kv_cache_usage_perc`, a percent-unit axis from zero to one, one series per model name) and **Queue depth** (`vllm:num_requests_waiting` and `vllm:num_requests_running` as two legended series, a whole-number axis from zero); no `id` fields, schema 41. The Overview's "Services and probes" panel charts `up` unfiltered and shows the engine job on its own. The metric names and their `engine` and `model_name` labels were read from the pinned image inside the running container (vLLM 0.27.1), as was the launcher's watchdog that exits the HTTP server within five seconds of the engine core erroring unless `VLLM_KEEP_ALIVE_ON_ENGINE_DEATH` is set — why `up` is the one signal and no `/health` probe was added.
- **Tests with the fifteen** (`tests/test_render.py`, `tests/test_render_grafana.py`, the three render fixtures): the engine job among the static targets, both GPU jobs present on a GPU host and absent under the marker with the engine's name absent from the no-GPU text; the sixteenth uid, its `metrics` group, its exact query, `for: 5m`, both states OK, Target down's exclusion on a GPU and a no-GPU render, the rule present with and without a tested driver and absent under the marker; the board's two panels held to their titles, their three series, the KV-cache panel's `percentunit` from zero to one, the datasource uid on each panel and target, no panel `id`. Fixtures regenerated: `example/` and `second-office/` move in the Prometheus file, the rules file, the board, and the manifest; `no-gpu/` in the rules file's one line and its manifest digest.
