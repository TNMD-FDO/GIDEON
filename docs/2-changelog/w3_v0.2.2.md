## Changes

This release implements slice-1 ticket 76 under the plan `docs/1-plans/turn-harness-unfiltered-offline-judged-turn.plan.md`, on the ticket's triage rulings (a)–(e) of 2026-09-16. A `replaced` row's stream record holds only the released prefix, so the text that tripped the Filter was never on record. Twice (`v0.1.43`, `v0.1.55`) a session wrote an uncommitted scratchpad driver to re-ask the prompt unfiltered and judge the answer by hand. That method is now a mode of the turn harness. The Filter, the seeds, and the managed turn's behaviour are unchanged.

- **`--unfiltered`** (API mode, `tools/turns/`). Each selected case's tagged prompt is posted once to the frontend's completions route as the eval identity. Streaming is off and there is no chat id, session id, or minted message id, which is the body shape the inlet probe's bare call already builds (`session.py`, one body builder with two named callers). The pinned frontend returns the upstream completion untouched and stores no chat, but the outlet still runs, so a trip still writes a `guardrail_trips` row with source `eval` (spec §18.1's residual, used here on purpose).
- **The offline judgement** (`classify.py`, `OfflineJudgement`). It reads only the Filter's public names and has three parts. The *verdict* is `judge_message` over the answer's content, with the prompt as sent as the user message. The *unsupplied figures* are, per family, the answer's figures that the prompt did not contain. The *raw hits* are every pattern of every family, with offsets and text and no gate applied. Reasoning is never judged. ADR-0006 is untouched: this is the Filter's own judge, used as a tuning tool, not a classifier in the gate.
- **Rows and records.** A row is content-free: the verdict (`tripped <family>/<pattern>` or `clean`), the unsupplied counts per non-zero family, and the seconds. No expectation is applied. The record under `--out` (required) holds the prompt as sent, the status, the whole completion, the figures, the hits, the stored-chat facts, and any problem. Records are never committed. The summary splits turns into tripped per family, clean, and errors. A record that cannot be written moves its turn to `error`. Exit 0 iff every turn completed, every stored chat was deleted with none unverified, and the record was written.
- **The stored-chat watch** (ruling (e)). After each post, the sentinel finder reads chats that are new since that turn's before-listing. It deletes those whose messages carry the run's tag and leaves the rest alone (slice-1 ticket 68's rule). The finder never raises. If the watch fails after a completed turn, the completion, the judgement, and the record are kept, and the row is marked unverified. The `cleanup` row reads `<n> chats stored, <m> deleted`. `owuiturn`'s candidate reader is made public for the finder, with no behaviour change.
- **`--case <id>`** (repeatable, every mode) narrows the retained set to the named ids, in file order. An unknown or retired id is refused before sign-in, with every absent id named. The guard's count, the browser mode's search refusal, the dry run, and the `preconditions` row all read the selection.
- **Seven refusals**, each before the root check and each printing its fix: `--unfiltered` with `--browser`, `--stream`, `--probe-inlet`, or `--concurrent` above 1; `--unfiltered` without `--out`; an absent `--case` id; and a selected search case under `--unfiltered`.
- **Tests**: `tests/test_turns.py`'s in-memory frontend learns the bare post, and `tests/test_turns_browser.py` covers `--case` and the `--browser` refusal. There are 16 new tests, the AST stdlib tripwire is unchanged, and the gate is green (179 affected tests).
