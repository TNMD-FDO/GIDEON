## Changes

This release implements slice-0 ticket 24 under the plan `docs/1-plans/rebuilt-box-pre-restore-push.plan.md`. On a rebuilt box, the total-loss runbook's §5 step 4 — `restore --from target` on the fresh stack `apply` has just brought up — stopped at the `pre-restore` stage: the stage took the fresh stack's own set and pushed it, `backup push` linked against the office's newest snapshot, saw every byte transfer, and refused with the §3.7 full-copy guard's one-filesystem fix. The guard's message is right for the retention overrun it exists for and misleading on a rebuilt box, whose fresh stack shares no path with the office's earlier snapshots. Since `v0.1.77` both the acceptance harness and the runbook worked around it by stopping the stack first, so the runbook's §5 had never been run with the stack the product leaves running.

- **The rule** (`gideon/host/restore.py`, `_pre_restore_stage`). The stage's order is now running, fresh, partial, incomplete, take, push:
  - A stack whose local staging lists **no entry at all** — `sets/` absent, as on every rebuilt box after step 3, or present and empty — is a **fresh stack**: an ok row, no set taken, no push made, the `restore` audit row's `pre_restore_label` null as before. A fresh stack has nothing a safety set would protect.
  - The row's text is the new public constant `FRESH_STACK_SKIPPED_DETAIL`, in the shape of `install.ENGINE_VERIFY_SKIPPED_DETAIL`: the acceptance harness imports it rather than restating it, and a test holds the two together.
  - A staging that lists entries **none of which is complete** — a `.partial` from an interrupted run, a manifest that does not parse — is damage, not freshness, and refuses with a count of the incomplete entries and a two-path fix: `backup run` to complete a set on a live box, or the stack stopped first on a rebuilt box whose nightly was interrupted. A check that read damage as freshness would have replaced a live box without its safety set.
  - A staging tree that cannot be listed is a failed row with the set fix, as `_staging_bound` already does.
  - Every existing row is kept: a stopped stack still reads "skipped (stack not running)"; a partly running stack holding a set meets the Postgres partial refusal before the incomplete classification, so its fix stays one it can follow; a running stack with a set takes, pushes, and stops on a push failure exactly as before.
- **The harness** (`tools/acceptance/{run,fullrestore}.py`). `FULL_RESTORE_STAGES` loses its `stop` row, so `restore` follows `snapshot` with the fresh stack running, and `stop_stack` is gone with it. `restore_target` now requires the `pre-restore` detail to equal the imported constant; the old "skipped (stack not running)" is red by design, since a stopped stack in this form means the VM's apply did not leave it up.
- **The runbook** (`docs/runbooks/backup-restore.md` §5 step 4). The interim stop and its parenthesis go. The restore runs on the running fresh stack and skips its pre-restore set by the rule. One conditional sentence keeps the `docker compose … down` line for the case that needs it: if the 01:00 nightly ran between steps 3 and 4, the stack holds a set, is not fresh, and is stopped first.
- **The leaves.** The backup leaf's `restore` line states the rule and names the constant; the tools leaf's full-restore table loses `stop` and its invariant becomes the stack left running with the product's fresh-stack row required, ticket 24 joining the entry's list.
- **The glossary** (`CONTEXT.md`, via `/domain-modeling`): **Fresh stack** added beside a sharpened **Pre-restore set** (taken of a running system that holds a set to protect; a fresh stack takes none).
- **Tests.** `tests/test_restore.py` adds the fresh-stack contracts (`sets/` absent and listed empty: the constant's row, neither `run_backup_run` nor `run_backup_push` called, `fetch` reached), the `.partial`-only and unparseable-manifest refusals with both paths in the fix, the partly running fresh stack's skip against the partly running incomplete staging's partial refusal, the stopped fresh stack's unchanged row, the push failure, and the unlistable tree. `tests/test_acceptance.py` holds the table without `stop`, `restore` at `snapshot` plus one, the required text taken from `gideon.host.restore`'s constant by import, the old row red, and no `down` command reaching the VM. The gate is green: `ruff`, `mypy` (206 files), and the suite.
- **Ruling (b) narrowed.** The ticket's "no complete set" reads as "no set at all": a staging of incomplete entries alone refuses rather than counting as fresh. The one residual is a live box whose `sets/` was removed by hand, which reads as fresh — accepted, since neither `pgbackrest/` nor `push.json` is a surer signal.
