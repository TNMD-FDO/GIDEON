## Changes

This release implements slice-1 ticket 79, under the plan `docs/1-plans/public-repository-is-the-application-alone.plan.md`. On 2026-09-16 the CSA ruled that the public `TNMD-FDO/GIDEON` carries GIDEON the application and nothing used to develop it. Nothing that leaves is confidential: this is a cleanup, and the history stays (ruling e).

- **The boundary** (`tools/exportboundary.py`, mirrored line for line in `.gitattributes`) grows from thirteen prefixes to thirty-one:
  - `.claude/` as a whole, replacing the skills line;
  - `CLAUDE.md`, `CONTEXT.md`, `docs/agents/`, `skills-lock.json`, `.out-of-scope/`, and `docs/4-unit-tests/`;
  - the release-note template and the box ledger;
  - `tools/tracker.py` and `tools/cycles.py`;
  - the eight test modules whose subject leaves.

  `ownership.py`, `gate.py`, and `exportboundary.py` stay (ruling a). A file prefix is written without a trailing slash, since git matches `name/` only to a directory. The module gains one predicate: a path is *absent from the export* when it is excluded and does not exist.
- **The boundary test** (`tests/test_export_boundary.py`):
  - The attributes rule decides from the tree whether a prefix is a file or a directory. It also reports an `export-ignore` line whose slash contradicts the shape of an existing path.
  - The text rule now skips every excluded file. Its exemption is two prefixes: the list itself and `tools/pinwatch/`, whose modules read the skills' record from `origin/main` at run time.
  - New seeded cases hold the shape finding, the exempt directory, and the predicate's contract.
- **The kept tree stays self-contained.**
  - Skips in an export tree: in `test_release_notes.py` (the template case), `test_pinwatch.py`, `test_pinwatch_bumped.py`, and `test_research_notes.py`, a case skips when a record it reads is absent from the export.
  - Adaptations: `test_office_values.py` and `test_lock_coupling.py` adapt instead of skipping, so the three locks' coupling is still enforced in the public tree.
  - `test_archi_budget.py`'s link finder skips an excluded target except its own documents (`CLAUDE.md`, `CONTEXT.md`, `docs/agents/`), so the development tree keeps every link check it had.
  - Removed guards: six leaving modules drop `in_export_tree` guards that could no longer fire.
- **The contribution surface** now points at access to the development repository:
  - A third issue form, `.github/ISSUE_TEMPLATE/access-request.yml`, asks who the requester is and what they want to work on.
  - The pull-request template keeps the CC0 dedication (ADR-0004). It drops the checklist and says that a pull request here is not merged, because each release's export overwrites `main`.
  - `CONTRIBUTING.md` and the README's `## Contributing` point at the form.
- **The kept documents' references.** Every link from a kept document to a leaving file is now backticked text naming it as the development repository's (ticket 56's ruling c). This covers six rows of the README's Documentation table, `docs/ARCHI.md` §§1, 2, 4, 8, 15, 16, and 17, and the tools and tests leaves. `docs/ARCHI-rules.md`'s budgets paragraph says the export tree has no `CLAUDE.md` or agent document. The five product references in the ticket's item 2 are unchanged.
- **The proof** is recorded on ticket 79. An archive of the staged tree, extracted to an empty directory, held 539 files and passed `ruff`, `mypy`, and `pytest`: 1,386 passed and 57 skipped, the skips counted by module on the ticket. The tag's public `checks` run is this release's export poll.
- **Ticket 78** gains a dated correction: the chooser shows three forms, and the template shows the not-merged statement.
