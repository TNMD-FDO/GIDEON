## Changes

This release implements general-turn ticket 10 under the plan `docs/1-plans/pypi-watch-kind.plan.md`: the pin watch's second watch kind, so ticket 01's `gideon` image can install its Python packages as watched build arguments. Per the maintainer's ruling at discovery, the watch reads PyPI's PEP 691 Index API rather than the project JSON, whose `releases` key PyPI lists as deprecated. Rulings (a)–(d) stand. No committed pin uses the kind yet, so `images.lock` is untouched and nothing was applied on the box.

- **The lock's shape** (`gideon/host/images.py`): `PypiWatch(project)` beside `AptWatch`, and `PYPI_PROJECT_NAME`, which is PEP 503's normalized form. The watch loop tells the kind by the entry's keys. Both kinds' keys in one entry, no kind's key, an unknown key (the hint can name `pypi_project`), an empty or non-string value, a valid name in another spelling (the refusal names the normalized one), and a string that is no project name are each refused with the host leaf's fix. The apt path is byte for byte as before. No PyPI host appears under `gideon/`.
- **The source** (`tools/pinwatch/pypi.py`, new): the index root, the `Accept` value, the supported API major, and the project page root are the module's constants. It has a stable-version order from PEP 440 Appendix B's own pattern, where a final or post release is stable and a pre-release, dev, or local version is not. Each file is attributed to a version by its filename, anchored on the project name. The reader validates the reply before using it: a JSON body, the PEP 629 major, the PEP 700 lists, PEP 592 yanks as a boolean or a reason, PEP 792 quarantine, no duplicate canonical version, and no file of an unlisted version. It returns PyPI's listed string for the newest stable release above the value that has an unyanked file. **The guard**: a release passed over while any file stands unattributed is a `FetchError` naming the files, so a failure shows as one failed row and is never a silent skip.
- **The pin** (`tools/pinwatch/pins.py`): `PypiProjectPin` beside `AptPackagePin` has the same id shape (`images.<name>.build_args.<ARG>`) and `proposal=True`, and the release page is its upstream link. Both argument pins narrow their entry to their own kind. `pin_registry` picks the class by the entry's type, in the lock's order.
- **The patch** (`tools/pinwatch/patch.py`): a replacement for a plain string scalar whose plain form would not load back as the same string, such as `2.0` or `20260919`, is written double-quoted. Every bump that already succeeded renders the same bytes.
- **Tests**: `tests/test_pinwatch_pypi.py` (new) covers the order, the attribution table, and Starlette's recorded reply (`tests/fixtures/pinwatch/pypi/starlette.json`, an excerpt), whose expectations are derived from the fixture. Hand-built replies cover the shapes the recording lacks, and the `Accept` header is asserted. `tests/test_pinwatch.py` covers the pin, the registry's order, the owned paths, the value-only patch with `inputs_digest` differing, the quoted rendering end to end, the vocabulary, and the CLI's failed rows and dry run. `tests/test_images_lock.py` covers the kind's acceptance and each refusal. The apt tests stand as written.
