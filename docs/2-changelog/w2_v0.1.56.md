## Changes

A TRIP cycle's three phases ran in one session on one model at one effort, the release's turns at the session's peak context (the audit `.scratch/workflow/assets/27-trip-delta-audit-and-phase-routing.md`: the plan a tenth of a cycle's tokens, implement 60–90 % over about 140 turns, the release the most expensive turns of the cycle when it is its own phase). This release makes the phase boundary a session boundary, adds the launcher that starts each phase on its paired model and effort, holds the pairing in one place, and splits the cycles record per phase so the pairing is corrected by the record (ADR-0017; workflow ticket 27, its antecedents workflow tickets 19 and 20).

- **The phase boundary is a session boundary** (CLAUDE.md's Ticket sizing; the `phase-handoff` blocks in `TRIP-1-plan` and `TRIP-2-implement`): "Approved — implement now" and the `--yolo` path after `APPROVED`, and "Yes, everything is complete", never chain the Skill tool — they print the handoff as one-line fenced blocks (the launcher's `bin/trip implement|release <plan>[ --yolo]`, the typed `/TRIP-2-implement` or `/TRIP-3-release` line for a session continued from a phone, `/effort <level>` only when the pairing changes) and end the turn; the user leaves with `/exit`, keeping the worktree. A clean exit is not a handoff — "stop here", "remaining items", and an early `/exit` all exit 0 — so when the environment carries `TRIP_HANDOFF` the block also writes the next phase's arguments to that file with one plain `printf`, and nothing in a session started by hand. The 150-turn seam holds within a phase.
- **The launcher** (`bin/trip`, bash in the primary checkout, resolved from its own path so `bin/trip …` from `~/src/GIDEON`, the absolute path, and a `~/.local/bin` symlink are one command): `plan <ticket>`, `implement <plan>`, `release <plan>`, each printing one line naming the phase, the model, and the effort, then running `claude --model <m> --effort <e> "/TRIP-n-… <path>[ --yolo]"` in the foreground and returning its status; `cycle <ticket>` runs plan, then implement only when the handoff record names `implement` and a plan path existing in the primary or the cycle's worktree, then release the same way, otherwise stopping with the command that resumes the chain. The pairing table is six assignments at the top — plan Fable xhigh, implement Fable high, release Fable high, rung 1 (the ladder and the account are workflow ticket 28's); `--model` and `--effort` after the subcommand replace the table's values for that session, `--yolo` passes through, `--dry-run` prints the command and the handoff path and runs nothing, `--help` and a wrong argument exit 2. Refusals with their fix: a copy invoked from under `.claude/worktrees/`, a path resolving (symlinks and `..` followed, the code review's finding) outside the primary and every worktree. `bin` joins `tools/exportboundary.py`'s excluded prefixes and `.gitattributes`; the launcher is never release content.
