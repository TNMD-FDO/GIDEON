## Changes

- **The tripwire** (slice-0 ticket 13): `tests/test_lock_coupling.py` loads `images.lock` and `host.lock` through the product loaders, builds the set of values the pin watch can move (every image source and digest; `registry_image`'s tagged source and digest; `gh_runner.version` and `.sha256`; `minimums.toolkit`; `driver.branch`; `acceptance_vm_image.url` and `.sha256`) plus the three a person moves after an on-box converge (`driver.tested`, `kernel_tested`, `driver.keyring_sha256`), and scans every `*.py` under `tests/` for any of them as a whole token — not touching a letter or digit on either side, so `nvidia-driver-pinning-595` and `595.91.07-1ubuntu1` count while a branch inside a hex digest does not. Comments count; `tests/fixtures/` is excluded because the render fixtures embed both locks by design and are regenerated on every bump branch. A finding is one line, `path:line: <key path> (<value>)`, and the message ends with the fix. Three more contracts pin the set's completeness (it grows with `images.lock`; null `driver.tested`/`kernel_tested` contribute nothing), the negative case over an in-memory source string (criterion 2), and the boundary rule's caught/not-caught shapes. The two integer floors are the rule's, not the scan's.
- **The cleanup**: the tripwire's first run on `main` found 64 lines in five modules — and the pin watch's open PR #2 (`host.driver.branch 595 → 610`) was red on three of them (run 33601681445), the same bug class as PR #1 one lock over. `test_host_lock.py`'s committed-lock contract now asserts shape (grammars `VERSION`/`IMAGE_REFERENCE`, newly exported from `gideon/host/lock.py`; types; the reference host's recorded facts), never pin values, and its fixture text is fictitious; `test_images_lock.py` pins `docker.io/library/example:1.0` with a repeated-hex digest and drops two dead constants; `test_host_steps.py` derives every driver, registry, runner, and acceptance-image fake from one module-level `HOST_LOCK` (the NVIDIA step judges the installed driver by `driver.branch`, so its fakes derive from the branch; the KVM image path is the lock URL's basename, as the step computes it); `test_preflight_checks.py` derives the matching driver from `driver.tested` and computes the above-tested one; `test_pinwatch.py` runs in a fictitious upstream world (`docker.io/library/example`, `ghcr.io/example-org/example`, `example:1@sha256:…`, runner `1000.0.0`, toolkit `100.0.0`, branches `1000`/`1010`, a fictitious cloud-image series). Verified in a throwaway worktree of PR #2's branch with the change copied on top: 407 passed, the three failures gone, the tripwire green against the bumped lock — and that proof caught one more: the pagination test's real frontend repository and tags were current on PR #2's pre-merge base. A stale real value is a coupling too; test-owned values are fictitious, never merely "not current".
- **The rulings** (discovery, 2026-09-02): the value set is everything the pin watch moves plus the on-box tested values, wider than the ticket's "digest, sha256, or tagged source", because PR #2's failures were a branch and a version; no allowlist — the loaders' contract tests are scanned like every other module, superseding the ticket's exemption clause; raw text, whole-token, letter-or-digit boundaries (Codex plan review, 2 rounds: the NVIDIA fakes derive from the branch, not `driver.tested`; the host-lock contract asserts no grammar the validator does not enforce; boundaries are alphanumeric so a digit-only branch cannot match inside a fictitious hex digest).
