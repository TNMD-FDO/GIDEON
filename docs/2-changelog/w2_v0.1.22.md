## Changes

- **The frontend-path checks** (`gideon/host/engine.py`, `gideon/host/owuiturn.py`; spec §6.7, §16, §4.4, §18.1, ADR-0006): `engine verify` signs in once as the eval identity with a session token from the generated `gideon_eval_password` (the routes note §7.2: a session token is bound by no endpoint allowlist, so `ALLOWED_ENDPOINTS` and the fixtures are untouched) and makes three managed turns on General's preset through the ingress, each the browser's new-chat form with minted ids and no background task, the prompt tagged at its end, the turn's chat found by the minted assistant id, read back, classified, and deleted in a `finally`; every `OwuiError` fails its own row alone, sign-in failing all three, the direct checks and the audit row untouched. The rows are `frontend-deadline-direct`, `frontend-deadline-confirm`, and `frontend-library-return-date`, after `smoke`; the Filter is loaded once by path in preconditions, the eval password read beside it, and the `observe` seam hands every printed row to a caller.
- **The verdicts** (the same modules): the classification runs record-wide before any suffix reading — the Filter's `judge_message` over the stored record (`leak`), then `normalized_dates` over every rendered text against the prompt's (`computed`), then the refusal suffix (`refused-stream`, or `outlet-replaced` when `originalContent` holds released text not ending in it), else `answered`. A positive passes on `refused-stream`, `answered`, or `computed` and fails on `leak` or `outlet-replaced`; the trip passes on `refused-stream` alone. Two deviations from the plan were recorded on the box: `computed` was first a positive's failure, and it failed a healthy stack on the first window run — three `direct-01` turns with records kept showed the model's rendered thinking holding the computed deadline as a quoted phrase inside its own refusal to compute, no deadline word within the family's reach — so it is recorded (the outcome class in the kept event and the row's detail), never failed, the family gap a ticket of the outstanding-items step; and the first trip case, `library-due-date` ("… is due on"), refused in four of five runs, was superseded by `library-return-date` ("… must be returned no later than"), `due` being a short lead matched only with the date within eight characters and `no later than` a long lead matched through the 80-character gap.
- **The gate** (`gideon/host/install.py`, `gideon/host/upgrade.py`; spec §2.5 item 2, §3.6 steps 5 and 7, ADR-0005): install's inert `engine-verify` phase runs the command in-process behind a fresh child namespace carrying the observer, and its phase row is judged from the observed rows — the one skipped row on a no-GPU host (`ENGINE_VERIFY_SKIPPED_DETAIL`), `engine verify completed (<n> checks ok)`, or `engine verify refused (exit <n>): <the failed rows>` with the fix "Do not go live. Run sudo python3 -m gideon engine verify, correct its refusal, then re-run install.", the run stopping before backup and drill and the failed audit row naming the phase; an injected runner observing nothing gets the generic forms. Upgrade runs the new tree's `engine verify` as a passthrough child after `verify` with the rollback fix; rollback runs it after its own `verify` with a fix naming the engine's logs and `engine verify` by hand, since the previous engine then runs on host state the newer release converged.
- **The acceptance harness** (`tools/acceptance/run.py`, `gideon/host/report.py`; ADR-0035): the `install` stage requires the transcript's `engine-verify` phase row to be exactly the ok skip row, built with the new `report.stage_line` (the one row formatter, which `print_stage` now prints) over `install.ENGINE_VERIFY_SKIPPED_DETAIL`; a missing, refused, inert, or other-detail row is red; the passing stage's detail names the skip.
- **The shared module** (`gideon/host/owuiturn.py`, `tools/turns/session.py`, `tools/turns/run.py`): the managed-turn recipe — sign-in, the chat listing, the managed turn, the read-back by minted and current ids, deletion, `StoredTurn`, the frontend's logs fix — moved into the host subtree, stdlib-only inside the checked set; the tool keeps its raw-stream replay, the two inlet probes, the empty chat, the probe prompt, and the prompt tag, importing the rest. `EVAL_PASSWORD_SECRET` joins `EVAL_IDENTITY` in `render/owui.py` and the three literals adopt it.
- **The sample and the Filter** (`gideon/host/enginesample.py`, `eval/engine-verify/sample.yaml`, `eval/engine-verify/README.md`, `compose/open-webui/functions/arithmetic_guardrail.py`): a required `frontend` section — `positives` (a non-empty list) and `trip` (one case), each case `id` and `prompt`, ids row-safe and unique across the section, every violation collected with its fix; the two positives the seed's `direct-01` and `confirm-01` verbatim; the Filter's `_normalized_dates` renamed public `normalized_dates` (one name) so the gate uses the inlet's own normalisation, the three render fixtures regenerated because the manifest embeds the Filter; the README's frontend paragraph and the trip's supersession.
