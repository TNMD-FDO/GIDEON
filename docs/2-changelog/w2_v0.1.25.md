## Changes

- **The service** (`gideon/host/render/compose.py`, `render/searxng.py`): `searxng` joins the Compose project after the frontend and the engine while `web.search` is on — the pinned image run as shipped (its entrypoint, default user, and command untouched), `restart: unless-stopped`, `TZ`, granian's access log pinned off by name, its settings bind-mounted read-only at the entrypoint's config path, its env file in the raw format the frontend's uses, a `wget` healthcheck on `/healthz` (the image carries no `curl` and declares no `HEALTHCHECK`), the `gideon` network alone, no `ports`, no `user`, no `depends_on`. Absent when `web.search` is off; on a GPU host and a no-GPU host alike, never in the drill.
- **The settings** (`searxng/settings.yml`, owner `searxng`): `use_default_settings` written as a mapping whose `engines.keep_only` is the site's `web.engines`, then every kept engine re-enabled by name — `bing` and `google` are `disabled: true` in SearXNG's own defaults and `keep_only` governs membership alone — so Google is never queried unless the office names it; the `html` and `json` formats (the frontend's JSON request is refused with 403 otherwise); the autocomplete and favicon resolvers, the limiter, the public-instance flag, and the image proxy off; debug off, which leaves the process at WARNING. No `secret_key` in the file: the env supplies it. Every value the upstream default made a rendered fact (ADR-0017), each with its why beside it.
- **The env file** (`searxng/env`, 0600, `secret`): `SEARXNG_SECRET` from `searxng_secret_key`, a new generated secret in `SECRET_REGISTRY` (SearXNG refuses to start on its placeholder and has no `_FILE` form), and under `egress_proxy` the proxy URL with its credentials, built by the one proxy helper the frontend's env now shares (`render/proxy.py`); the pinned image's HTTP client honours the proxy environment while `outgoing.proxies` is unset. The render command reads the secret when search is on and, before the first apply, refuses naming `apply`. The backup set's derived exclusions carry the file on their own.
- **The frontend's connection** (`render/owui.py`): with search on and the frontend connected, `ENABLE_WEB_SEARCH`, `WEB_SEARCH_ENGINE=searxng`, the bare `/search` endpoint on the service's name and port, three results a query, the `safe_web` loader, the snippet shortcut off, the loader's trust-env switch and SSL verification pinned, the confirmation dialog on with `WEB_SEARCH_CONFIRMATION_TEXT` — §15's reminder, verbatim, a release constant — and `WEB_SEARCH_DOMAIN_FILTER_LIST` as the JSON array the pinned frontend parses (`[]` when empty); `ENABLE_WEB_SEARCH=false` alone otherwise; `BYPASS_WEB_SEARCH_EMBEDDING_AND_RETRIEVAL=true` on every host in every state, beside the existing bypass; `searxng` among the `NO_PROXY` names while the service is rendered. General's record does not change.
- **Site validation** (`host/site.py`, `site_schema.py`, `config/site.schema.json`, `config/site.example.yaml`): `web.engines` accepts only `WEB_ENGINE_VALUES` — duckduckgo, brave, bing, startpage, wikipedia, google — refusing an unknown name, a repeated one, or an empty list while `web.search` is on, each with its fix; `web.domain_filter` entries are bare lowercase domain names (`DOMAIN_NAME`; a leading `!`, a scheme, a path, or a dotted address refused, since the frontend reads a `!` as a block rule and an address as a network); the schema carries both as the items' enum and pattern; the example file says so.
- **Observability** (`render/prometheus.py`, `render/grafana.py`, `compose/grafana/provisioning/alerting/search-probe-rule.yaml.tmpl`): a `$search_jobs` blackbox probe of SearXNG's health and a "Search probe failing" page-class rule on `probe_success{job="search"}` for ten minutes, each its own template or block rendered only while the service is and as one blank line otherwise, the `$gpu_jobs`/`$gpu_rules` pattern; "Target down" reads a scrape's `up`, which the blackbox exporter keeps at 1 while a probe fails, so every probe pages through its own rule.
- **The pin watch** (`tools/pinwatch/oci.py`, `pins.py`): `TagShape` gains a kind; SearXNG's `<year>.<month>.<day>-<hash>` tags are the dated-commit shape, the hash never part of it and a year rollover never a major bump. The newest date wins; a same-date tie — several builds on the newest date, or another build on the pin's own date — is broken by each candidate's image-configuration `created` time read through the registry's index, manifest, and configuration blob, the pin itself weighed on its own date so an earlier build never replaces it; an equal or missing time is one `failed` row proposing nothing. `images.lock` gains the mirrored `searxng` pin at its dated tag with the grammar in its comment.
- **The research note** `docs/research/searxng-service-and-owui-search.md`, verified against SearXNG at the pinned tag's commit and Open WebUI v0.11.3: the entrypoint's behaviour, the secret-key rule, `keep_only`'s semantics, the client library's proxy inheritance, the logging levels and granian's access-log switch, the frontend's search variables, what its SearXNG client sends, the per-turn page bound (a prompt's "1–3", not a code cap), when the dialog fires, and two failure-path log lines that carry query text above DEBUG — handed to ticket 16.
