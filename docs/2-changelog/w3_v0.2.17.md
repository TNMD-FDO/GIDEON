## Changes

This release implements slice-2 ticket 05 under the plan `docs/1-plans/reference-run-and-regression-list.plan.md`, ADR-0023's gate and spec §18.5–§18.6. `eval run` gated `extraction` on the scorer's two bounds alone; a case that passed at the last release and fails now was invisible while the per-type figures stayed inside the bounds. The comparing half now reads a committed file, so a fresh install, the hosted checks, and a box whose `eval_runs` rows have aged out all gate without history.

- **The reference file** (`gideon/evaluation/reference.py`, new; its docstring the format's one home): the format number, the header keys, the two verdict words, and the path rule `eval/reference/<slice>/<list>.json` as release constants. One file per id list, mirroring the export boundary's split, so `harvest.json` leaves with `harvest.ids` and an exported tree's reference names only cases the exported set holds. The header carries the format number, the version triple, `hardware_profile`, `tag`, `slice`, `list`, `repeats`, and `set_digest`; the body is `cases`, id → `pass` | `fail`, a case with repeats passing only when every repeat did. The run id, timestamps, latency, metrics, the judge, `git_sha`, `kind`, and `stack` are excluded by rule, and no key can carry case text. Metrics are out by ruling (c): ticket 02's branch shifts existing cases' per-type counts whenever a family lands, so metrics would rewrite the file where verdicts show only what changed.
- **The reader and the comparison**: the reader reports every structural finding at once in the loader's `Finding` shape, content-free, and refuses bytes unequal to their own re-serialisation. The comparison yields *regressed* (pass there, fail now — the only list that blocks), *gained*, *new*, and *dropped*, or one of two refusals. **Corruption is never absence**: a file that does not read, headers disagreeing across a slice's files, a file naming no id list, or a *partial* reference is `malformed`; absence is no reference file for the slice at all. `malformed`'s fix is to restore the slice's files from the release, or to remove every one of them and re-record — never the writer's line alone, since the writer refuses on the same findings. `other-version` is sound and not comparable, and the writer is its fix.
- **The comparison in `eval run`** (`gideon/evaluation/command.py`): after `run` and before `record`, over the release checkout's references whatever `--set` names, so the planted-regression proof works. One `reference: <outcome>` line from the closed vocabulary, the reference's tag and version, then one line of ids per non-empty list; findings to stderr. `record` receives the whole gate's verdict, and the `gate` row carries both halves with the fix of whichever failed, the bounds' first when both do. A refusal fails the row **after** `record`, because the first run of a new set version is the one its reference is written from — refusing at `load` would make that run unrecordable and the gate unrecoverable by its own instructions. Staleness never touches the exit code.
- **The writer** (`gideon/evaluation/reference_command.py`, new; `eval reference --run <id>`, ruling (a) — a subcommand, never a flag on `eval run`): `load` → `read` → `check` → `write`. `check` takes a run as the release's only when the checkout was clean with a non-null `git_sha`, no override was in force, the slice is the loaded set's, `eval_set_version` and `set_digest` equal it, the tag `v<product_version>` resolves to the row's `git_sha`, and the slice's current reference reads clean and is not regressed against. `write` writes one file per id list — a list with no evaluated case still gets its file, so the partition is total — hands each to the checkout root's owner, and reports `written` or `unchanged`.
- **The read** (`gideon/evaluation/record.py`): a reader-role constant equal to `stores.py`'s `gideon_ro_metrics`, held equal by test, and `read_run` — one statement, the run id bound as a `psql` variable after a UUID check in Python, selecting neither `metrics` nor `judge`. `gideon_eval` stays insert-only; `0004` already granted the `SELECT`, so no grant, role, or migration lands and nothing is written to Postgres by the writer.
- **The loader** (`gideon/evaluation/evalset.py`): `LoadedSet.slice_lists`, slice → list stem → ids in the digest's sorted order; `slices` stays the union. Findings, order, and the digest are unchanged.
- **The CLI** (`gideon/cli.py`): `eval reference --run <id>` beside `eval run`, behind `_guarded` with the same lazy import. It lands real, so `STUBS` did not move.
