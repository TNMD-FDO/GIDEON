# Changelog - Week 3, 16-09-2026, V. 0.1.72

**Release Date**: Week 3, 16-09-2026 at 17:34

**Object**: hotfix: v0.1.72 — the host-mode fakes answer exists from their dict alone

## Changes

- **Issue**: `v0.1.71`'s release declared this box the build box (`sudo python3 -m gideon host provision --build-box`, slice-0 ticket 21's dated comment), and from that moment nine tests were red on it: eight `RunnerTests` in `tests/test_host_provision.py` and `tests/test_preflight.py::PhaseA::test_build_box_only_step_is_a_skipped_pass_without_marker`, each asserting what a host without the marker does. `bin/release-export v0.1.71` runs the tag's tree through pytest on this box before it pushes, so it stopped red and pushed nothing; the tag's own tree keeps the old fake, so `v0.1.71` never exports and this tag exports in its turn, as the export's refusal says. CI never saw the nine: the hosted `checks` job holds no marker, and the self-hosted jobs run no pytest. The `checks` red on the tracker commit after the tag (run 35157774506) is `tests/test_turns.py::TurnHarness::test_concurrent_sessions_overlap_and_record_their_own_chats` asserting that some turn saw three candidate chats and seeing two — a timing defect of that test's own, recorded on the tracker, outside this hotfix.
- **Fix**: `FakeHost.exists` in `tests/test_host_provision.py` and the fake `Host.exists` in `tests/test_preflight.py` answer from the fake's file dict alone; the fallback to the real filesystem is gone. Both modules pass on the declared box (50 tests), and the whole gate is green in the worktree. `docs/4-unit-tests/TESTING.md` carries the rule beside its `FileNotFoundError` line: a fake `Host` never reads the real filesystem.
- **Root Cause**: both fakes returned `key in self.files or Path(path).exists()`, so any path the box itself holds answered true in a test that assumed it absent. No box had held a marker on a path these tests read until the build-box declaration, so the fallback was never exercised; the other fakes (`test_nogpu.py`, `test_host_steps.py`, `test_apply.py`) already answered from their dicts.

**Window**: none. The change is to two test modules, the testing doc, and the version; nothing on the box is applied or recreated. No release note or human read, since this is a pre-General 0.x tag. No acceptance run, since this is a patch tag. Tutorial skipped: a hotfix with no design decision.
