## Changes

This release implements slice-2 ticket 01 under the plan `docs/1-plans/extraction-grammar-contract-and-first-families.plan.md`. It lands the first half of §11.2's GIDEON regex grammar: the contract every exact-object extractor answers to, the three families chat text needs most, and the frozen extraction set that measures them. No question's text or span appears in this entry, the plan, a ticket, or a commit message (§19.4).

- **The contract** (`gideon/extraction/contract.py`): `ExactObject` (type, code-point offsets, verbatim text, key, pattern id, subsections) and the closed vocabulary of thirteen types, written once for both extractors. Five are landed here (`statute`, `guideline`, `court_rule`, `bare_section`, `bare_rule`). The other eight belong to ticket 02 and slices 3 and 4. A keyed type always carries a key and every other type never does, so a bare section or a bare rule can never yield an anchor key, whatever code path produced it. The key is ADR-0024's permanent key at section level (`/us/usc/t<title>/s<section>`, `ussg/<id>`, the USLM path of the rule set). Parenthesised designators stay in the span and are carried as `subsections`, never in the key. Key comparison folds case, because a section's letter cannot be derived from the text.
- **The grammar** (`gideon/extraction/grammar.py`, grammar version 1): six patterns with versioned ids (`usc/titled-section@1`, `usc/titled-list-member@1`, `usc/bare-section@1`, `ussg/id@1`, `rules/set-and-number@1`, `rules/bare-number@1`). They sit in a static registry, and each pattern declares the one type it emits. Every repeat is bounded. One hyphen rule covers ranges: a hyphen after a letter joins a hyphenated section; a digit-to-digit hyphen is a range of two endpoints only under a plural marker. The bare-section rule admits a markerless number only with a subsection or beside a closed cue list. It declines year-range numbers, text after a C.F.R. or state-code token, and a state code's two-hyphen shape. The bare rule declines inside the habeas-rules and Supreme Court Rules constructions, which are ticket 02's. Resolution follows a fixed family precedence and takes the longest match. `extract(text)` is the one entry point. It is pure and standard-library only, and an AST test holds the import rule.
- **The measure** (`gideon/extraction/scoring.py`): the active set over `supersedes`, the hit rule (type, offsets, subsections, and key where labelled), per-type precision and recall against the §11.2 bounds (≥ 0.95, ≥ 0.90), and a report that prints case ids, types, and offsets only. The landed types are an argument. The gate passes in the registry's declared types, so a family that emits nothing stays gated and fails on recall. The scorer reads no file, and ticket 04's `gideon eval run` reuses it unchanged.
- **The set** (`eval/sets/eval-v1/build-gates/`): `extraction.jsonl` holds `extraction-001`–`-040`, one case per harvest record, and 20 of them have no object. `extraction-invented.jsonl` holds `extraction-041`–`-062`, the invented block the maintainer ruled at the claim, because the harvest holds no Guidelines id and at most one Federal Rules cite. Four of its cases have no object, and it carries one label for each of four unlanded neighbours, so the declines are measured. Every case was labelled from the text alone before any pattern existed. The invented block was also relabelled blind by a second model (82 of 82 labels agreed), and the maintainer read every case (`CSA-1`, 2026-09-19). Each file is byte-pinned by prefix, at (40, `dc1e0c92…2d462e`) and (22, `8c057174…298a0`). The README holds the label guide and the never-edited rule. A correction is a new id that supersedes the old one.
- **The gate**, pooled over both files: `statute` 19 hits, `guideline` 12, `court_rule` 11, `bare_section` 13, `bare_rule` 10, all with no false hit and no miss, so precision and recall are 1.000 per landed type. Over the invented block alone (the exported tree's view) every landed type is also at 1.000. The unlanded types are reported and not gated: `caption` 10, `state_code` 2, and one each of `case_cite`, `regulation`, `appendix_statute`, `habeas_rule`, and `scotus_rule`. The gate runs in the hosted `checks` job through `python -m tools.gate --all`.
