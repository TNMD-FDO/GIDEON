## Changes

This release implements general-turn ticket 04 under the plan `docs/1-plans/branch-gate-function.plan.md`, ADR-0045's ruling (d). The branch refusal leaves the arithmetic guardrail's inlet for an inlet-only global Function of its own, so the guardrail retires whole at ticket 09 with nothing left to carve. The refusal's text and rule are unchanged (ADR-0043).

- **The gate** (`compose/open-webui/functions/branch_gate.py`, new; frontmatter version 1): `BRANCH_REFUSAL` byte for byte, the eval identity's address (held equal to `render/owui.py`'s by a test), `BranchRefusal`, `_is_preset` over `info.base_model_id`, and a `Filter.inlet(body, __user__, __model__)` alone. A `user`-role request whose model entry is not a preset is refused, an unusable `__user__` too (fail closed), and admins and the eval identity pass. It is standard library only, with no Valves, toggle, requirements line, stream, outlet, `__metadata__`, state, or message read.
- **The inlet order**: neither Function has Valves, so the pinned frontend's `(priority, id)` sort runs `gideon-arithmetic-guardrail` before `gideon-branch-gate` (`docs/research/owui-filter-function.md` §3.3). A raising inlet ends the chain, so a request failing both gates reads the session refusal and the gate never runs. The order is stated in the gate's header and beside its id in the render module, and `tests/test_branch_gate.py` holds it.
- **The manifest row** (`gideon/host/render/owui.py`): the gate's template, id, name, description, and a global, active row builder over `_function_row`. The manifest's `functions` carry three rows in id order and `template_paths` names the template. `bootstrap` is generic over the rows and did not change. The render fixtures were regenerated.
- **The guardrail's carve** (`arithmetic_guardrail.py`, version 10 → 11): `BRANCH_REFUSAL`, `BranchRefusal`, `_is_preset`, the inlet's branch check, and its `__model__` parameter leave; the stash and the session gate stand. `tests/test_arithmetic_guardrail.py` loses the branch tests, and its inlet calls drop the model argument. A negative holds the carve.
- **The equality test** (`tests/test_guardrail_equality.py`): the three carved names leave the Function-only set, and `tests/test_branch_gate.py` joins the held by-path users of the guardrail's file for its inlet-order test.
- **The turn harness** (`tools/turns/`): rebased over `v0.2.8`'s `GateTexts`. Under `--probe-inlet`, `classify.load_gate_texts` reads the session refusal from the guardrail's file and the branch refusal from the gate's (`BRANCH_GATE_FUNCTION`). Either load failure raises `GateTextUnavailable`, which carries the path and never the cause's text, and it prints as one `preconditions` row naming that file. A run without the flag opens neither file. `run` refuses a probe spec with no texts before any sign-in. Row names, order, and the record's shape did not change.
- **The contract job** (`tests/contract/owui_apply_manifest.py`): the gate takes the Filters' hand edits and hand delete, and Function rows are indexed by id. The first run by hand on the box failed on the listing's order: the pinned list route answered neither id order nor push order. As the plan's Risk bullet ruled, the listing is compared as a set, and the second run was OK.
- **On the box** (`.scratch/general-turn/assets/04-on-box.txt`): `render --diff` from the worktree showed the manifest's and the four units' hunks and `Services apply would recreate: none`. Two applies ran, each with the `apply-manifest` row ok. In the users seat's `--probe-inlet` run, `inlet-base-model` was refused with the branch refusal (HTTP 400), `inlet-bare` got the session refusal, and `inlet-chat-id` and the case answered on General. The eval identity's API-mode run answered on General. The proof ran before the rebase. After it, the probe's texts load through `load_gate_texts` and the unit tests hold the rows.
- **Architecture**: the map's §2 and §8 rows, §4's tree comment, §14's fail-safe sentence, and §16's hidden-base bullet are phrase swaps. `engine-frontend.md` gains the gate's Inventory row, its constants and test module, and the split of the session gate from the branch gate with the inlet order. `render-apply.md` now lists three Function rows, and `tools.md` says the harness loads three Functions by path.
