## Changes

- **The set** (`gideon backup run`, `gideon/host/backup.py`, `backupset.py`; spec §19.1, ADR-0026): one `/data/backup-staging/sets/<label>/` per run — `files/<root>/` for the four snapshotted roots (`/etc/gideon` minus `secrets/` and the frontend's secret env file, the checkout minus tool caches, `/data/registry`, `/data/bulk/openwebui`) taken with `rsync --link-dest` against the previous set and a hard-link verdict over a sample (`linked 98 of 98 sampled`; zero links with a previous set fails the run, since a full copy would hide a retention overrun); `secrets.tar.age` from a `tar | age` pipeline under `pipefail` (plaintext never on disk); the pgBackRest backup (full when `--full`, `--label`, or no full within seven days; else incremental; labelled and pre-restore fulls never auto-expire); then **the archive boundary** — the time captured before pgBackRest's `check` forces and confirms a WAL switch — so every point-in-time bound is a recorded fact, never a clock; exact row counts for both databases; and `manifest.json`: every file and directory of the four roots and of the repository (a fifth, inventory-only root) with sha256, size, owner, group, mode, and mtime, each root itself as `.`, repository hashes carried forward for unchanged files, the tarball's hash, the recipient, and a keyed secrets fingerprint. A set is complete only once its manifest exists (`.partial` until then); local sets older than `backup.local_days` and day-old partials are pruned; the repository expires under time-based retention equal to `local_days`.
- **The push** (`gideon backup push [--verify-all]`; §3.7): `push.json` (the snapshot's coverage record) rides in the staging directory, then one `rsync -aH --no-owner --no-group --delete --stats` over SSH to `<backup.target.path>/<label>.partial/` with `--link-dest` against the newest complete snapshot (a transfer above 90 % of the total when a previous snapshot exists fails the push: the target is not keeping snapshots on one filesystem), a remote rename, pruning of snapshots older than `backup.remote_days`, and **the off-box check**: the newest set's manifest, `push.json`, the tarball, pgBackRest's `backup.info`, `archive.info`, and the set's backup manifest (all mandatory) plus 1 % of every root, streamed to the target's `sha256sum -c -` on stdin; `--verify-all` re-hashes every inventoried file. The plain NAS account cannot store ownership; the manifest carries it. Preflight's `backup-ssh` check now also proves `rsync` and a working `sha256sum -c` on the target.
- **Restore** (`gideon restore --from staging|target [--at <ts>]`, `restore.py`; §19.2, ADR-0005): selects the files set (newest, or newest finished by `--at`) and, for `target`, the **oldest snapshot whose `archive_through` covers `--at`**; takes a `pre-restore-<ts>` full first when the whole stack is running (a partially running stack refuses; for `target` the safety set is pushed too); fetches a remote snapshot into a side directory with `-H` and **re-owns the whole snapshot from the manifests** (repository wholesale to the container's Postgres ids, every set from its own manifest, the skeleton from `sets/` down, each root's own `.` entry); **verifies everything before anything stops** — every inventoried hash (pgBackRest's rewritten info files excluded; its own `verify` proves the repository) after a physical `find` walk that refuses a link where a file is recorded or any path beneath a link; then `compose down`, the host registry stopped, the staging directory swapped by rename with rollback, the roots restored in place with their recorded owners and modes (symlink entries with `chown -h`, never `chmod`; a set without a `.` entry keeps the live directory's owner), Postgres restored with `--delta` and `--type=time` under `--at`, the store tier brought back to prove the cluster promotes and to write its row. It ends with the frontend and ingress down and the store tier and host registry running, and prints whether the secrets on disk are the set's (the keyed fingerprint decides — `apply` regenerates files, so presence proves nothing) with the decrypt line for a rebuilt box, then `apply` and a fresh full. The checkout copy is never restored in place.
- **The drill** (`gideon backup drill`, `drill.py`, `render/drill.py`; §1.8, [22]): a pure `gideon-drill` Compose document (Postgres and the frontend, `/data/drill` mounts, the repository read-only, no archiving, loopback port 18090) written at run time; the previous drill torn down first; the tarball's hash and age header (read as base64 across the text-only seam); pgBackRest's `verify`; the set's own backup restored to its consistency point with `--archive-mode=off`; exact row counts against the manifest; the frontend healthy after its migrations; the CAS walk and retrieval read `inert` until slice 3; teardown in a `finally`; one `backup_drill` row in production's audit log. 23 seconds on the box.
- **Apply and provision**: the `postgres` service renders with `archive_mode`, `archive_command`, and `archive_timeout=300` as command-line settings, the repository and the rendered `postgres/pgbackrest.conf` (time-based retention from `local_days`) mounted in; apply's stores stage creates the repository with the container's ids (`id -u postgres`, never 999), creates the stanza absent-only (a repository belonging to another cluster refuses naming `restore`), and runs pgBackRest's `check`. Provision gains `age` and `rsync` in `host-tools` and the **`age-recipient`** step: `age-keygen`'s output captured through the seam, only the recipient written (`/etc/gideon/backup_age_recipient`), the identity returned as an announcement the runner prints once after the step's row and never again. `backup.local_days` and `remote_days` must be at least 1 (`FieldSpec.minimum`, schema regenerated). Four rendered units: `gideon-backup.timer` (01:00, run then push in one oneshot) and `gideon-backup-drill.timer` (`DRILL_CALENDAR`: the six `drill_interval` values as Saturday 04:00 expressions).
- **Shared code**: `report.Problem` (a problem and its fix, never text with an embedded `Fix:`), `report.StageResult`/`print_stage` (moved from apply), `stages.py` (the stage runner, the clock, the psql argv, the identifier grammar), `sshtarget.py` (the target's SSH and rsync argv, the streamed `sha256sum -c -`), `pgbackrest.py` (every invocation as argv: exec as the container's postgres user, one-off `compose run`, a side-path repository), `stack.running_services`/`parse_ps`, `secrets.secrets_fingerprint`, `apply.wait_for_services` public, a command-boundary guard turning any unexpected exception into a refusal line.

Three defects only the box could show, fixed and tested: `find`'s NUL in argv, pgBackRest's rewritten info files in the byte check, and the fetched skeleton's NAS ids reaching the live root directories.
