## Changes

The three build-box roles are `kvm`, `registry`, and `gh-runner`. They now converge only on a host that has declared itself the build box with `host provision --build-box`. Before this release they shared the GPU-host-only flag with the driver and the toolkit. As a result, a receiving office's GPU host would have installed libvirt and a registry, then stopped at `pending-input` waiting for a runner token for TNMD's organisation, and preflight would have refused on that row. The declaration is inverted from the ticket's first wording: the build box declares, an office declares nothing, and a host with no declaration is an office's host (slice-0 ticket 21; spec §1.5, §1.8, §3.5, §19; ADR-0028, ADR-0035 amended, ADR-0042). The plan is `docs/1-plans/build-box-roles-at-1-0.plan.md`.

- **The marker** (`gideon/host/nogpu.py`, which now holds both host-state markers):
  - `/etc/gideon/build-box` is written absent-only by `declare_build_box`, readable by everyone, and read through `is_build_box`.
  - It is exclusive with the no-GPU marker. `--build-box` on a no-GPU host and `--no-gpu` on a declared build box are each refused, and the refusal names the marker to remove.
  - A hand-made pair of markers makes the no-GPU marker win, so `is_build_box` is false and the three roles skip. This was the code review's one Minor finding, fixed with regression tests.
- **The flag** (`gideon/host/steps/`): `Step.build_box_only` is new. The three roles carry it in place of `gpu_host_only`, and the driver and toolkit keep `gpu_host_only`.
- **Provision** (`gideon/host/provision.py`, `gideon/cli.py`):
  - `--build-box` and `--no-gpu` form one mutually exclusive group, so passing both is exit 2.
  - The declaration prints one row before any step. `--dry-run` prints `would declare`, and an existing marker prints `ok`.
  - Without the marker, the three steps are `skipped — not the build box: host provision --build-box declares one`. A prerequisite skipped for that reason satisfies the steps that depend on it.
  - `--only` on one of the three refuses and names the flag, and `--list` marks the three `[build-box-only]`.
- **Preflight** (`gideon/host/preflight.py`): `PreflightContext.build_box` is new, and a build-box-only step on an undeclared host is `pass — skipped`.
- **The backup set and restore** (`gideon/host/backupset.py`, `gideon/host/restore.py`):
  - `build-box` joins `etc_gideon_exclusions()`, so no set carries the marker and no restore writes it.
  - `restore` stops and starts `gideon-registry` on the build box only.
  - An undeclared host whose registry unit is still active is refused before any stage, because a former build box keeps its units.
- **Render** (`gideon/host/render/`, `compose/grafana/provisioning/alerting/`):
  - `RenderInputs.build_box` is new, and the manifest's `inputs` record it.
  - The *Host unit inactive* rule moves into `host-unit-rule.yaml.tmpl` and renders at its old position on the build box only.
  - The node exporter's unit pattern names the registry and the runner on the build box only. Every other host gets `^gideon-.*\.service$`.
  - The build box's rendered `compose.yaml` and rules file are byte-identical to the previous release's.
- **The fixtures**: `example` is the build box, `second-office` an office's GPU host, and `no-gpu` a no-GPU host. All three were regenerated by `tests/regenerate_render_fixtures.py`.
