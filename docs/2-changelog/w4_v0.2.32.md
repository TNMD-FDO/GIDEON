## Changes

This release implements general-turn ticket 13 under the plan `docs/1-plans/pin-watch-cannot-judge-the-gideon-images-base-tag.plan.md`, rulings (a) and (b). The built pin `images.gideon` has the base `python:3.14-slim-trixie`, whose two-word suffix the pin watch's tag rule could not read: the pin's row was `failed` with a fix blaming `images.lock`, and every hosted `pin-watch.yml` run was red for it.

- **The suffix is dash-joined words** (`tools/pinwatch/oci.py`). `_TAG`'s suffix group is a word followed by any number of `-<word>` groups, each word a letter then letters or digits. The numeric group is unchanged and a word starts with a letter, so every tag that parsed before parses to the same `TagShape`. `same_shape` compares the suffix whole, so `slim`, `slim-trixie`, and `slim-bookworm` are different shapes.
- **An unreadable tag names the rule** (`tools/pinwatch/oci.py`, `tools/pinwatch/cli.py`). `UnreadableTagError`, a `ValueError` subclass carrying the tag, problem, and fix, is raised by `newest_same_shape` and `newest_same_shape_candidates` alike; its fix is to teach `tag_shape` in `tools/pinwatch/oci.py` the tag's grammar. `_resolver_fix` prints that fix before the lock's, which every other resolver `ValueError` keeps (spec §1.5).
- **Tests** (`tests/test_pinwatch.py`): the dash-joined suffix contract over fictitious tags; the fail-closed test learns the error's class and fix; a CLI row for an unreadable tag (exit 1, the rule named, never the lock); a CLI row for an unstable PyPI current version keeping the lock's fix. The truth table and compound-tag tests run unchanged.
- **The proofs**: `python3 -m tools.pinwatch --dry-run --only images.gideon` from the worktree exited 0 with `images.gideon: current`; the hosted dry-run dispatch from the branch, run 35766974223, was green with 34 rows and none `failed` (the ticket's CI-evidence comment).
