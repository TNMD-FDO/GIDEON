## Changes

- **The command** (`gideon/host/engine.py`; spec §6.7, §5.2–5.3, §19.4, [10] item 20, ADR-0006, ADR-0017, ADR-0027): `run_engine_verify` in the shape of `alerts test` — `preconditions` (root; the no-GPU marker, which prints one `engine: ok — skipped — no-GPU host (§2.5)` row and returns 0 before any other read; the site file; the rendered Compose naming the engine; the models lock and the site's profile, the generator's served name and `max-model-len` read from its serve baseline; the engine running and healthy now through `apply.wait_for_services`; the sample; the audit writer's probe) → `needle-32k` → `needle-128k` → `needle-256k` → `structured` → `smoke` → `audit`, each row printed as its check completes, every check running after a failure, the exit 1 iff any check or the audit write failed. The engine call seam: `stack.exec_argv` into the engine's own container running a fixed POSIX script whose positional parameters carry the secret file, the URL, and curl's time bound — the key streamed through `tr -d '\r\n'` into one `header =` line of a `umask 077` temporary configuration file removed in a trap, `curl -K` with the JSON body from stdin, an empty `Expect` header, and one write-out line behind a fixed marker for the HTTP status and the two timings — parsed into a frozen `EngineReply` (JSON or SSE payloads; a redacting `repr`); a non-zero curl exit carries curl's own last stderr line, bounded, never a body; a 400 names the sample with the engine's error message on one bounded line, any other status the engine fix.
- **The needle** at §6.7's nominal lengths (32,768, 131,072, 262,144): target = min(nominal, window − 64 − 256), floor = 0.97 × target; two estimate `/tokenize` calls (the `messages` form with the needle's own `chat_template_kwargs`) seed a block count, then each whole candidate is tokenized and corrected into the band over at most six rounds (a candidate that never lands is a sizing fault naming `needle.filler`); the request thinking-off (`enable_thinking: false`, so the pinned template bakes a closed think block into the prompt and the whole reply is content), `temperature 0`, a fixed seed, `max_tokens 64`, non-streaming; the exact count recorded and `usage.prompt_tokens` held equal to it (a mismatch an engine anomaly); the verdict a whitespace-normalised substring test of the expected code in the answer. Figures kept: nominal, target, floor, window, prompt and completion tokens, blocks, sizing rounds, finish reason, elapsed, HTTP status, recalled.
- **The structured case**: `response_format` of type `json_schema` from the sample (no thinking or sampling override, so the grammar is proven after the reasoning section on the engine's `auto` backend), the reply parsed as one JSON document and validated by `enginesample.validate` — a stdlib validator over exactly the keyword subset the loader admits (`type`, `properties`, `required`, `additionalProperties: false`, `enum`, `items`, `minItems`/`maxItems`, `minimum`/`maximum`, `minLength`/`maxLength`; anything else refused at load, a nested object accepted, a typeless object refused), `finish_reason` required `stop`; violation paths carry schema-known names, array indices, or the `<additional-property>` marker for a key the model chose, never the instance's text.
- **The smoke**: a streaming request with `stream_options.include_usage`, `delta.reasoning` and `delta.content` counted (the engine emits `reasoning`, never `reasoning_content`), the usage chunk before `[DONE]`; pass iff `[DONE]`, non-empty text, and a `stop` or `length` finish; the single-stream chars/s and tok/s over the interval from the first byte (the stream's role chunk, about 4 ms) to the end, and the three implied lags — the lag, twice the lag, the quotation hold — from `LAG_CHARS` and `QUOTE_HOLD_CHARS` read from the Filter loaded by path from `compose/open-webui/functions/arithmetic_guardrail.py`; reported and recorded, never thresholded (ADR-0017).
- **The kept event**: one `audit_log` row of kind `engine_verify` (§19.4's row kind; no migration) — outcome, profile, served model, window, the sample file's sha256, and per check its figures; no prompt, planted text, answer, or model-chosen key anywhere in a row, a detail, a repr, or an exception message.
- **The sample** (`eval/engine-verify/sample.yaml`, `README.md`; [21] item 18): `version: 1`, the needle case (an invented filler paragraph, the planted sentence with the code `4471-ORCHID-92`, the question, the expected code, depth 0.5), the structured case (a plan-shaped `gideon_plan` schema), the smoke case (an open prompt, 256 tokens); loaded by `gideon/host/enginesample.py` with collect-all refusals ending in their fix, unknown keys refused, `expected` inside `planted`, depth strictly inside (0, 1), the schema held to the validator's subset; `build_needle_prompt` numbers each paragraph so no two blocks are byte-identical and plants the sentence at the depth; the README records the sequencing (slice 2's eight `research-qa` cases, ticket 13's two `deadline-trap` positives, slice 3's supporting-model checks) and the supersession rule.
- **Dispatch**: `gideon/cli.py`'s `verify` handler is `host_cli.run_engine_verify` behind `_guarded`; `tests/test_cli_surface.py`'s `STUBS` loses `engine verify`. `install` keeps its inert phase until ticket 13.
- **Tests** (`tests/test_engine_verify.py`, `tests/test_enginesample.py`, 33 new): the command over a fake `Host` whose replies are computed from the request (a non-linear fake tokenizer so the sizing loop must correct), the stage order and rows, the exact exec argv with the key nowhere, the script run under `/bin/sh` against a stub `curl` and a newline-terminated fake secret (the exact header line, the config file's mode and removal, the body's arrival, the `Expect:` header, exit 99 on an empty secret), every precondition refusal with its fix, every check's failure variants with their fixes, the no-GPU skip, the audit row's kind and figure-only detail, the three lag figures against the Filter's constants; the loader's refusals, the validator over every keyword, the committed sample free of the example site's hostname, office name, and domain.
