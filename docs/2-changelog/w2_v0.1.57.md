## Changes

`bin/trip cycle` applied one `--model`/`--effort` to all three phases, so a rung of workflow ticket 28's ladder whose plan and implement pairings differ could not be typed as one command, and the account a session ran under was whatever `CLAUDE_CONFIG_DIR` the shell had exported — a `.bashrc` alias the launcher never sees. This release adds the switch ticket 28's weekly trial types for a few weeks: two optional words in front of the phase, the account then the rung, every phase of the invocation running both, the words printed on each session's first line and carried by the resume line and the skills' handoff commands, so the command typed is the record of what ran (ADR-0017; workflow ticket 33, split from ticket 28; the launcher itself workflow ticket 27's at `v0.1.56`).

- **The two words** (`bin/trip [work|personal] [1-4] <plan|implement|release|cycle> <path> [--yolo] [--model <id>] [--effort <level>] [--dry-run]`): before the phase the launcher consumes `work` or `personal` if present, then a digit `1`–`4` if present; omitted, the account is the default account and the rung the default row, two constants beside the table (`work` and `1`) whose comments name ticket 28's cleanup as the edit that changes them. A word in either position that is neither a known account, a known rung, nor a phase is refused in the launcher's shape — `trip: unknown word before the phase: <word>. Fix: type work or personal, a rung 1-4, then the phase`, exit 1 — before the worktree, the temporary directory, or any session; `--help`, `-h`, no arguments, and a rung with nothing after it keep the usage line at exit 2. `bin/trip 4 work cycle …` refuses on `work` (the order is account then rung), `bin/trip personal personal cycle …` on the second word.
- **The account's effect**, once for the invocation: `personal` exports `CLAUDE_CONFIG_DIR` set to the personal directory (one constant, the alias's `$HOME/.claude-personal`); `work` unsets an inherited value, so the printed account is always the running one (the discovery's decision). Every session the invocation starts inherits the result through `run_phase`'s call; the handoff record's one-line shape is unchanged and never carries the words.
- **The table**: rung 1 is the six `PLAN_MODEL` … `RELEASE_EFFORT` assignments as they stand, in their shape and order, read into a row at lookup time — the values `tests/test_skills_vendored.py`'s rule j holds to `tooling.md` §3's `Routing:` line are the ones that run, never a copy; rungs 2–4 are one line each under names outside that key set (`RUNG_2` … `RUNG_4`), six words in phase order, ticket 28's ladder as amended: Fable xhigh / medium / medium, Fable high / medium / medium, Fable xhigh / Opus high / Opus high. `phase_model` and `phase_effort` take the rung; `--model`/`--effort` replace the selected row's values for every phase of the invocation as before.
- **The note for the skills**: beside `TRIP_HANDOFF` the launcher exports `TRIP_WORDS`, the effective account and rung as two words — `personal 4`, or `work 1` when none were typed, always explicit in a launcher-started session. The two `phase-handoff` blocks (`TRIP-1-plan`, `TRIP-2-implement`, each under §4's 1,500-byte ceiling) print the launcher's next command with those words before the phase when the environment carries the note — the words expanded, never the variable's name — and the `/effort` line at the level the selected rung's row gives the next phase; a session started by hand has no note and the blocks print the plain line, so ticket 28's cleanup needs no block edit.
- **What each session prints**: `trip <phase>: <account>, rung <n> — <model> <effort>` replaces `trip <phase>: <model> at <effort>`; under `--dry-run` the command line follows, prefixed by the `CLAUDE_CONFIG_DIR=<dir>` assignment for `personal` and plain for `work`, then the handoff path; a `cycle` dry run now prints all three phases this way, the later two with the literal placeholder `<plan path from the handoff>` as their path since their handoffs never happen, and starts nothing. A stopped cycle's resume line reads `trip cycle: <phase> ended; resume with bin/trip <account> <rung> <phase> <path>[ --yolo]`.
