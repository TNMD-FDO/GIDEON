## Changes

- **The action majors** (slice-0 ticket 12): `.github/workflows/ci.yml` and `.github/workflows/pin-watch.yml` move `actions/checkout` `v4` → `v7` (four uses) and `actions/setup-python` `v5` → `v7` (two uses). Verified on the day against the actions' release pages and each `action.yml` at the tag: `checkout` v7.0.1 and `setup-python` v7.0.0 are the current releases, both majors declare the node24 runtime (checkout since v5.0.0, setup-python since v6.0.0), and `actions/create-github-app-token@v3` was already node24. Every hosted and self-hosted job had been annotating "Node.js 20 is deprecated … forced to run on Node.js 24"; the annotation is GitHub's signal that a runtime is on its way out, and by the discovery ruling it stays the only drift-noticing mechanism for the actions (no Dependabot, no workflow-parsing test; ADR-0031's pin watch keeps its subject, the lock files).
- **What was checked before the edit**: checkout v6 moved the persisted token from `.git/config` to a file under `$RUNNER_TEMP` included from the checkout's git config, and its README says plain `git fetch`/`git push` keep working — the pin watch pushes its bump branches through exactly that credential via `subprocess.run` with the inherited environment, so `tools/pinwatch` needs no change; checkout v7's refusal to check out fork-PR code covers only `pull_request_target` and `workflow_run` (both workflows use `push`, `pull_request`, `schedule`, `workflow_dispatch`); setup-python v7 dropped only the unused `pip-install` input; both actions state a runner floor of v2.327.1, and the box's runner is the pinned 2.337.0 with `externals/node24` (24.19.0) beside `node20`, so the self-hosted jobs run the node24 actions natively.
- **Unchanged by design**: `python-version: "3.14"`, the `PyYAML==6.0.3` stand-in for `python3-yaml`, the pinned tool installs, the `checks` → `mirror-images` → `frontend-contract` graph with its push-only guard on the self-hosted jobs, the App-token checkout in the pin watch, the egress allowlist (the box fetches the `v7` archive from the same hosts as `v4`). No product code, site key, image, or lock moved — a patch under §2.1.
