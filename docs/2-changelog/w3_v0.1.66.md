## Changes

`v0.2.0` puts General in front of the whole office on one engine. The engine's sizing (ADR-0009) was an argument, and nothing had measured it. The turn harness ran its cases strictly one after another. This release gives the harness `--concurrent N` and takes the first measure of General under overlapping turns: the register's **M27**, a measure with its conditions and no threshold (slice-1 ticket 62; spec Appendix B, §16, ADR-0017, ADR-0023, ADR-0035). The plan is `docs/1-plans/general-under-concurrent-load.plan.md`.

- **The flag** (`tools/turns/cli.py`):
  - `--concurrent N` (positive, default 1) signs in N sessions of the eval identity and runs the whole case set in each, all at once.
  - `N=1` is the present loop: `tests/test_turns.py`'s existing tests pass unchanged.
  - The office-hours guard counts what the run sends: the turns multiplied by N, a searched case as two engine calls, and the browser factor and the `--stream` replay as before. The `preconditions` and dry-run rows name the session count, and they name the engine calls only when those differ from the turns.
  - `--concurrent` with `--browser` is refused before the root check, and so is a browser run over a file carrying a searched case. The screen under load is a one-case browser run started beside the API run.
- **The loop** (`tools/turns/run.py`):
  - One per-turn function serves every session. Each session's copy of the set is rotated so the sessions don't all start on the same case, and its rows are named `<id>@<k>`.
  - A shared lock keeps the write-then-count order under N. The counts merge into one summary, and each session finds and deletes only its own chats through ticket 68's finder.
  - A failed sign-in stops the run before any turn. An errored turn does not stop the other sessions.
  - `--stream` replays merge into the summary, and the records gain the session keys.
  - For a searched case, the API driver sends the managed turn's `features` mapping.
- **The `search` case field** (`tools/turns/cases.py`): `Case.search` (boolean, default false) and `CaseSet.searched`. A non-boolean value is refused with the case named, and so is the field on a seed case.
- **The load set** (`eval/seed/general/load.yaml`): five invented cases, four short unsearched answers and `search-01` searched, all `expect: recorded`. Its README section says ticket 39's smoke set supersedes it as General's set.
- **The tests** (`tests/test_turns.py`): the fake frontend gains a lock, monotonic chat ids, and a barrier that proves the sessions overlap. Fourteen new tests cover the flag, the guard, the dry run, the refusals, sign-in and turn failures, `--stream` under N, searched cases, the record-write failure count, and the loader.
- **The proof** (`.scratch/slice-1/assets/62-on-box.txt`, 2026-09-16 15:55–16:20 UTC, from the worktree, through `tools.redact`; drivers `62-load-run.sh`, `62-engine-metrics.sh`, `62-screen.sh`, `62-records.py`):
  - It ran in office hours under `--force`, by the maintainer's decision. The journal read before it was clean.
  - Each measured batch was bracketed by idle Prometheus scrapes, and each batch's request count matched the count it expected, so no office traffic fell inside a bracket.
  - The set ran with `--repeat 2` at N = 1, 5, and 10, and a shorter N = 10 batch had a one-case browser run beside it.
- **M27 as first taken** (the figures are the spec's Appendix B line):
  - Time to first token: mean 0.26, 0.28, 0.41 s at N = 1, 5, 10, with the 95th percentile in (1.0, 2.5] s at each.
  - Queue: every request's queue time in (0, 0.3] s, and `num_requests_waiting` 0 at every 15 s scrape.
  - KV usage at most 1.0, 3.2, 5.7 %.
  - Time to complete an unsearched turn: median 2.5, 2.9, 3.4 s. A searched turn: median 22.6, 28.6, 32.7 s.
  - A seat's browser turn beside the N = 10 batch painted its first text 5.8 s after its first state, against 7.8 s on an idle engine.
  - The frontend's sign-in limiter bounds the harness at N ≤ 15 per rolling window.
