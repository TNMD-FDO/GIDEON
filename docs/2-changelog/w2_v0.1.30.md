## Changes

- **The record** (`gideon/host/render/command.py`, `compose.py`, `yamlout.py`): `manifest.yaml` and `applied.yaml` gain, beside `files:`, a `services:` map of service name to the sha256 of that service's Compose block and a `top_level` digest over the document with its services removed — each over `yamlout.dump_fragment`, the deterministic serializer without the file header, so a digest is a function of the block alone. The Compose module enumerates its blocks (`service_blocks`) and its top level (`compose_top_level`) beside `service_names` and `service_images`; `compose_digests` computes both digests from the render inputs; `manifest_document`'s signature is unchanged, so the regeneration script, the render command, and apply's `record` stage write the map without a change of their own. The three fixture manifests are regenerated by additions alone.
- **The rule** (`recreate_judgment`, `recreate_services` its tuple view): judged against the applied record only, never the disk, with three owners per service — its rendered files, its block, and the top-level sections jointly. A changed, new, or removed file names its owners as before; a block digest that differs from the record's or has no entry there names its service; the top-level digest differing or absent names every current service, as does the whole-file sha moving while every digest is equal (ruling (d)'s residual, the header) and a record without the `services:` map (every box before this tag), which reads as every block changed and judges nothing further. The union keeps service order and the intersection with the current set, so a departed service is still left to orphan removal. `read_applied_manifest` returns the record (`AppliedManifest`: the files, the optional map, the optional top-level digest) and refuses a malformed map or digest the way it refuses a malformed files map; the two manifest readers share one loader.
- **The row and the rows**: `render --diff`'s `Services apply would recreate: …` keeps its caption and shape and is now the whole set. Apply's `recreate` and `start` stages force-recreate the judgment's members of their tier and group them by reason in a fixed order — `recreated caddy, open-webui: changed rendered files (caddy); changed compose block (open-webui)`, a uniform reason collapsing to one clause, `first apply` unchanged, a service under two reasons in both; the none texts read `no store-tier rendered file or compose block changed` and `no other rendered file or compose block changed`. The row before an apply and the rows after it name the same set by construction. Compose's own config diff at `up -d` still runs and is the backstop the row does not model; Compose's `config-hash` labels are never read by the product (ruling (a)) and stay the proof's cross-check.
- **The gap ruling (d) had, closed at discovery**: the whole-file sha always differs when any block differs, so "every service when it alone differs" could never fire for a top-level change (`networks:`, `volumes:`, `secrets:`, `name:`) riding with a block change. The top-level digest is the one more field that closes it; the whole-file reading stays as ruled for what remains.
