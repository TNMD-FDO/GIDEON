## Changes

This release implements slice-1 ticket 41 under the plan `docs/1-plans/frontend-bump-reproves-browser-mode.plan.md`. The browser mode reads the pinned frontend's page by ids, classes, labels, and routes, and the API mode's routes are tied to the same tag. Until now nothing proved either against a new frontend image before it merged. An `images.open-webui` pull request from the pin watch is now proven on the box before its merge, with the turn harness in both modes on a committed cases file. This cycle applied that step once, to pin-watch PR #3 (the pinned v0.11.3's digest rebuilt), which the maintainer merged after the green run. This release's tag carries that digest.

- **The cases file** (`eval/seed/general/frontend-bump.yaml`, new): seven invented cases in the cases format. They are ticket 34's three (`refused`, `recorded`, `not-confirmed`, each with an explicit `block: any`), the seed's three shapes (`direct-01`, `confirm-01`, `control-02`), and `cancel-force-02`, the one case that reaches the stream hook's trip and the frontend's Stop path. There is no search case, so both modes load the file whole. The searched row comes from running General's smoke set in the API mode, where `search-01` must read `sources present`. The file's entry is in `eval/seed/general/README.md`.
- **The watch's pull-request body** (`tools/pinwatch/pr.py`, `body_for`): for `images.open-webui` only, one sentence names the pre-merge two-mode proof, the cases file, and the runbook's §5. Every other pin's body is unchanged. PR #3 never carried the sentence, because it was written before this release. The pull-request comment with its rows names the step instead.
- **The runbook step** (`docs/runbooks/pin-watch-app-setup.md` §5): a frontend-bump bullet listing the window and its riders, the branch current with `main` in a checkout on the box, `backup run`, `registry mirror`, and `apply` with `render --diff`'s row naming the frontend alone, then the API mode on the cases file and the smoke set. After those come the browser mode with `--probe-inlet` and the engine-call quotient per uncancelled turn, the listed notes read against the new tag, the rows on the pull request, fix-before-merge, and how to undo a red bump. The Merge bullet now points frontend bumps to that bullet.
- **The pointers**: `docs/ARCHI.md` §17's image-bump paragraph and the browser-mode bullet in `docs/archi/tools.md` each gain one clause. The map's old §8 browser-mode sentence now lives in that leaf, as recorded on the ticket at the claim.
- **Tests**: `tests/test_pinwatch.py` checks that the sentence appears for the frontend pin and is absent for another image pin and for a host pin. `tests/test_turns.py` checks the cases file's load contract: the seven ids in order, their expectations, the four explicit `block` values, no `must` or `must_not`, and no searched case.
