## Changes

- **The tier, rendered** (`gideon/host/render/compose.py`, `render/prometheus.py`, `render/grafana.py`, `compose/prometheus/`, `compose/blackbox/`, `compose/grafana/`; spec §19.5): seven mirrored pins join `images.lock` (Prometheus, Grafana OSS, the node exporter, the DCGM exporter from `nvcr.io`, the Postgres exporter, cAdvisor from GHCR, the blackbox exporter) and render as seven services on the private network. Prometheus keeps one year and publishes on `127.0.0.1:9090` only; Grafana is reached only through Caddy's new `/grafana/` handle; nothing else is published. Fourteen new rendered artifacts (25 in all): the scrape configuration, the probe modules (the site hostname as SNI and `Host`, verified against the office CA — the served chain, reached on the Compose network so the firewall's `DOCKER-USER` rule is never crossed), Grafana's `ldap.toml` (values serialized as TOML strings, one group mapping: the admins group to Admin with server-admin; anyone else is refused at the form), the datasources (Prometheus and the `gideon` database as the new read-only role `gideon_ro_metrics`, its password by `$__file{}`), the dashboards provider, the three boards (Overview, Backup, GPU — release JSON emitted verbatim, checked for parse and declared datasource uids), and the alerting files. Every rendered file is a pure function of the site file, the locks, the templates, and the release; both fixture sites render byte-for-byte.
- **Grafana is the one alert engine** (ADR-0034, superseding ADR-0027's alerting sentence only): the contact point (`alerts.recipients[]`, one email, the office short name in the subject), the notification policy (grouped by alert name, repeated daily while unresolved), a Saturday 08:00–09:00 office-time interval, and fifteen rules provisioned from release files. Rows over `audit_log` for backup set, push, and drill overdue (26 h; the drill's calendar's longest real gap — 7/21/35/98/189/371 days — plus three) and a failed drill, all alerting on no data; Prometheus rules for a failed `gideon-*` unit, a scrape target down (the one rule that pages on silence or a query error — a dead Prometheus is that page), Postgres down, the ingress and frontend probes failing, a host unit (the registry, the runner) inactive, the node exporter's systemd collector failing (the one blind spot silence would otherwise open), `/data` under 15 % free (the interim line until slice 3's live generation), the served certificate within 14 days, driver drift (DCGM's `DCGM_FI_DRIVER_VERSION` label against `host.lock`'s tested version, rendered only when one is recorded), and the always-true heartbeat routed to the Saturday window with a six-day repeat, so its absence on a Saturday is what a person notices.
- **`gideon alerts test`** (`gideon/host/alerts.py`, `host/grafana.py`, `host/ingress.py`): four rows — preconditions (root, the site file, the rendered project with Grafana, the break-glass secret, the audit writer), Grafana ready through the ingress, the stored `page` receiver read back from the Kubernetes-style receivers API and checked against the site file's recipients before its one email integration is posted to the receiver's `test` subresource (the route the research note named answers 410 Gone at Grafana 13.0.2 — an erratum on the note), and an `alerts_test` audit row that always follows the send (recipient count, relay, outcome, SMTP code; never an address). The Grafana client shares the SNI connection with the frontend client (`ingress.py`); the break-glass credential appears in no repr or message; Grafana's error text is redacted of every configured and stored address.
- **Provision, secrets, stores**: `disk-layout` gains a per-directory owner and mode (`/data/observability/{prometheus,grafana}` owned by the containers' fixed ids); `secrets-dirs` converges every secret file to `root:gideon` 0440 and `write_secret` chowns what it writes, because Compose ignores ownership on file secrets — Grafana and the Postgres exporter read them through `group_add` with the service group's gid, a new host fact; two generated secrets (`grafana_admin_password` printed once, `postgres_gideon_ro_metrics_password`); the role's `pg_monitor` membership granted by the superuser on every converge (a migration runs as `gideon` and may not grant a predefined role); migration `0002` grants the reader `SELECT` on `audit_log`; a site file naming an SMTP user refuses at render without `secrets/smtp_password`; Grafana's SMTP requires STARTTLS exactly when a user is set, and trusts the office CA through a mount in its trust directory; the apply verify stage proves Grafana answers through the ingress; preflight's ports check knows 9090; `gideon-backup-verify.timer` runs `backup push --verify-all` on the second Saturday of each quarter's first month; the pin watch's tag grammar accepts compound tags (`4.6.0-4.8.3-distroless`) so the DCGM pin proposes instead of failing weekly; the egress allowlist gains `nvcr.io` and its blob host.
- **On the box** (`.scratch/slice-0/assets/07-apply-first-pass.txt`): six applies to convergence — the `pg_monitor` grant path, cAdvisor's rejected `accelerator` flag, Grafana's sub-path metrics, and the node exporter's D-Bus socket (dialled at `/var/run/dbus`, refused under Docker's AppArmor profile until the service runs outside it) were all found and fixed live.
