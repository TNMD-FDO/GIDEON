## Changes

This release implements slice-2 ticket 10 under the plan `docs/1-plans/harvest-forty-as-research-qa-cases.plan.md`, spec §18.2, §18.3, §18.4(b), §18.6, §19.4, §2.6, and §0.2's supersede rule, [21] items 4, 7b, and 16, and the maintainer's five rulings at the claim. The harvest's questions are the measured form of "comparable to the prototype" at the go/no-go gate, and until now the set had no shape that could hold them: `SHAPE_REGISTRY` knew three suites and none of `research-qa`, and no signed or unsigned notion existed anywhere under `gideon/` or `tools/`. Both are built here. Nothing is applied on the box and no command, flag, or `STUBS` entry moves.

- **The ticket's premise was wrong, and the record says so.** The ticket as opened, and its `Blocked by` line, had ticket 04's loader already holding the case shape and the unsigned state. It holds neither, which is why a case file of an unregistered suite refuses the *whole* set rather than its own line — the proof that exposed it. The correction is the dated comment on the ticket and its `Blocked by` line, written at the claim.
- **Thirty-eight cases, one file** (`eval/sets/eval-v1/research-qa/harvest.jsonl`, new, excluded from the export; its `README.md` kept): the harvest's ids in order with `HARV-014` (a prompt-writing request) and `HARV-017` (a word-processor how-to) skipped, ids `research-qa-001` … `research-qa-038`, so `research-qa-NNN` and `judgments-NNN` share a seed for every N to 38. Each case takes, from the `judgments` query of the same seed, its reviewed question text, its wording and query-type labels, its `jurisdiction` and `reference_date` where that query has them, its `cluster_id`, its `notes`, and its accepted redaction flags; what is new per case is its id, its suite, and its **category**. The split is `retrieval` 22, `synthesis` 11, `lookup` 4, `edition` 1, stated in the README and derived in test from the same table. §18.2's forty is a starting value (ADR-0017): the harvest holds thirty-eight legal research questions and the set says so, recorded as a dated comment on greenfield [21] rather than a spec edit. Ids only, in the file and in every assertion; no question text is restated in any asset (§19.4).
- **A case carries no `expected`, and that is a consequence, not a preference** (ruling (c)). A case is never edited (§0.2) and every committed case file's leading bytes are pinned, so an answer arriving later could not ride in the line it belongs to without breaking both rules; and an expected answer is an attorney's, which means it arrives later by construction. It lives instead in `research-qa/signoffs.jsonl` beside the cases — **uncommitted today**, so every case here is unsigned — whose shape is a product module's as the judgments file's is (`gideon/evaluation/signoffs.py`, new): closed ordered keys, `expected` carrying an `answer` string and a non-empty `must_cite` of source ids so the field cannot hold prose in place of a citation, `signed` carrying an attorney role id and an ISO date, a case id once, a final newline, and a `repr` that withholds the answer as a populated judge mapping's does. It imports the source-id and attorney-role patterns from `judgments.py` rather than restating them. [21] item 16's sketch puts `expected` in the case; the departure is recorded in the same [21] comment, and the loader stays the one reader of where an expected answer lives, so slice 4's runner never learns which file held it.
- **Unsigned is the absence of a line, derived at load.** A shape says whether its cases take a sign-off — the four `research-qa` shapes do, no other shape does. The loader parses the sign-offs file when present, through its module behind a function-level import as it parses the judgments file, puts its bytes in the set digest, and after the `supersedes` pass resolves every `case_id`: a line naming no case, a superseded case, or a case whose shape takes no sign-off is a finding by line. `LoadedSet` gains the sign-off records and `unsigned_ids`, the active sign-off-taking cases with no line. There is no `signed: false` anywhere and no migration the day the first signature lands.
- **One selection, one guard, one refusal.** The three registered runners each repeated the same inline filter of a slice's ids by `active_ids` — the same four lines written three times, which is a bug generator rather than a bug: the fourth runner, written in slice 4 by a session that has not read this plan, would inherit nothing. It becomes one loader function returning a slice's ids split into **counted** and **unsigned**, and all three runners call it, so a future runner inherits the rule by calling what it must call to get its cases at all. `eval run` calls the same function for its summary: where the slice lists any case whose shape takes a sign-off, the `run` row's detail ends `, N unsigned excluded` — zero included, which at go/no-go reads "all signed" — and a slice with no such case prints exactly what it printed before, which is how the clause stays conditional. Behind the convention, a result whose case id is unsigned fails the `run` row by id before `record`; the check reads **the set's** unsigned ids and not the slice's, since a runner that reached past its own selection did not necessarily reach past it within its own slice. `eval reference`'s `check` refuses a recorded run whose results name an unsigned case, by id, so none reaches a written reference whatever produced the run and whenever it was recorded.
- **No slice, no runner, no flag** (ruling (e)). The loader does not require a case to sit in a slice, and no `research-qa` slice is frozen here: the suite's gates differ by category — `lookup` and `edition` admit a right answer and a wrong one, `retrieval` and `synthesis` are read and reported — so how its id lists partition is the first runner's decision, slice 4's. "Runs if asked" waits for that runner; it is a `NOTES.md` line with that trigger.
- **Not built, deliberately.** A sign-off, like a case, is never edited, and no superseding form exists for one. A sign-off naming a superseded case is a finding, so a superseding case starts unsigned and its signature is a new line; the old line's retirement is a mechanism nothing has needed yet, and the finding is what will surface the need. The first need opens the ticket that builds it, the grading kit's precedent.
- **The digest moves with the new file**, as it has with every case file added to `eval-v1`, and will move again the day a case is signed. That is deliberate: a run recorded before a signature is not a run of the set that came after it. It costs nothing standing — the comparison never reads the digest, so every committed reference stays `current` — and means only that a run recorded before this release cannot be *written* as a reference after it, which is the writer's existing refusal working as designed.
- **The boundary** (`tools/exportboundary.py`, `.gitattributes`): the cases file joins the list with its attribute mirror, the README kept. The sign-offs file gets neither yet — there is nothing to pin, and the attribute rule would read an absent prefix as a directory and write the entry in the wrong shape — and that debt is the second `NOTES.md` line, owed the moment a file exists, since it is wholly harvest-derived.
- **Tests** (`tests/test_evaluation_signoffs.py` and `tests/test_research_qa_set.py` new, three modules changed; 24 new tests, 2,335 passing at the review). The sign-offs line and file rules with every refusal content-free — an `answer` is text, so a finding names the key and never quotes it — and the serializer's round trip; the four shapes' refusals on the existing per-shape pattern with an `expected` key among them; the three relational findings; `unsigned_ids` over signed, unsigned, superseded, and non-sign-off cases; the selection's order and split; the digest moved by one changed sign-off byte. End to end through `cli.main`: the `run` row's clause with its count and with zero, a runner's unsigned result failing the row by id with no `record`, the writer refusing a recorded run that names an unsigned id and a clean run's written files holding none, and **every entry of `SLICE_RUNNERS`**, enumerated, run over a copy of its slice with one unsigned case planted in its list and returning no result for it — the tripwire that turns a future runner red if it filters for itself. The committed cases are held by their bytes (a line count and SHA-256 prefix pair, the sibling suites' mechanism), by thirty-eight ids in one unbroken series, by field-for-field equality with the `judgments` query of each seed, and by **the exact id → seed → category table**, kept test-side and compared row for row with the plan's, because the byte pin is taken from the file as written and would hold a wrong assignment as faithfully as a right one; the per-category counts are derived from that table and read from the README. No assertion can print a question. `test_evaluation_run.py`'s exact-text assertions on today's `run` rows pass unchanged, which is the proof the clause is conditional; `test_export_boundary.py` needed no edit, its committed-tree rules judging the new entry and its mirror.
