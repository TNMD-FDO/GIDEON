# Changelog - Week 1, 02-09-2026, V. 0.0.12

**Release Date**: Week 1, 02-09-2026 at 03:42

**Object**: directory identity is the userPrincipalName: LDAP_ATTRIBUTE_FOR_MAIL=userPrincipalName rendered, users reconcile joins and snapshots by UPN, preflight's LDAP check is set-complete on memberOf and refuses members without a UPN; TNMD's account re-keyed (slice-0 ticket 09)
**Code review**: `docs/3-code-review/CR_w1_v0.0.12.md` (Codex loop, 1 round -> APPROVED)

## Changes

- **The frontend keys every human by the directory's `userPrincipalName`** (ADR-0030; slice-0 ticket 09): `gideon/host/render/owui.py` renders `LDAP_ATTRIBUTE_FOR_MAIL=userPrincipalName` in place of `mail`. Sign-in stays by `sAMAccountName`; the address the frontend stores is now the one attribute every directory account carries, so an office never has to type E-mail addresses into ADUC before people can sign in. No site key: a per-office attribute would make the same person a different account on two installs (ADR-0028). Both byte-stable render fixtures regenerated — one env line and one digest per site.
- **`gideon users reconcile` joins, snapshots, and reports by UPN** (§4.1, §19.4): the membership search requests `sAMAccountName` + `userPrincipalName`; the join is by casefolded UPN through one map (the `sAMAccountName`/`username` fallback is gone, since the frontend stores no username for LDAP accounts — ticket 05's live finding — and `owui.User` loses the field); each `membership_snapshot` member is recorded as `{account, upn, user_id}` (rows written by `v0.0.11` keep their shape); a users-group member without a UPN is reported as `inconsistency: <account> has no userPrincipalName`, never matched and never a refusal — the nightly run keeps correcting everyone else.
- **Preflight's LDAP check is set-complete and gates on the UPN** (§1.5): its `memberOf` search over the users group requests the same attribute pair, and "some result" no longer passes — the visible DN set must cover the group's `member` set, and an incomplete result refuses naming the invisible DNs with the fix that names both live causes (a per-OU *Read memberOf* delegation that misses an OU, or a member outside `auth.ldap.search_base`, which the frontend's own search is scoped to). Only then does a visible member without a UPN refuse, naming each by account (or DN), with the ADUC fix; the pass detail reads `… N users-group member(s) resolved, each with a userPrincipalName`. The empty-result, empty-group, missing-group, and bind-failure outcomes are unchanged.
- **Runbook and example file**: `.scratch/slice-0/assets/03-office-services-setup.md` §1 and §1a replace the "set E-mail on every account" requirement with the UPN note (and name the visibility refusal); new §1b records the one-time re-key of accounts created before `v0.0.12` (edit the address in the admin panel — the frontend updates both its auth and user rows, so the id and everything attached to it survive). `config/site.example.yaml`'s `auth.ldap.host` comment no longer names `mail`.
- **Spec bug (t) recorded on the ticket**: §4.1's "email from AD `mail`" and [09] item 3 are superseded by ADR-0030; the `v0.0.11` stopgap is withdrawn.
- **On-box pass** (`.scratch/slice-0/assets/09-upn-identity-pass.txt`): `render --diff` showed exactly the one env line; `apply` ran all twelve stages ok and Compose recreated the frontend on the config change with no forced recreate; the frontend held one `mail`-keyed human row (not the two the ticket expected — only one account had ever signed in), which a bare reconcile flagged and the CSA re-keyed per §1b; `mail` was cleared on `adm-derakhshan` in ADUC and the account signed in on the LDAP form, landing on its UPN-keyed row with its original id; reconcile bare and `--now` reported zero corrections and wrote both snapshots with `upn` on every member; preflight passed `ldap: … 4 users-group member(s) resolved, each with a userPrincipalName` (29 checks; 26 pass, 3 inert).
- **Tests**: 3 new (367 total, 98 subtests) — the partial-visibility refusal, the missing-UPN refusal naming an account and a DN, and the ordering case (an invisible member refuses before a visible one without a UPN); the reconcile truth table re-keyed to UPNs with `frank` as the no-UPN case and the audit-SQL assertion deliberately reversed to positive on the UPN (an identifier the snapshot records by design) while knowledge-base names and the admin key stay asserted absent; the render env assertion.
