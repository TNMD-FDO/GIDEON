## Changes

This release implements slice-0 ticket 25 under the plan `docs/1-plans/restore-reowns-by-name.plan.md`. `restore`'s two re-owning stages, `fetch` and `files`, `chown`ed every restored path by the numeric `uid:gid` the manifest's inventory recorded on the host that made the set. A rebuilt box's `gideon` system account need not have the old host's ids, so after a total-loss recovery everything the old `gideon` owned belonged to an id the new host maps to nobody, and `preflight`'s `disk-layout` refused — ticket 20's third full-restore run failed `preflight-2` with `directory /data/registry is not owned by gideon`. Since `v0.1.77` a `host provision` after the restore repaired it, in the harness and in the runbook, but provision re-owns the managed `/data` directories themselves and never their contents, so the repair held only while no set carried a `gideon`-owned file below one — and a harness stage that repairs it hides the regression until a real recovery.

- **The record** (`gideon/host/backupset.py`, `gideon/host/backup.py`). `backup run` reads the making host's `gideon` ids once at its preconditions, through the seam (`getent passwd gideon`, the passwd record's third and fourth fields — `secrets.service_group_gid`'s shape), and refuses before any stage when the account is absent or the record malformed, the fix naming `host provision`. The pair is written as the manifest's new optional `gideon_ids` object, the `Manifest` dataclass's defaulted last field, under **version 1**: `to_json` writes it only when present, the parser reads it as optional with `gideon_ids.uid` and `gideon_ids.gid` named in its problems, and no earlier set changes. A set this release makes therefore parses in the previous tree, whose parser ignores the key — the rollback path of ADR-0005.
- **The map** (`backupset.OwnerMap`). A frozen pure value over a manifest's record and the host's pair: a recorded uid becomes the host's, a recorded gid the host's, **each independently**, every other id passing through, and no record is the identity. The per-component rule is what the tree needs: the secrets and the backup public key are written `root:gideon`, so a `0:983` entry must become `0:<host gid>` and a `999:0` entry `<host uid>:0`.
- **The read and the two stages** (`gideon/host/restore.py`). `restore` reads the restoring host's ids at its preconditions, refusing there the same way. `_root_owned_metadata` builds one map per set from that set's own manifest and `_restore_files_stage` one from the selected set's, each computing the `OwnerKey` before grouping, so the fetched side and the live tree agree and a set fetched under `--from target` and restored later `--from staging` maps to the same result. `_run_grouped_chown`, the skeleton, the staging-root re-own, the repository's container identity, and the live-directory owner kept for a root without a `.` entry are all untouched.
- **The rows say what happened.** `fetch` reads `re-owned N path(s), M mapped to gideon <uid>:<gid>`, `files` the same clause after its roots; the mapped phrase is the public constant `REOWN_MAPPED_DETAIL`, as `FRESH_STACK_SKIPPED_DETAIL` is, and a set without the record carries `REOWN_NO_RECORD_DETAIL` instead. For such a set the `next` stage's `Next:` line names `host provision` before `apply`, with the first provision's mode flags, because provision re-owns the managed `/data` directories.
- **The interim repair is gone on both sides** (ticket 25's ruling (c)). `FULL_RESTORE_STAGES` loses `provision-3`, so `apply-2` follows `reinstall` and `preflight-2` proves the product path alone; the runbook's §5 loses step 6 and its seven steps are six. `select_set` now refuses, before anything boots, a set whose manifest carries no record, the fix naming `backup run` from the release's checkout — the form proves a manifest change only over a set the release's tree made. `restore_target` requires the `files` row to carry the product's mapped-phrase constant, held equal by import.
- **The documents.** §4's "what a restore does" gains the by-name clause and names `v0.1.79` as the boundary; the backup leaf states the record, the read, and the map; the tools leaf drops `provision-3` from the table, states the `set` stage's requirement and `restore_target`'s check, and adds ticket 25 to the entry's list. The glossary's **Backup set** gains the record's clause through `/domain-modeling`. `docs/ARCHI.md` §11's acceptance bullet gains the clause it was missing: a release whose plan's to-dos name an acceptance run against its own tag runs the named form whatever the tag's kind (`v0.1.78`'s precedent, this tag's too).
