## Changes

- **Issue**: one test of the reference writer failed in the export tree and nowhere else, so the export has refused every tag since `v0.2.17` and the public repository still stood at `v0.2.16`. `Writing::test_malformed_reference_requires_removal_then_writes_and_partial_still_refuses` in `tests/test_evaluation_reference_command.py` did three things in a row over a temporary copy of `eval/`: a hand-edited reference file refused with its fix; the slice's whole reference removed and written; and **one** file removed, expecting the *partial reference* refusal. That third act needs a slice with more than one id list. The development tree has two — `invented.ids` and `harvest.ids` — and the export has one, since the harvest id list and its reference are outside the boundary. There, removing the slice's only file is absence, which the reader rightly does not report and the command rightly exits 0 on. The assertion was wrong in that tree; the behaviour was not.
- **Fix**: two cases where there was one. The first keeps acts one and two, needs one list only, and runs in both trees under a name that no longer promises the third. The second holds act three alone: it skips, visibly and with its reason, when `tools.exportboundary.absent_from_export` says the harvest id list is outside this tree, and where it runs it first asserts its premise — the loaded `extraction` slice has more than one id list — so a slice collapsed some other way fails naming the premise rather than passing vacuously or skipping in silence. The guard is on the id list the boundary removes, never on the absence of `.git` and never on the list count alone. **No assertion was weakened**: exit 1, *partial reference* on stderr, and `SLICE_REPAIR_FIX` on stdout stand exactly as they were, and no tree accepts exit 0 for a partial reference. The rule itself is still held in both trees at the reader, by `test_partial_reference_is_malformed_not_absent` over hand-written lists no boundary touches; the case split here is its command-level restatement.
- **Root cause**: the export boundary moves a slice's *shape*, not only its files, and the test asserted on the shape while reading nothing excluded. `docs/archi/tests.md`'s export-boundary bullet listed only tests that read an excluded path, so nothing pointed at the failure mode.

**Proven in the export tree before the tag.** A committed asset script, `.scratch/slice-2/assets/23-export-tree-check.sh`, repeats `bin/release-export`'s check block — an archive of a chosen tree extracted into a fresh temporary directory, then `ruff check .`, `mypy gideon tests tools`, and `pytest`, in that order, with the primary's `.venv` tools. It clones nothing, pushes nothing, and reads no network. The record is `.scratch/slice-2/assets/23-export-tree.txt`: the failure reproduced first over an archive of the unfixed tip, then the staged tree green with the new case skipped for its reason, then the development tree's run with the new case passed and not skipped. The release ran it once more over the tag's own tree, since that commit adds the changelog, the release note, and the version, all of which the export's suite reads.

**What this tag carries.** Four tags stood privately and never export on their own — `v0.2.17`, `v0.2.18`, `v0.2.19`, `v0.2.20` — because each one's own tree holds the unportable test. The public history therefore goes from `v0.2.16` to this tag.
