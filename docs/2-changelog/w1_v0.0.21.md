## Changes

- **Two skill-source pins** (`tools/pinwatch/pins.py`, `sources.py`, `cli.py`; ADR-0033): `skills.trip-workflow` compares `PiLastDigit/TRIP-workflow`'s latest release with the shared `ref` of the 14 TRIP entries in `skills-lock.json`; `skills.matt-pocock` compares the head of `mattpocock/skills` `main` (a new `github_branch_head` resolver, sha and committer date only) with the commit on the provenance line of `docs/agents/tooling.md` §2. Both are proposals in the built-image sense: the pull request patches the record only — the refs as the CLI's byte-stable JSON, or the line's commit and date tokens, through `patch.apply_bump` dispatching by record (`tools/pinwatch/skills.py` owns both loaders and patchers, stdlib only) — never a file under `.claude/skills/`, carries no fixture, and its body names the recipe a person completes on the branch. The run reads four records from `origin/main` and refuses when one fails to load. A release published without notes no longer fails its row (a null body reads as empty).
- **A branch a person has committed to is never pushed to again** (`tools/pinwatch/pr.py`): the watch always makes exactly one commit on `origin/main`, so for a skill record `git rev-list --count origin/main..origin/<branch>` above one is human ownership — judged before anything can read as stale, whether or not the branch's record is readable, and failing closed on a bad count (a `failed` row, nothing pushed). Such a branch is `completed`; its pull request's title and body are rendered from what the branch holds (a `SkillPin.branch_bump` with the branch's values and their own upstream page) and edited only when the title misnames it; the row reads `completed — <head>`, then ` — PR <url> retitled to <value>` when edited, then `; upstream now <new>` when upstream has moved on. A closed, unmerged pull request with the same title stays `declined` for a skill pin as for every other. Stricter than ADR-0032's built-pin rule on purpose: a rebuild is regenerable on the box, a resolved three-way merge is not.
- **The tripwire** (`tests/test_skills_vendored.py`, in the hosted `checks` job like every test): every lock entry has its directory; for the 34 entries outside §3's slot table the folder hash recomputed with the `skills` CLI's own algorithm equals `computedHash`; the GIDEON blocks across every vendored skill equal §4's table exactly, as `(file, id)` pairs, well-formed; no `[ADAPT_TO_PROJECT`/`[PROJECT_NAME]` placeholder outside `TRIP-init` and `TRIP-upgrade`; no conflict marker; every `scripts/*.sh` executable, `*.template.sh` exempt (git records `diagnosing-bugs/scripts/hitl-loop.template.sh` at 644 upstream — the ticket's rule as written was red on `main`); no two skill directories differing only by case; and the lock's TRIP `ref` equal to the provenance line, which must parse — the records-agree rule that keeps a TRIP proposal red until a person completes it. Both tables are read from the document, so a block without a row is red. The hash was read from the CLI's source at `v1.5.23` (`src/local-lock.ts`): files only, `.git` and `node_modules` skipped, relative paths sorted by `localeCompare`, path bytes then content bytes into one SHA-256 — a bytewise sort reproduces only the four single-file skills, an ICU-like key all 34 non-slot ones; GIDEON adds one rule, under `state/` only `.gitignore` counts (the gitignored Codex thread state). Every rule has a negative case over a temporary copy of the skills, the lock, and the document; the failure lists every finding with its fix.
- **The clone checker and the recipes** (`python3 -m tools.pinwatch.skills --source <owner/repo> <clone>`; `docs/agents/tooling.md` §5–6): the CLI clones with `--branch` and cannot install a commit, so a Matt Pocock refresh reads the head sha first, installs, and proves the install by hashing three things per entry — the lock, the clone at that sha, the installed folder — every row `match`; the same checker is §5's pristine step, and it hashes the installed directories directly, which is how the five slot skills are proven pristine after the CLI run where the tripwire must exempt them. A mistyped source is a refusal naming the known ones. Live: against a clone of `v2.8.0` exactly the five slot skills read `installed differs from clone` and the other nine `match`; against a clone at the recorded commit all 25 Matt Pocock skills `match`. The upgrade recipes now run on the watch's branch when its pull request is open; §6 is four steps (read, install, prove, record).
- **Records and the vocabulary**: the provenance sentence in `docs/agents/tooling.md` §2 is a machine-read record on one line behind a comment naming its readers; `tests/test_lock_coupling.py` scans for the TRIP `ref`, the recorded commit, and its date as values the watch moves; ADR-0033 records the widened subject and why the skill pins are proposals the watch never completes; `CONTEXT.md` widens **Pin watch** and gains **Vendored skill** (via `/domain-modeling`); `CLAUDE.md`, `README.md`, `TESTING.md`, and the Monday-review runbook name the pins, the tripwire, and the branch rule.
