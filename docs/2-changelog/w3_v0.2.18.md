## Changes

This release implements slice-2 ticket 06 under the plan `docs/1-plans/the-judge.plan.md`, spec §18.4–§18.6, [21] items 8 and 16, ADR-0023 and ADR-0006. `eval_results.judge` had been null since ticket 04 and `gideon/evaluation/` had no module that reached the engine. It has one now, and the release's real work is the machinery that keeps a model-written number out of every decision the product makes.

- **The judge** (`gideon/evaluation/judge.py`, new): one entry point over the Host seam, the rendered directory, the served model, a registered prompt, and a question, a reference, and a candidate, returning a **grading** — a verdict (score 0–3, reason, failure modes) or a failure (code, content-free detail) — with prompt tokens, completion tokens, and elapsed seconds, each optional, since a request that timed out has none of the three. It owns the prompt registry, the rubric, the closed failure-mode vocabulary, the verdict schema, the request's shape, the parse, the validation, and the row's judge field. It reaches the engine through `gideon/host/engine.py`'s in-container curl, so the key never enters Python (§16), and an AST test holds that the module imports no secrets module and reads no secret.
- **The prompt is a versioned product artifact.** `PROMPT_REGISTRY` is keyed `name@N` — the first and only entry `synthesis@1` — each entry carrying its system text, its user template's three named slots, its schema name, and its schema; `PROMPT_DIGESTS` pins each registered version over exactly those five fields, so an edit under an existing id is a failing test and a change takes its next `@N`. The id is written with every verdict. The rubric is [21] item 8's: the reference is the truth for grading and the judge's own recall is not, length earns nothing, and claims beyond the reference that carry no source are marked down. The question, the reference, and the candidate go into the user message in delimited, labelled blocks, so a candidate's text cannot pose as an instruction.
- **The verdict schema** uses only keywords both the engine's guard and `enginesample.validate` admit: `score` as an `enum` of 0–3 rather than a numeric range, `reason` a string with a minimum and a maximum length, `failure_modes` an array of the vocabulary's `enum` bounded by the vocabulary's size, `additionalProperties` false. `uniqueItems` is not used — vLLM rejects it for xgrammar — so a repeated mode is collapsed in order by code, which touches no score. The request sets `temperature` 0 and `chat_template_kwargs` with `enable_thinking` true **explicitly**, so [21] item 8's ruling survives a template default flipping at a model bump.
- **A failed grading is never a score** (ADR-0006): a non-200 status, a finish reason other than `stop`, content that is not one JSON document, a schema violation named by key or index, or a reason empty after whitespace collapse is a failure code with a content-free detail, and its row carries no `score` key at all. The finish reason is read *before* the content, so a reply that exhausted the reserve inside its reasoning block reports `finish-reason` and names the token reserve rather than reporting missing content — a code-review finding, fixed with its regression test.
- **The judge grades and never gates, held three ways**, none of them a habit. *By shape*: the gate stage reads one bool the runner computed in code, and a score and everything derived from it — the band, the in-band flag — live in the case result's `judge` mapping, never in `verdict` or `metrics`. *By invariance, registry-driven*: `tests/test_judge_never_gates.py` drives **every** slice in the registry twice over a stub engine whose replies differ in every verdict field and asserts the slice verdict and each case's `verdict` and `metrics` are identical, so a slice registered later (tickets 12 and 15, slice 4) is enrolled on arrival rather than having to remember the test. *By name*: the same module walks every registered slice's `metrics` keys at any depth and fails on one naming a judge fact, reads each gate function by AST against its own attribute list, and — the clause that earns its keep — fails a `gate` row printed by any function outside the walked set. That last check exists because of a near-miss: this branch was cut before `v0.2.17`, whose reference gate landed while the branch was away, and neither of the other two mechanisms would have noticed a gate nobody had registered.
- **The slice-runner seam is generalised once.** `CaseResult` and `SliceResult` move to `gideon/evaluation/results.py` (new) beside `RunContext`; `SLICE_RUNNERS` moves to `gideon/evaluation/slices.py` (new), each entry now a `SliceSpec` — the runner, `reaches_engine`, `repeats`, an optional `judge_prompt`, `compares_reference`, and the gate's pass, fail, and fix texts. `CaseResult` gains `repeat`, an optional `judge` mapping, and an optional latency (a grading whose request never returned has no elapsed time, and its row's latency is SQL `NULL`); the runner receives the run context, so it hard-codes neither its repeats nor its prompt. `run_extraction` takes the context and ignores it, and `--slice extraction` prints and records exactly what it does on `main`.
- **Ruling 5 — `judge-triples` keeps no reference** (the maintainer's, at the mid-cycle rebase onto `v0.2.17`): whether `eval run` compares a slice with its committed reference is one more registry fact. `extraction` compares exactly as `main` does; `judge-triples` does not, prints no `reference:` line, and gates on its own row. `main`'s reference block moved whole into two functions beside the slice gate, each walked by the tripwire with its own attribute list. `eval reference --run` refuses a run of a slice that keeps none, before any write, and a test holds every directory under `eval/reference/` to a comparing slice; `eval/reference/README.md` carries the rule. A triple passes when its grading came back on-schema, which the slice's gate already refuses on, so a regression list would say it twice. The flag flips when a judge case's pass means something about the product (slice 4).
- **The command** gains a `preconditions` stage between `load` and `run` for an engine-reaching slice, stopping at the first refusal, each with its fix: root, the no-GPU marker (a refusal, not `engine verify`'s skip, since nothing here is gated on by install), the site file, **the quiet window**, the engine's target, and — unless `--set` was given — everything `record` can refuse on that does not need the run: the git provenance and the writer role's connection probe. Its guarantee is stated as exactly that and no wider: the probe proves the role connects, not that the insert will succeed. A rollback-only trial insert was weighed and left out — a second SQL path through an insert-only role and a `SECURITY DEFINER` partition function, for a failure no run has shown. The ok row names the profile, the served model, the window judgement, and the spec's prompt id.
- **The quiet window** (`gideon/evaluation/window.py`, new): one pure judgement over an aware clock and an IANA zone — §18.5's 19:00–06:00 office time and the weekend — returning the inside flag, a content-free description, and the next opening; a naive clock is read as UTC, as the turn harness does. Tickets 16 and 11 adopt and extend it, and `tools/turns/cli.py` keeps its own copy until ticket 11's move retires it, since `tools/` may not import `gideon.evaluation`.
- **`engine.py`'s target resolution and reply-values reader become public** and shared with the judge, its only other caller. `run_engine_verify` now calls the helper; every problem and fix text is byte-identical to what it printed before, and `tests/test_engine_verify.py` is the contract and was not edited.
- **The recorder's text binding becomes backslash-safe.** `_escape` doubled the apostrophe alone while `psql` applies C-like backslash substitutions inside a single-quoted `\set` argument. Every row so far had held ids and integers, so it never showed; a reason is the first value that can carry a double quote (the encoder writes `\"`) or a non-ASCII character (`§` is written `§`), which would have failed the `jsonb` cast or been silently altered to `u00a7`. The binding now doubles every backslash as well, the JSON encoding states its ASCII default explicitly, and a `ResultRow`'s populated judge mapping is redacted from its `repr`. The CR/LF/NUL refusal is unchanged: it guards the script's line structure, which doubling does not.
- **The triples** (`eval/sets/eval-v1/judge/`, new): eight cases, two of each kind — faithful, wrong, partial, unsourced-length — every text invented and carrying documentation values only, and **at least two resting on a plainly fictitious authority**, so a right score can only have come from the reference and not from recall. The loader learns the `("judge", "triples")` shape with its own refusals: `expected` has exactly `answer` and `band` (two integers 0–3, low not above high), `candidate` is a non-empty string, `labels` is exactly one kind plus `invented`. The bands are a person's: the implement session printed a sheet and the maintainer accepted or corrected each, recorded in `review`. The suite README is the suite's authority, `slices/judge-triples/triples.ids` freezes the slice, and the triples stay in the export as `extraction-invented.jsonl` does.
- **On the box** (`.scratch/slice-2/assets/06-on-box.txt`, ticket criteria 3 and 4): inside the quiet window, detached, from the worktree, after a journal read and two idle scrapes of the engine's Prometheus counters. Sixteen gradings over eight cases at two repeats. **The discovery note's pairing is the pairing that works**: 16 of 16 returned an on-schema verdict with thinking on at temperature 0, every finish reason `stop`, no failed grading — the constraint holds behind the reasoning block, and no alternative design was needed. 8 of 8 scores in band; 8 of 8 equal across repeats with byte-identical reasons, so vLLM's batching risk did not materialise on an idle engine. The engine's own counter deltas equal the sum of the progress lines, so the figures are attributed and not assumed. Every one of the 16 stored rows carries the score, the reason's length, and the reason's SHA-256 prefix its progress line printed — the binding fix proven on the record, content-free on both sides — and `metrics` carries `prompt_tokens` and `completion_tokens` alone. Measured sizing (ADR-0017): seconds 4.27–27.53 against the 180 s request bound, completion tokens 198–1289 against the 2048 reserve, the padded `unsourced-length` case the expensive one at 63 percent. Named as **not** settled: whether the pinned xgrammar wheel enforces the reason's `maxLength` — the longest reason was 182 of 1000, so the grammar was never asked to cut one off, and code validation remains the guarantee. No finding for the maintainer; nothing was re-run.
