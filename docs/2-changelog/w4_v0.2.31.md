## Changes

This release implements workflow ticket 56 under the plan `docs/1-plans/two-cycles-chose-one-version.plan.md`, rulings (a) and (d); rulings (b) and (c) closed at triage. At `v0.2.28` two cycles rebased onto the same `main`, both read its tag as `v0.2.26`, both typed `v0.2.27`, and the second learned of it from `git tag`'s "already exists" after its release commit, masked gate, and export check had run against the taken number. The collision was decided at Step 2 and discovered at Step 12; it now surfaces at Step 2 as one line.

- **The taken-tag refusal** (`bin/release-git`). After the "not above `main`'s tag" refusal and before the message-subject check, so in both the `--derive` and the commit form and before any rename or write, the script reads `origin`'s tags once with `git ls-remote --tags origin` (peeled `^{}` entries dropped) and each candidate's local tag with `git rev-parse --verify`. A `__version__` whose tag exists is refused in the one-line `release-git: … Fix: …` shape, naming where the tag is — locally, on `origin`, or both — and the next free patch: the first number above `main`'s tag taken in neither place, so a taken run split across the two places is skipped whole. The walk is bounded and refuses rather than loops. A missing `origin`, or an `ls-remote` that exits non-zero, is its own refusal naming the remote, never a pass. The header comment names the refusal.
- **Tests** (`tests/test_release_git.py`, six cases added). The fixture gains a bare `origin` the primary pushes `main` and its tag to, so the existing sixteen cases run with the remote in place and stayed green. The new cases: the `v0.2.28` shape (a sibling tag on a commit not on `main` refuses the worktree's number, the retype to the next patch derives the renames, and the commit form commits and rebases with no unmerged file), the tag local only, the tag on `origin` only, `origin` unreachable (the commit form), `origin` missing, and two taken numbers skipped to the third.
- **The skills and the worktree rule.** `TRIP-3-release` Step 2 and `TRIP-hotfix`'s version line say the script's refusal is the retype's trigger and the renames the script's on the re-run, never a hand step; `docs/agents/worktrees.md` §8 step 1 says the same and its `_Origin_` gains ticket 56. `TRIP-3-release` Step 14 confirms the CI run of the release's own pushed tip, never the primary's `HEAD`, which may already carry a peer's release or a tracker commit: the tag's commit when no evidence commit was made, else the evidence commit's id, since `ci.yml` runs on pushes to `main` (Codex round one, P1). Step 15.4 confirms the tracker commit by its own id captured at the commit (the code review's one Major finding). `TRIP-hotfix`'s re-entry retypes when the script refuses — below the tip or its tag taken — and confirms by the tag's commit.
- **A known limit.** `ls-remote` over a real network can block rather than fail; no timeout is added, the contract being the exit code, and a hung run is interrupted and re-run.
- **Architecture**: Step 7: no structural change — no command, module, release constant, or test module added, removed, or renamed. `docs/archi/workflow-tools.md`'s git-tail paragraph names the refusal by replacing words, net-neutral: ~5,998 tokens of its 6,000 warning, as at the claim.
