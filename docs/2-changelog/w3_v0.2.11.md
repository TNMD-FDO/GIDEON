## Changes

This release implements slice-2 ticket 04 under the plan `docs/1-plans/gideon-eval-run-records-a-run.plan.md`: `gideon eval run` stops being a stub for the one frozen slice that needs neither the engine nor the frontend. The three layers every later suite reuses — a loader, a record, and a gate — land together and are proven on the `extraction` slice, sixty-two labelled cases through the bounded regex grammar, before any suite that costs engine hours is built on them. No minor is demanded by spec §2.1: no site key and no `/etc/gideon` contract change.

- **The frozen slices** (`eval/sets/eval-v1/slices/`): one directory per slice, one `.ids` file per source file, the README its authority. `extraction/harvest.ids` (the harvest's forty) is excluded from the export beside the cases it names, by `tools/exportboundary.py` and `.gitattributes`; `extraction/invented.ids` is kept. Until now a frozen slice was a glossary term with no committed id list.
- **The loader** (`gideon/evaluation/evalset.py`, new): reads a set version in sorted-path order, checks every case against a shape registry (suite and category, the ordered keys, the fixed fields, the id, cluster, role, court, and query-type patterns, the court-map check), resolves the slices' ids, and reports **every** finding at once, each naming the file and the id and carrying no question text. Order, slice order, findings order, and the SHA-256 `set_digest` over the ordered bytes are independent of file-creation order; one changed byte in a case file or an id list moves the digest. `supersedes` naming a higher-numbered id is refused whichever file holds it.
- **The runner** (`gideon/evaluation/extraction_slice.py`, new): the grammar over the slice's active cases with the registry's declared types as the landed types, the scorer's id-only report, and one content-free `CaseResult` per case (verdict, per-type counts, latency). `SLICE_RUNNERS` is the registry a later slice joins.
- **The record** (`gideon/evaluation/record.py`, `migrations/0004_eval_runs.sql`, both new): `eval_runs` and `eval_results`, the third and fourth kept-event tables, partitioned by the run's `started_at` under ADR-0027's scheme, each with its own hardened `<table>_ensure_partition` — the ruling that every kept-event table carries one, `turn_log` to follow. `gideon_eval` is the fifth role, holding `INSERT` and the two functions alone; the metrics role reads. The writer binds every value as a `psql` variable, refuses CR/LF/NUL, serialises JSON with sorted keys, and writes in one transaction. **The provenance columns** are five past [21] item 16's list — `slice`, `finished_at`, `verdict`, `git_dirty`, and `set_digest` (§7.9 leaves the final DDL to TRIP) — so ticket 05 can write a reference only from a clean run of the committed set.
- **The command** (`gideon/evaluation/command.py`, `gideon/cli.py`): `load` → `run` → `record` → `gate`, the gate's verdict the exit code, behind `_guarded`. `--slice` and `--set` join the surface (the `backup drill` precedent; §20.2 records neither — the spec-bug comment is on greenfield [21]). `record` is skipped without failing for a set outside the release and for an unreachable database (the row says rows were not written), and refuses for a site file that will not load, a broken git probe, or a failed write. **The git probe**: both `rev-parse HEAD` and `status --porcelain` run under a `safe.directory` grant for the checkout, since the command runs as root over a CSA-owned tree; both columns are null only where the checkout root has no `.git` entry, and then git is not called at all. A failing run of the release's own set is still recorded, with `fail` verdicts. `--decision` and `--force` refuse as not implemented, naming ticket 16.
- **Tests**: `test_evaluation_set.py`, `test_evaluation_run.py`, and `test_evaluation_record.py` (new) hold the refusals, the order and digest, the command's recorded and unrecorded paths in-process over a fake `Host`, the recorder's SQL, and the package's imports by AST. The shape cases moved off `test_extraction_set.py` and `test_judgments_queries.py` onto the loader's own module, each deleted with its twin landing. `test_stores.py` gains `Migration0004`; `test_secrets.py`, `test_render_consumers.py`, `test_cli_surface.py`, and `test_export_boundary.py` take the new role, secret, and entry.
