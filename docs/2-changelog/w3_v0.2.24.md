## Changes

- **The metric definition, `judgments@1`** (`gideon/evaluation/rankmetrics.py`, new; its docstring the definition's one home). §18.2's and [21] item 13's three numbers as code: **nDCG@10** on the attorneys' primary grades, **recall@50** with relevant meaning a grade of 2 or more, and **Hole@10**, the share of a query's top ten nobody has judged. Two rules sit under them. **Meets**: a ranked chunk meets a judged passage iff both carry the same source id and the same canonical-text SHA-256 and their half-open code-point ranges overlap by at least the threshold — `0.5`, an ADR-0017 starting value — of the **shorter** of the two, so a chunk inside a passage and a passage inside a larger chunk both meet at 1.0 and E11's small and large arms are scored alike. **Crediting**: the list is walked from rank 1, a judged passage is credited at most once, a chunk's gain is the highest grade among the passages it meets that are not yet credited, and a chunk meeting only credited passages keeps its rank, counts as judged, and gains 0 — ties broken by larger overlap then lower coordinates, so the walk is deterministic. Without crediting, a passage the indexer split in two is paid for twice: the ruling's example, P (grade 3) split into P1 and P2 with R (grade 2) behind them, scores **1.383** uncredited and **0.939** credited, and nDCG structurally cannot exceed 1. An unjudged passage holds its rank and gains 0 (trec_eval's and BEIR's definition, the one [21] item 13 cites), which makes nDCG@10 pessimistic by an amount Hole@10 states: the ruling's second example, grades A 3, B 2, C 0 against a list X, A, Y, B with X and Y unjudged, is 0.646 beside a Hole@10 of 0.5. The module is pure over integers, strings, and grades — no file, no clock, no host, no text — and nothing in it rounds.
- **Three populations, each stated.** Every figure is a *judged* query's — one with one or more primary grades. nDCG@10 is undefined when the ideal is 0, recall@50 when no passage is graded 2 or more, Hole@10 for an empty list; an undefined figure is null on the row, enters no mean, and the query is reported by id. **Each mean is over the queries where its own figure is defined and prints its own count**, so a single denominator cannot quietly average in a number that does not exist. A query with no grades yet carries null for all three, Hole@10 included: counting its trivially whole hole would let the state of the grading, not the retriever, move the number while forty-eight queries are graded a few at a time. Below 25 judged queries the summary says the set detects regressions and ranks nothing ([21] item 13).
- **The ranked-list file** (`gideon/evaluation/ranked.py`, new). The suite's production door is `/turn` with `stop_after: retrieve`, slice 4's; slice 3's Phase A needs the numbers first, so this cycle's door is a file — UTF-8 JSONL, one line per query, closed ordered keys `query_id` and `ranked`, each entry exactly `source_id`, `sha256`, `start`, `end`. No caption, no text, no score: the file is **content-free by shape**, and a `text` key is a refusal rather than an ignored extra. Rank is list position, length is unbounded and the metrics read the first fifty, and the file may live anywhere readable and is never committed. It is checked whole, every finding at once, located by line, query id, and entry ordinal and echoing no value: a query id of the judgments pattern, once per file, naming an active query of the slice; coordinates by the judgments module's own rule, through a shared helper so the two files cannot drift; no coordinates twice within one query.
- **A finding names the file `ranked-list`, never its path.** The Codex review's one major finding, addressed without an override: the ranked file lives outside the repository, so its directory can name a client or a matter, and a malformed-file or unreadable-file refusal would have printed it. The path is now used for the read alone and reaches no stream and no row; what identifies the file on the record is its SHA-256 (§19.4). A regression case reads a malformed and an absent file beneath a matter-like directory.
- **The `judgments` slice runner** (`gideon/evaluation/judgments_slice.py`, new) and **the verdict is coverage, never a metric**. One result per active query of the slice, in id order: a judged query with a ranked list is `pass` with its three figures (rounded to six places, null where undefined) and three counts; a query with no grades yet is `pass` with null figures and enters no mean; a judged query the ranked file does not cover is `fail` and is reported by id. The slice's verdict is true iff no judged query went unscored — the `judge-triples` precedent, where a case passes iff its grading came back. So a poor nDCG is a green run and a missing input is a red one, and no continuous figure can reach the gate (§18.3, ADR-0023). `command.py`'s `_gate` and `_reference_gate` are untouched and the never-gates tripwire's attribute lists do not move. The slice keeps no reference: its comparison is paired, ticket 16's.
- **The count is `graded_passages`, not `judged_passages`.** `tests/test_judge_never_gates.py` forbids a `metrics` key that *contains* one of its four tokens rather than one that equals it — which is how `failure_modes` and `raw_score` are caught as surely as the bare words — and `judged_passages` contains `judge`. The tripwire is never weakened to suit the code, so the key was renamed; the domain word is unchanged, since a judged query's passages are the ones the attorneys graded.
- **The door's flag: `eval run --slice judgments --ranked <file>`.** Whether a slice takes a ranked list is its registry entry's, a new `SliceSpec.takes_ranked` beside `reaches_engine` and `compares_reference`. A new **`ranked`** stage sits between `load` and `run` for such a slice: a missing flag and a stray one each refuse with the command that fixes them, the file is read against the slice's active ids with every finding printed before the refusing row, and otherwise the row carries the query count, the passage count, and the file's SHA-256. `RunContext` gains the lists as its last, defaulted field.
- **The run row names the definition and the file.** Recorded like any other run — one run row, one result row per active query, `kind=manual`, `repeats` 1, latency null — with the run row's `overrides`, empty until now, carrying one key: the definition id and the ranked file's SHA-256. It is the schema's one run-level free-form column, so no migration, and its other reader already agrees with the meaning: `eval reference` refuses a run with overrides, and a run scored over an arbitrary hand-built file must never become a release's reference.
- **The loader change ticket 08 handed on** (`gideon/evaluation/evalset.py`, `gideon/evaluation/judgments.py`). `_file_paths` skips the judgments file **by its name** under the set root, never by suffix, so the first committed `judgments/judgments.jsonl` no longer refuses every `eval run` at `load` with each grade line a malformed case. Its bytes **stay in the set digest**, read into the same file map the digest is taken over, so a changed grade moves the digest as a changed case does. Every `query_id` is resolved after the `supersedes` pass — an id naming no case, a superseded case, or a case of another suite is a finding by line, reported with every other finding at once — and `LoadedSet` carries the parsed records, the runner filtering `assessment: primary`. `judgments.py` gains a bytes-level parse that `read` wraps, so the loader reads the file once for the digest and the parse both and a fault is one finding rather than two, and a located-record form carrying each `Judgment` beside its line number, which the loader alone consumes; `read`'s signature and its eight-field result are unchanged, so the grading kit and `agreement` see nothing.
- **The committed slice and the export boundary.** `eval/sets/eval-v1/slices/judgments/queries.ids`, the thirty-eight committed query ids in id order, leaves at the export boundary with the queries it names — one prefix in `tools/exportboundary.py`, one directory-shaped line in `.gitattributes` — since an id list resolving to no case is a loader finding. In an export the registry holds a `judgments` slice the set does not, which `eval run` already answers correctly; the never-gates tripwire's drive now asserts that an entry the set lacks is one whose slice directory `absent_from_export` reports, so the development tree still drives every registered slice and an export's omission is the boundary's and nothing else's. A run on the release set before any grade exists reports 0 judged queries and the small-set line; the day slice 3's intake appends grades, the same command scores them with no code or set change.
- **The set digest moved, by design, and no reference is touched.** The digest is taken over every case file and every id list, so this cycle's committed set digests differently from `v0.2.18`'s. The committed `extraction` references need no re-record: `reference.compare_reference` reads the set version and the per-case verdicts and never the digest, and no reader holds a reference's recorded `set_digest` equal to the loaded set's. The precedent was already on `main` — the two committed references carry `v0.2.16`'s digest while the set has digested differently since `v0.2.18`, and they compare `current`. The reference check below confirms it. The loader change by itself moved no digest: no judgments file is committed.
- **Two known limits, stated and not solved**, in the module's docstring and the judgments README. A chunk that swallows two graded passages earns the higher grade alone, so a large-chunk arm cannot reach 1.0 on such a query; E11's own gold-span crossing rate is the companion figure. And a judged passage whose canonical text the index under test does not hold reads as not retrieved — the one named gap against §18.6, whose drop rule needs a generation's `(source id, hash)` manifest that has no producer until slice 3's sample build. It does not bite Phase A, whose pools are drawn from the sample index the arms are scored on. A unit case pins today's behaviour (the passage is unmet, the query still scored) and a dated `NOTES.md` line hands slice 3's `/to-tickets` the mechanism, the fact, and the trigger; the drop arrives as the definition's next `@N`.
