## Changes

This release implements slice-2 ticket 03 under the plan `docs/1-plans/courts-yaml-and-the-jurisdiction-check.plan.md`. It lands §8.6's court map as a committed product artifact and wakes its first reader: preflight's `jurisdiction` row, inert since slice 0, now judges the site's `circuit`, `districts`, and `states` against the map ([35] item 6's first rule). The rules that read a corpus lockfile's `courts[]` are not built; no lockfile exists until slice 3.

- **The map** (`courts.yaml`, repository root): every CourtListener court id → `{circuit, state, level, name}`, 3,361 rows from `courts-2026-06-30.csv.bz2` (sha256 `d5a7a5aa…37ea8be`), the file, date, hash, and per-level counts in its own `source` block. `scotus` 1, `circuit` 13, `district` 94 (the statute's counts, 28 U.S.C. §§ 41, 81–131); `state_supreme` and `state_appellate` for the fifty states, DC, and the five territories; every other row `other`. Generated, never hand-edited; geography, never a site key (ADR-0028).
- **The generator** (`tools/courtmap/`, `python3 -m tools.courtmap --csv <file> [--check]`): a pure join of the CSV to the hand table `tools/courtmap/geography.yaml` (`states`, `federal`, `state_courts`, `unplaced`, `corrections`), refusing any state-coded row the table does not place, so an upstream addition is a loud failure at the next regeneration. It never fetches. The table carries `dakotasup` as unplaced and fourteen upstream code corrections, each with its reason: `ohctapp1` (blank → `SA`), `oklacrimapp` (`SA` → `S`, Oklahoma's criminal court of last resort), and twelve live rows coded appellate that are not courts of appeal (eight trial courts → `ST`, `superctguam` → `TT`, three non-appellate bodies → `SS`).
- **The loader** (`gideon/host/courts.py`, bare-host): `egress.py`'s shape — a duplicate-key-refusing loader, collect-all validation, a frozen `CourtMap` with the queries its readers ask (by id, by level, nearest at a level, unresolved ids, a state's appellate courts), and the three closed vocabularies. Every refusal says to restore `courts.yaml` from the release checkout, never to regenerate it on a box. Codex's one finding — a present YAML `null` passing a required field — was fixed in both loaders with regression tests.
- **The check** (`JurisdictionCheck`, `gideon/host/checks/artifacts.py`; the runner in `gideon/host/preflight.py`): the map is loaded beside the locks and the allowlist and reaches every check on `PreflightContext.courts`; a missing or malformed map refuses before any row. An absent id refuses with the nearest id of the leaf's level; an id at the wrong level refuses naming both; every bad id is in the one row; the fix names the site key. A green row says the lockfile rules are not yet judged. The lockfile branches stay behind the `lockfile_courts` seam for slice 3, a state now warning when *none* of its appellate courts is installed ([35] item 6's wording).
- **The site model's words**: `jurisdiction.states`' description (`gideon/host/site.py`, `config/site.schema.json`) and the example's comment (`config/site.example.yaml` and its spec twin, byte-equal) say what a `states[]` id is — the state's court-of-last-resort id, expanded by USPS code — and the [35] item 6 refuse/warn split; the two render fixtures' `site_sha256` lines move with the comment.
- **A site file with a mistyped `jurisdiction` id is now refused** at `preflight`, and so at `install` and `upgrade`'s preflight. This is §3.4's recorded contract arriving, not a contract change: the box's ids resolve (below).
- **The proof** (`.scratch/slice-2/assets/03-on-box.txt`, driver `03-jurisdiction-proof.py`): the real `gideon preflight` on the box, 33 of 33 pass with `jurisdiction: pass — 3 jurisdiction id(s) resolved in courts.yaml`; a copy of the site file with one district id misspelt refused as `district 'tnmdx' (nearest 'tnmd')` with its fix line.
