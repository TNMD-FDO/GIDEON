## Changes

This release implements general-turn ticket 01 under the plan `docs/1-plans/gideon-api-in-the-rendered-stack.plan.md`: the first GIDEON service container. ADR-0045's `gideon-api` role joins the rendered Compose project on a GPU host, running from an image GIDEON builds, and answers its first route. Nothing in the frontend changes — its connection still names the engine until ticket 09, and no turn reaches the service before ticket 02's proof. No minor is demanded by spec §2.1: no site key and no `/etc/gideon` contract change.

- **The service** (`gideon/api/`, new): `settings.py` reads the four environment values and both mounted key files and refuses a missing or empty one by path; `auth.py` is a pure ASGI middleware comparing the bearer as bytes — never `BaseHTTPMiddleware` — answering an OpenAI-shaped 401 with `WWW-Authenticate: Bearer`; `upstream.py` is the bounded httpx client (2 s to connect, 5 s to read, both under the frontend's ten-second model-list timeout, so a dead engine is the service's 502 and never the frontend's own timeout); `app.py` carries `/health`, unauthenticated and independent of the engine, and `GET /v1/models`, the engine's status and body passed through; `__main__.py` runs it under plain uvicorn with a 5-second graceful-shutdown bound, under Compose's ten-second stop grace. The request log holds a method, a route template, a status, and seconds and nothing else (§19.4).
- **The image** (`images/gideon/Dockerfile`, `images.lock`, both new to each other): §17.1's one image, `gideon-api` its first role. The Python base plus **ten `*_VERSION` build arguments** — the three direct packages and the seven resolved beneath them — installed wheels-only with no resolution, then `pip check`, run as an unprivileged user; no GIDEON code is copied in. Each argument carries a `pypi_project` watch entry of the kind `v0.2.10` landed, so `test_images_lock.py`'s contract — every committed build argument watched — holds as written. Built and recorded on the box in one batch with the pin's commit; PyPI's two hosts join `image-build`'s egress group, and `tools/imagebuild`'s `Smoke` takes several version arguments for the first time.
- **The mount and its digest** (`gideon/host/render/api.py`, new; `render/{__init__,command,compose}.py`): the block bind-mounts `<checkout>/gideon` read-only, `<checkout>` being the tree that ran `apply`, and carries a label holding a sha256 over the service's declared sources (`gideon/api/` today). The digest is gathered through the `Host` seam with render's other inputs, recorded in the manifest's `inputs` block, and a moved digest is a `changed compose block` for `gideon-api` alone — so a host-tooling release recreates nothing and a mid-cycle edit re-applied from the same worktree is seen. `render_all` stays pure.
- **The key, the probe, and the row**: `gideon_api_key` is a generated secret in the registry with the engine key's rotation class, mounted beside the engine's key the service uses itself; `secrets rotate` names its one consumer. The blackbox probe gets a job and a `probe_success` rule of its own (`compose/grafana/provisioning/alerting/api-probe-rule.yaml.tmpl`, new), the pattern SearXNG's probe set, so a down service pages from the first release that runs it. The memory row is 1 GB, a starting value (ADR-0017) read again under E9 at ticket 06; the table's sum moves from 73 GB across twelve services to **74 GB across thirteen**.
- **The import tripwire** (`tests/test_service_import_boundary.py`, new): every import in the declared sources, at any depth, must be the standard library, an image dependency, or the declared set, and every `gideon` import must be at module level — so nothing of the mounted tree loads lazily after `upgrade` has checked a new tag out under a running container. `gideon/__init__.py`, which `python -m gideon.api` runs from outside the digest, is held inert: a docstring and the one `__version__` assignment.
- **Tests**: `test_api_service.py` (the service over `httpx.MockTransport`), `test_service_import_boundary.py`, and `test_render_api.py` are new; the memory-table union, the committed profile's row tuple, the consumer map and rotation, the self-update registry, the smoke's arguments, the egress allowlist, the ten toolchain copies, and every GPU-host `RenderInputs` builder moved with them, and all three render fixtures were regenerated. The whole suite is green: 1,867 tests, 5,504 subtests.
