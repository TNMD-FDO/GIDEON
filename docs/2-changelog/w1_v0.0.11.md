## Changes

- **Two new Compose services** (spec §20.1; slice-0 ticket 05): `postgres` (`postgres:18`, PGDATA on `/data/fast/postgres`, superuser password through `POSTGRES_PASSWORD_FILE`, a `pg_isready` healthcheck) and `open-webui` (`open-webui:v0.11.0`, `DATA_DIR` on `/data/bulk/openwebui`, `depends_on` a healthy Postgres, the Dockerfile's healthcheck declared in Compose because the published OCI config carries none). Both are pinned by OCI index digest in `images.lock` and pulled from the release registry; `config/egress.yaml` v4 adds GHCR's two hosts. Caddy's template now reverse-proxies to `open-webui:8080` in place of the 503 placeholder.
- **The frontend is configured from env and the apply manifest only** (§3.5, §4): `ENABLE_PERSISTENT_CONFIG=false`, self-signup off, the §4.2 permission set rendered as `USER_PERMISSIONS_*` from the versioned artifact `compose/open-webui/permissions.yaml` (every v0.11.0 leaf listed with its source), API keys on but endpoint-restricted to the release's allowlist (which binds admin keys too), sessions at `auth.session_hours`, strict secure cookies, metadata-only audit, the version update check off (an egress outside §2.3). The three values with no `_FILE` path (`LDAP_APP_PASSWORD`, `DATABASE_URL`, `WEBUI_ADMIN_PASSWORD`, plus the proxy URLs when credentials exist) live in a rendered raw-format `env_file` at mode 0600 that `render --diff` never prints; `WEBUI_SECRET_KEY` is a Compose file secret via `WEBUI_SECRET_KEY_FILE`.
- **LDAPS sign-in gated to the users group** (§4.1): the login filter is `(memberOf=<users-group DN>)`, RFC 4515-escaped; `sAMAccountName` is the username, AD `mail` the email (an account without `mail` is refused at sign-in — a runbook fact now recorded); group management on with creation off, so only the installer's pre-created groups are mirrored. **Site keys widen from CN to CN-or-DN**: `auth.ldap.users_group`, `admins_group`, and `mirror_groups[]` accept a group's full distinguished name (a CN derives AD's default `Users` container), and preflight's LDAP check now resolves every configured group by DN, refuses with the DN-form fix, and probes that the bind account can actually see membership through `memberOf` (refusing with the directory-permission fix otherwise). Both refusals fired live at TNMD and are recorded on the ticket.
- **Apply grows from eight to twelve stages** (`preconditions → secrets → render → registry → pull → recreate → stores → start → apply-manifest → verify → timers → record`): `secrets` generates the release's absent generated secrets (`gideon/host/secrets.py`'s registry; 0440 files; the break-glass password printed exactly once, on the run that creates it); `recreate` handles the store tier and `stores` converges it (roles `openwebui`/`gideon`/`gideon_audit` and both databases created absent-only over the container socket with SQL on stdin, then `migrations/*.sql` forward-only under a runner-owned `schema_migrations`); `start` recreates the rest only after that, so the frontend never boots against an uninitialized database; `apply-manifest` waits for `/ready` through the ingress, mints the break-glass and eval API keys absent-only, and pushes groups, permissions, the eval identity, and the (empty) Function and preset sets desired-state — a hand-added Function or a stray group is removed and named; `verify` adds the frontend's readiness; `timers` links the rendered `.service` units and enables the rendered `.timer` units; `record` writes `applied.yaml` only after verify.
- **`gideon users reconcile [--now]` is real** (§4.1, §19.4): bare reports with `would`, `--now` enforces. It reads direct group membership from AD through `ldapsearch` (bounded), lists frontend users with the break-glass key, skips the two machine identities, joins humans by AD `mail`, and enforces admin ⇔ admins-group both ways, `pending` for accounts outside the users group, reports orphaned knowledge bases on the post-reconcile role, flags admins outside the users group, and writes audit rows through the INSERT-only `gideon_audit` role: membership snapshots, then an intent row before and an applied row after each correction under one run id, each batch a single transaction, every correction announced only after its applied row. A rendered systemd timer runs it nightly at 03:00 with a start deadline; the first migration (`0001_audit_log.sql`) creates the monthly-partitioned `audit_log` with a partition-ensuring function the writer role may execute.
- **One stdlib frontend client** (`gideon/host/owui.py`): `http.client` to the ingress on loopback with SNI and the office CA, the site hostname as the `Host` header (Caddy routes by it), credentials never in diagnostics; shared by apply, reconcile, and the contract test.
- **CI** gains `frontend-contract` on the self-hosted runner after `mirror-images`: a throwaway Postgres + frontend pair on loopback from the mirrored digests proves a hand-added Function is removed by the manifest push, a second push changes nothing, store convergence is idempotent, and the audit role cannot read.
- **Spec bugs recorded on the ticket** (never improvised around): (m) §3.6's install-only bootstrap steps live in apply; (n) §4.2's 17 permission leaves against v0.11.0's 60-odd; (o) the plural `API_KEYS_*` names; (p) `WEBUI_SECRET_KEY_FILE` shrinks the `env_file` exception; (q) `VECTOR_DB=qdrant` waits for slice 3; (r) no Postgres extension is needed at first boot; (s) bare `users reconcile` reports.
- **On-box first pass** (`.scratch/slice-0/assets/05-apply-first-pass.txt`): three apply passes (the `Host` header and the unlinked service unit were found only on the real ingress and the real systemd), then all twelve stages ok and a no-op fourth; two directory findings — TNMD's groups live outside the default `Users` container (fixed with DN-form site values) and the bind account could not read `memberOf` (fixed by a *Read memberOf* delegation, now a preflight probe); a users-group member signed in over LDAPS, was promoted by reconcile with intent/applied rows, a non-member was refused, and the v0.11.0 access dialog shares knowledge bases with named users as well as groups. Every acceptance criterion exercised live.
- **Tests**: 96 new (364 total, 98 subtests) plus the two-case frontend contract on the box — the LDAP helpers and RFC 4515 escaping, the secrets registry and absent-only generation, store convergence (no password in argv, idempotent re-run, migration ordering and failure), the client over a loopback HTTP server and the bootstrap's order/idempotence/removals, the rendered env/env_file/manifest/units, apply's twelve stages and refusals, the audit writer's bound variables, and reconcile's membership truth table and write protocol.
