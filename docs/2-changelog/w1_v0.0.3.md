## Changes

First behaviour in the `gideon` package — the site-file model (spec §3.3–3.4, slice-0 ticket 01, the prefactor provision/preflight/render read through):

- **`gideon/host/site.py`** (new, bare-host): `FIELD_REGISTRY` declares Appendix C's 14 required and 19 defaulted leaves once — paths, kinds, defaults, allowed values, descriptions. A customized safe loader (duplicate keys refuse; YAML 1.1 boolean resolver removed on an isolated resolver table so `on`/`off` stay strings) feeds a collect-all validator: unknown keys refuse with the nearest valid key, missing required keys point at the example file's line, enumerated values refuse with the allowed list, shape checks cover timezones/CIDRs/types/empty lists, and file-level failures (missing/unreadable/non-UTF-8/parse error/empty/non-mapping) are structured errors with problem-specific fixes. Every rendered refusal ends with its fix (§1.5). One frozen dataclass per section; `auth.ldap.search_base` derived from the LDAP host when omitted.
- **`gideon/host/site_schema.py` + `config/site.schema.json`** (new): a byte-deterministic JSON-Schema (draft 2020-12) emitter over the same registry; the committed artifact is the editor schema §3.4 requires, regenerated via `python3 -m gideon.host.site_schema` and pinned byte-for-byte by a drift test. `search_base` carries no default (it derives); `web.search` is the string enum `on|off`.
- **Tests**: `tests/test_site_validation.py` and `tests/test_site_schema.py` (15 tests, 74 subtests) pin the ticket's acceptance criteria — example-file conformance and resolved defaults, the recorded refusal message shapes over `tests/fixtures/site/`, loader failures, resolver isolation, and both drift gates (schema bytes, example-line table).
- **CI**: `PyYAML==6.0.3` added to the dev-tool install (stands in for the box's `python3-yaml`; the product never installs from PyPI).
- **Tracker**: ticket 01 planned (`docs/1-plans/F_0.0.3_site-file-validation.plan.md`), implemented, and resolved; the §3.3 leaf-count discrepancy recorded as a spec-bug comment. `hardware_profile`'s `models.lock` cross-check is deliberately inert until that lock exists (discovery ruling); jurisdiction id cross-checks belong to preflight (ticket 03).
- No CLI surface change: §20.2 records no `site validate` command — preflight (ticket 03) is the surface that tells a CSA whether the file is valid.
