# General's frontend contract

What GIDEON takes from its frontend for General, written down so the dependency can be measured and can shrink. The frontend is Open WebUI, unforked (ADR-0001), and stays so; ADR-0045 rules that GIDEON owns General's turn and that the direction is a replaceable frontend — everything GIDEON takes from the frontend a written contract that shrinks a layer at a time, when a cycle is already there and never as a project of its own. This document is that contract for General. It is edited in place by the release that moves a layer, and slice 6's frontend contract suite (spec §22.1) is to become its tested form.

**From `v0.2.29` this document is the record of the running mechanism**, the `general-turn` effort's cutover having landed: the frontend's one connection is General's service and the branch gate (row 8) is the one GIDEON Function inside the frontend. Facts of the frontend are as read on the pinned tag (`v0.11.3`) at standing ticket 78's triage; a pin bump re-reads the rows its release notes touch.

## 1. What the frontend is given

One OpenAI-compatible connection, with no guardrail and no stamp of GIDEON's left inside the frontend. General's service answers `GET /models` under the generator's served name and serves chat completions, streamed and whole; it is the only caller of `gideon-generator` on General's behalf, judges every completion with the arithmetic guardrail's shared module, and appends the citation stamp. A frontend that satisfies section 2 receives a judged, stamped answer over Chat Completions; a client that speaks the protocol and brings none of section 2 gets the judged, stamped model without General's instruction, search, or gate, which is what section 4's layers would close. What reaches the screen and the stored chat is the answer as streamed text, or the released prefix and the tripped family's refusal, with the stamp appended under a citation-shaped answer, and no reasoning text.

## 2. What General takes from the frontend

| # | Dependency | What GIDEON relies on | If it changes |
|---|---|---|---|
| 1 | **Sign-in** | The frontend authenticates every person under the directory identity (ADR-0030) and admits only signed-in users to General; the service authenticates the frontend alone (row 6) and never a person. | Reconcile's and the break-glass account's proofs (`tests/test_users_reconcile.py`, `tests/test_tls.py`); nothing in the service. |
| 2 | **Chat storage and rendering** | The frontend stores and paints what the stream carried: `content` deltas as the answer's text; it never reads `finish_reason` and absorbs absent reasoning deltas, so an answer ended at a refusal renders and is stored as text. Since general-turn ticket 06 the service settles that end itself: a tripped stream ends as the engine ends any stream, a finish chunk under `stop` and then `[DONE]`, and no reasoning key is sent on either path, streamed or whole. Retention of the stored chats is the frontend's store (spec §19.3). | The turn harness's stored-shape read in both modes. |
| 3 | **The search path and File Context** | The native web search against SearXNG, the page loader, and File Context run before the model call and put the fetched pages into the messages the service receives; the sources reach the browser as the frontend's own event. The per-chat default-off toggle and the privilege reminder on the search-confirmation dialog are the explicit act before egress (spec §15). | The search-sentinel contract and the browser mode's page facts. |
| 4 | **General's record** | The preset carries General's instruction (`params.system`), its versioned id, and its capability toggles; a preset's turn reaches the connection rewritten to its base's id, so the service sees one model id. The base row keeps its public-read grant, without which General answers "Model not found". | `bootstrap`'s model sync and the frontend contract job. |
| 5 | **The forwarded headers** | `ENABLE_FORWARD_USER_INFO_HEADERS` rendered on, in the plain form: `X-OpenWebUI-User-Name` (URL-quoted), `X-OpenWebUI-User-Id`, `X-OpenWebUI-User-Email`, `X-OpenWebUI-User-Role`, and `X-OpenWebUI-Chat-Id`, on chat completions and task calls alike. The frontend strips `metadata` from the upstream body and sends no OpenAI `user` field, so the headers are the only identity on the wire. The service decides on **one** of them, the email, for one purpose — the guardrail trip's `source` word, `eval` when exactly one value under it equals the eval identity's rendered address after trimming and case-folding, `user` when it is absent, empty, repeated, or another's — and never logs, stores, or forwards any of them (spec §19.4). The email is the one that can decide: the eval identity's role is every seat's and its name a display string, while its address sits under `.invalid`, which no directory identity can hold (ADR-0030). The header's name and the identity's value reach the service as rendered settings, so Open WebUI's name appears in the render alone. The signed-JWT form is unused. | The kept event's `source` on an eval turn and a seat's turn. |
| 6 | **The connection's bearer key** | The frontend presents a per-connection bearer key, a generated secret file like the engine's (spec §1.7); the service refuses a request without it and holds the engine's key itself. | `secrets rotate` for the key; the connection's render. |
| 7 | **The task calls** | General is the task model (spec §15): a chat's title and tags and the search's queries arrive on the same connection as whole completions, run no Filter in the frontend, and are judged whole like any other. They are **stamped** like any other too (general-turn ticket 08): no body field, header, or model id separates a task call from a whole chat turn on the pinned frontend, so the citation stamp takes no branch, and a citation-shaped task output carries ADR-0043's label after its JSON object. What discards it is the frontend's own parse — on every live task path it keeps the text between the first `{` and the last `}` — so the label rides with a search query used whole and never reaches a stored title or tag. A stored tag is read from the record's `meta.tags`, the tag ids the frontend writes there; the chat blob's own `tags` is the empty list the page writes at the chat's creation and never touches (general-turn ticket 15). A replaced task output is the correction signal; the lever, if one is ever wanted, is a `{{TASK}}` header on the connection, which needs the per-connection configuration the render leaves out on purpose. | The title and query tasks after a turn in the browser mode, and the title and tags read after a citation-shaped one. |
| 8 | **The branch gate's Function** | The one GIDEON Function left inside the frontend: an inlet-only global Filter that refuses a `user`-role request on a model row with no base — the hidden base addressed by its own id — before anything is called, admins and the eval identity passing. It stays because the wire cannot tell the base row from General (row 4). It depends on the frontend's Filter inlet and the model entry's `info.base_model_id`. | The gate's inlet probe at every frontend pin bump. |

## 3. What the frontend stopped carrying at the cutover

Retired at `v0.2.29` (general-turn ticket 09), this section the record of what left. The arithmetic guardrail's Filter whole — its stream hook and outlet, its per-request state on `__metadata__`, its cancel of the frontend's chat task, and the session refusal, which has nothing left to guard once every completion is judged; the citation stamp's Filter; and the audit role's secret on the frontend's mounts with the Filter's Postgres driver import, the service writing the guardrail trip's row itself (ADR-0045 superseding ADR-0039). The outlet's whole-message replacement was not rebuilt: a trip leaves the released prefix and the refusal on every path, the direct path included.

## 4. The layers left

Each is a dependency this contract still holds, with the event that would move it; none is owed, and none adds to `general-turn`'s build. The open slice's notes carry them as dated lines, moved forward whole at each slice's close until a split or a triage acts.

1. **General as the connection's own row.** The pinned frontend applies a model row's `params` with or without a base, so General could be the record on the service's own model id with no hidden base beneath it, and the branch gate (row 8) would have nothing to refuse. Unread on the pin: what the task calls then receive, how the row's capabilities behave on the chat path, and what becomes of the versioned preset id. Opened as `.scratch/slice-2/issues/25-general-as-the-connections-own-row.md` at `v0.2.29`'s close-out, with layer 2; awaiting triage.
2. **General's instruction.** The preset's `params.system`, injected by the frontend, is what makes the model General (row 4); a second frontend would get the raw model, judged and stamped but without the instructed refusals. The service owning the instruction, and with it the record of which instruction answered a chat, closes that. It is the second half of slice-2 ticket 25, opened with layer 1.
3. **General's search.** Row 3 whole is the frontend's, so a second frontend brings its own search and its own reminder. A search step owned by the service is the lever; its open question, a person's ruling, is how the explicit act before egress is kept without the frontend's dialog. Trigger: a pin bump that changes the dialog or the native search path, or slice 7's split.
4. **The Legal chat's turn events.** Spec §13.1 has `/turn` stream its own events with the Pipe as transport; the direction asks slice 4 to keep the source chips, the status phases, and the final `replace` defined as `/turn`'s protocol, the frontend's event names appearing in the Pipe alone. Trigger: slice 4's split.
5. **The Legal chat's other dependencies.** ADR-0022's list beyond sign-in and the Pipe — the file upload, knowledge-base sharing, the extraction hook — arrives with Ingestion GA; the direction asks for a GIDEON interface before each. Trigger: slice 6's split, whose contract suite tests this document.
6. **Identity, storage, and the host tooling.** Rows 1, 2, and 5 themselves, and the tooling written against the frontend — the render's frontend module, `bootstrap`'s model and Function sync, the managed turn the turn harness, `engine verify`, and the sentinel contract share, the harness's browser mode. The last layer and the one a receiving office would meet. Trigger: slice 7's split, which decides whether the frontend becomes a named seam of the distribution or stays Open WebUI alone with this document as the record.
