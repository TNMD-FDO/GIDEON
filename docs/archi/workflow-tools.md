# The development repository's tooling — architecture leaf

**Read this when** implementing the cycles record, tracker board, cycle launcher, guard scripts, or public export; the owning modules are `tools/cycles.py`, `tools/tracker.py`, and the scripts under `bin/`, each in the Inventory with its tests. All of it is development-repository tooling the public export omits; the tools the export carries — the gate and the export boundary list among them — are [`tools.md`](tools.md)'s. The map is [`../ARCHI.md`](../ARCHI.md); its §8 table names every command's leaf.

## Commands

- **The cycles record** (`python3 -m tools.cycles`, the dev venv on the machine holding the transcripts; `tools/cycles.py` and `tests/test_cycles.py`; workflow tickets 06, 20, and 34): reads the checkout family's harness transcripts — the primary's and its worktrees', a run from a worktree resolving its primary — and writes one row per session (its ids, turns, **peak context**, compactions) under the band table per effort, read from the tickets' directories against the two constants. Without arguments the tables go to stdout; `--latest` prints one line, the count a session reads at a seam, `--session <prefix>` selecting the present session; `--write` merges into `.scratch/CYCLES.md` by short session id, on demand, never by a release. The three decisions it serves are a ticket's band, the seam, and the pairing (`CLAUDE.md`'s Ticket sizing). Invariants: ids and figures only — a model id and an effort word are ids — no prompt text (§19.4); a transcript without usage or with a malformed `usage` yields no row and is counted, never a row of zeros; a second write byte-identical; every refusal prints its fix and writes nothing.
- **The release's git tail** (`bin/release-git <message file>` and `--derive`, in the cycle's worktree at the release's commit, rebase, and merge re-entries; `bin/release-git` and `tests/test_release_git.py`; workflow tickets 32 and 38): the version is typed once, in `gideon/__init__.py`, and the script derives its copies before any git command — the release files the branch adds since the merge-base renamed to `__version__`, their version lines and the changelog's title rewritten, the README's status tag moved, and the `CHANGELOG.md` index line written for the changelog file (a hand-written phrase kept) — each printed by path; `--derive` stops there. With a message file, the decision printed next — an **amend** when HEAD is not reachable from `main` and HEAD's subject starts with the file's type prefix, else a commit from the file — then `git add -A`, the commit or amend, and `git rebase main`, each printed as `+ <argv>` first. Invariants: the refusals (a bad message file, a directory outside a work tree, the branch `main`, a rebase in progress, `__version__` absent or not above `main`'s tag, the subject naming another version, two release files under one directory, a rename target in the way) print `release-git: <problem>. Fix: <fix>` and exit 1 before any write, so a conflict's unmerged files are never staged; a second run changes nothing; it stops at the first non-zero exit with that code, a rebase conflict left in progress for §8; no flag for the evidence-commit reset or the tag; a wrong argument count exits 2.
- **The public export** (`bin/release-export v<x.y.z>`; slice-1 ticket 57): its guards — a worktree copy, `origin` not `TNMD-FDO/GIDEON-dev` (the public URL its name swapped), the tag not on `main` and `origin` at one commit, no git identity, `gh` reading `TNMD-FDO/GIDEON` as other than itself and public — refuse first; a tag already public goes to the wait. Else the tag's archive, in a temporary directory, passes the primary's `ruff`, `mypy`, and `pytest`; a clone of the public repository on `main`, whose tip must be empty or a `v*` tag's commit titled that tag (**the lineage invariant**), is emptied, refilled from the archive, committed with the tag as the message (empty allowed), tagged, and pushed `--atomic`; the export commit's public `ci` run is polled within a bound. Invariants: `+ <argv>` lines; `release-export: <problem>. Fix: <fix>`, exit 1, before any public write; a red check, refused push, red run, or timeout keeps and names the directory; the checked tree is never the committed one; nothing forced; usage exits 2.
- **The claim's worktree** (`bin/worktree-claim <slug> [feat|fix|hotfix]`, from the primary's root at `TRIP-1-plan`'s claim; `bin/worktree-claim` and `tests/test_worktree_claim.py`; workflow ticket 32): resolves its own path as `bin/trip` does and refuses a copy under `.claude/worktrees/`, then from the primary `git worktree add .claude/worktrees/<slug> -b <kind>/<slug> main` and the relative `.venv` link, each printed, the worktree's absolute path the last stdout line, for the `EnterWorktree` call that follows. Invariants: a worktree already registered for the branch or at the path is refused with the enter-it fix and nothing is created; a malformed slug or kind is the usage line and exit 2; git's own refusals pass through as they come.
- **The release's removal** (`bin/worktree-remove <slug> [--units-dir <dir>]`, from the primary's root in `docs/agents/worktrees.md` §8 step 10's slot; `bin/worktree-remove` and `tests/test_worktree_remove.py`; slice-1 ticket 84): self-resolves and refuses a copy under `.claude/worktrees/` as the claim does. Stages: the worktree registered, its branch read from git's listing; the branch on `main`; no rendered unit's `WorkingDirectory=` naming the worktree or a path under it; then `git worktree remove` (never `--force`) and `git branch -d`, each printed. Invariants: every refusal comes before any removal; a unit naming the worktree is refused with the upgrade from `/opt/gideon` at `main`'s nearest version tag as the fix; an absent or empty units directory passes; a malformed argument is the usage line and exit 2.
- **The tracker board** (`python3 -m tools.tracker`, the dev venv in the primary at the outstanding-items step or any checkout by hand, never a `gideon` command; `tools/tracker.py` and `tests/test_tracker.py`; workflow tickets 01, 04, and 32): reads every ticket under `.scratch/<effort>/issues/` once — the title and the `Status:`, `Blocked by:`, and `Tag:` lines — and the vocabulary from the one `Statuses:` line in `docs/agents/issue-tracker.md`, and writes `.scratch/BOARD.md` and its page `.scratch/BOARD.html` from one model, sections in this order: the lint, the critical path to the next tag, the frontier, the decisions owed, the triage owed, every open ticket by effort in the vocabulary's order, and the standing tickets in a section of their own; the blocker grammar, the standing ticket's two states, and each lint rule are `issue-tracker.md`'s conventions, read as written there; without git the ages are blank and the claim rule unchecked, said in the header. Invariants: numbers, titles, statuses, references, and ages only, never a ticket's body (§2.6); two runs over one tree, one set of facts, and one date are byte-identical in both files; the page carries no script and no external reference; the threshold constant is held to the figure the tracker document states; exit 0 when both files were written; `--check` writes neither file (the worktree form, `issue-tracker.md`); `--strict` exits 1 on findings in either form; every refusal prints its fix and writes nothing, both files or neither.

## Footprints

None on the box. The cycles record and the tracker board use the dev venv, import only the standard library, never run on box units, and write only in the checkout. The bash files under `bin/` run in the checkout with git (export also `gh`) and have no footprint.

## Tests

- `test_cycles.py` — the cycles record over a synthetic store: the merge's byte stability, the refusals, the hygiene assertion, and the AST check holding `tools/cycles.py` to the standard library.
- `test_trip.py` — the launcher by subprocess: the dry-run lines from the table, `cycle`'s chain through a fake `claude`'s records, the refusals, the exit codes.
- `test_tracker.py` — the tracker board over a synthetic tracker and the real one: the AST check holding `tools/tracker.py` to the standard library, the threshold constant and `triage-labels.md`'s column held to the tracker document, both renderers byte-stable and the page self-contained, the check mode and the refusals writing nothing.
- `test_release_git.py` — the release's git tail by subprocess in a temporary repository: the derivations, commit, rebase, and amend, the conflict stop, `--derive` twice changing nothing, the refusals leaving files, log, and unmerged files untouched, the usage exit.
- `test_release_export.py` — the export beside two bare repositories named as the real ones, stub tools and `gh`: first, second, and empty exports, a re-run, the lineage and hook refusals, red checks and runs, each guard, usage.
- `test_worktree_claim.py` — the claim script copied into a temporary primary, never run in place: the worktree on its branch with the `.venv` link and the path as the last line, the three kinds, the refusals, the usage exits.
- `test_worktree_remove.py` — the removal script copied into a temporary primary with a temporary units directory: the removal and the branch's deletion, the unit refusal and its bare tag's upgrade fix, the unmerged and unregistered refusals, the absent directory, the usage exits.
