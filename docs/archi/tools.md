## Tooling on the box

The build tool, pin watch, acceptance harness, turn harness, and evidence redaction run with system Python and `python3-yaml`, importing `gideon.host` and `gideon.guardrail` and nothing heavier (the turn harness also loads three Functions by path, release content and not modules: under `--probe-inlet` the guardrail's for the session refusal and the branch gate's for the branch refusal, and the citation stamp's for its tail). Browser mode alone runs from the dev venv: `tools/turns/chromium.py` imports Playwright inside its launch function. The gate uses the dev venv, imports only the standard library, and never runs on box units. The acceptance harness also needs the `kvm` target state; it and the turn harness run as root through `sudo` and hand output back through `tools/ownership.py`.

## Footprints

**`/root/.config/gideon-turns/`** is the turn harness's browser-mode footprint, development-only and never product state: the test account's password file (root-owned 0600, typed by a CSA), the headless shell, and the browser's own `HOME` with the NSS store `--trust-ca` fills from `/etc/gideon/ca.pem`; removed with `sudo rm -rf` of that directory and `pip uninstall playwright`.

On the build box: `/etc/sudoers.d/gideon-acceptance` (the runner's one line) and `/data/acceptance/<name>/` (one acceptance run's disks, under `disk-layout`'s managed directory; the teardown row reports its allocated size).

## Commands

- **The build tool** (`python3 -m tools.imagebuild`, a CSA on the box, never CI; `tools/imagebuild/` and `tests/test_imagebuild.py`; ADR-0032): a built pin's Dockerfile built from the mirrored base by digest (BuildKit, `--provenance=false --sbom=false`), the **smoke command** (`SMOKE`) run *before* `docker push`, the pushed digest and `inputs_digest` recorded in the lock value-only and the render fixtures regenerated. `--check` proves the registry's image (present, pulls, labels equal the lock's inputs, smoke) and is what the contract module calls.
- **The acceptance harness** (`sudo python3 -m tools.acceptance <ref>`, the build box only; `tools/acceptance/` and `tests/test_acceptance.py`; ADR-0035): `run.STAGES` — `preconditions` → `image` → `seed` → `services` → `boot` → `clone` → `provision` → `reboot` → `site` → `provision-2` → `authorize` → `preflight` → `install` → `alerts` → `probe` → `rehearse` → `restore` → `verify` → `teardown` — one `StageResult` row each, teardown in a `finally` unless `--keep`. The VM is a no-GPU host with its own office services, cloning the box's checkout at any ref it resolves, a staged index included (`docs/agents/on-box-proofs.md` §5). Invariants: every transcript reaches `--out` only through `vm.redact`; the rehearsal's tag is made in a worktree of the mirror, the box's checkout never touched; the `install` stage requires the transcript's `engine-verify` phase row to be exactly the no-GPU skip row (`install.ENGINE_VERIFY_SKIPPED_DETAIL`), any other row red. **The full restore** (`--full-restore`; `tools/acceptance/fullrestore.py`; slice-0 ticket 20): `run.FULL_RESTORE_STAGES` — `preconditions` → `set` → the shared `image` … `preflight` → `apply` → `snapshot` → `restore` → `counts` → `decrypt` → `reinstall` → `apply-2` → `health` → `preflight-2` → `mode` → `users` → `backup` → `audit` → `drill` → `teardown`; `--until` refuses the other table's identifiers. Invariants: the `set` stage takes the product's staging selection and requires, before anything boots, the box identity's recipient among its manifest's and the manifest's `gideon_ids` record, so the form runs only over a set the release's tree made — a change to the manifest is proven after a `backup run` from that tree, never before; the snapshot on the VM's loopback target has the shape `backup push` writes; the stack is left running, the `restore` stage requiring the product's fresh-stack row (`restore.FRESH_STACK_SKIPPED_DETAIL`) and a `files` row carrying `restore.REOWN_MAPPED_DETAIL`, so the transcript shows the map ran and `preflight-2` that it sufficed; the box identity is named by path in the `age` argv alone and the plaintext tarball flows box `age` → SSH → VM `tar`, never through Python; the VM's site material is re-installed after the decrypt and before `apply-2`; transcripts are redacted with the VM's site and the box's. Both forms print an `elapsed:` line.
- **The turn harness** (`sudo python3 -m tools.turns <cases>`, the box only; `tools/turns/` and `tests/test_turns.py`; slice-1 ticket 35): rows `preconditions` → `signin` → one per case (`<id>`, or `<id>#<n>` under `--repeat`) → `summary` → `cleanup` → `record` (with `--out`). Per case a **managed turn** through the frontend's own chat path as the eval identity — one engine call, the managed turn and the chat finder of [`engine-frontend.md`](engine-frontend.md) — the stored answer read back and judged by the guardrail's judge, `gideon/guardrail.py` (`classify.py`) against the case's expectation and checks, the `withheld` and `sources` checks among them; `--stream` replays the turn on the raw streaming route with every released prefix judged, that chat alone deleted in a `finally`, a turn with none identified reported unverified; `--concurrent N` signs in N sessions and runs the set in each, rotated, at once (rows `<id>@<k>`, the guard counting the turns N times); `--unfiltered` (slice-1 ticket 76) posts each prompt once, bare and non-streaming, so the answer arrives past the Filter's replacement, and judges it offline (`classify.offline_judgement`) with no expectation applied — the Filter's verdict and each family's unsupplied figures on the row, raw hits in the record alone — then deletes any chat new since the turn that carries the run's sentinel, the live outlet still writing its `eval`-source trip row; `--case <id>` narrows any mode's retained set, an absent or retired id refused; the modes' refusals of one another are `cli.py`'s, made before sign-in. Invariants: the password read from its file and the session token held in memory; no prompt, answer, or secret in any row; the seed read directly (positives `refused`, controls `recorded` — counted, never gated), a case another names by `supersedes:` retired, in a cases file too; more than `SMOKE_TURNS` engine calls during office hours in the site's timezone refuses without `--force` (§18.5); the prompt tagged `[turn harness <sentinel> <case id>]` at its end; `--out` records handed back to the `sudo` caller. Exit 0 iff every case met its expectation, cleanup was verified, and the record was written. General's smoke set, `eval/seed/general/smoke.yaml`, is its pass/fail set, `load.yaml` timing turns and grading nothing (slice-1 ticket 39). The classes of `classify.KINDS` and the expectations each passes are the module's; a stored replacement may carry the cancel's released prefix before its refusal ([`engine-frontend.md`](engine-frontend.md)'s shape, slice-1 ticket 52), the prefix judged for a leak first; the decline form's length bound is a release constant of `classify.py`, a starting value corrected by the seed runs' lengths on slice-1 ticket 38; a `declined` or `disclaimed` row shows the stored length, and for the `guardrails` suite the controls' `declined` count is slice 2's `false-refusal` (§18.3; the qualifiers are ticket 38's ruling). **The browser mode** (`sudo .venv/bin/python -m tools.turns --browser`; `tools/turns/{browser,chromium}.py` and `tests/test_turns_browser.py`; slice-1 ticket 36) is the same loop behind a second turn driver: rows `preconditions` → `trust-ca` (when flagged) → `browser` → `signin` → `observe` → the case rows → `inlet-bare`, `inlet-chat-id`, and `inlet-base-model` under `--probe-inlet` (the replies held to the gate texts `classify.load_gate_texts` reads from the Function, a failed read a failed `preconditions` row) → `summary` → `cleanup` → `requests` → `record`. The guard counts each browser turn as `BROWSER_ENGINE_CALLS_PER_TURN` engine calls. A frame observer judges every painted frame of the answer with the same judge, and the row's `live` field names what a seat saw, every state but clean red; a painted answer ending in a refusal is a replacement, and the field then carries `refused at <s>, ended at <s>` on the page's own clock, their difference the cancel's cost. Invariants: every pause is the page's own, never a Python sleep; every request routed through one allowlist, any other host aborted and logged; `--stream` refused; the API mode untouched. `docs/research/owui-browser-surface-playwright.md` holds the page's and Playwright's facts; a frontend pin bump re-runs both modes on `eval/seed/general/frontend-bump.yaml` before its merge (`docs/runbooks/pin-watch-app-setup.md` §5).
- **The evidence redaction** (`python3 -m tools.redact --site <file>`, stdin to stdout, the box, as the session's user or under `sudo`; `tools/redact/core.py` and `tests/test_redact.py`; slice-1 ticket 55): `redact(text, site)`, the acceptance harness's `vm.redact` and the sink's redactor the same function. Invariants: the secret masking (the print-once line, the age identity, any age secret key token); the marked leaves of `FIELD_REGISTRY` (`office_value`) the one list, each value replaced by its site-key placeholder; a value equal to its registry default, an empty value, and a loopback or unspecified address never matched; whole tokens, longest first, never inside a placeholder already present; a text passed twice unchanged; a stored message redacted decoded and re-serialized only when changed; the command's one refusal the loader's, exit 1 with each fix and nothing on stdout; under `sudo` the checkout's bytecode caches handed back.
- **The pin watch** (`python3 -m tools.pinwatch`, never a `gideon` command; `tools/pinwatch/` and `tests/test_pinwatch.py`; ADR-0031, ADR-0033, ADR-0041): reads the four records from `origin/main` (the three product locks, the provenance line of `docs/agents/tooling.md`) and the `pin-watch/*` branches and pull requests, judges each pin of `pin_registry` by its branch's state, and opens or updates one bump pull request per pin. **A model pin** (`hub.py`, slice-0 ticket 14) follows the Hub repository's default-branch head and regenerates the model's `files` block beside the value-only revision; `.hub <repo> [<revision>]` prints a candidate's `files:` block by hand. **A built pin's watched argument** is read at an apt index or, by `pypi.py` (general-turn ticket 10), at PyPI's Index API (PEP 691): the newest stable release above the value — a final or post release with an unyanked file — each file attributed to a version by its filename, a release passed over beside an unattributed file one `failed` row, never a silent skip; a replacement YAML would read as a number is written quoted; the facts are `docs/research/pypi-index-api-pin-watch.md`'s, on its research branch until general-turn ticket 01's release folds it. **Every body ends with the research notes verified against the pin** (`notes.py`, workflow ticket 05), each note's front matter under `docs/research/` naming the pins it was verified against; `.notes` lists the join per pin offline. Images resolve to the **newest same-shape tag**, an unbroken tie one `failed` row proposing nothing (slice-1 ticket 15); a leading-component change, the driver branch, the minimums, a built pin's inputs, a model bump that moves a role's bytes while a memory row names the role (§7.6), and the Matt Pocock skills' pin (`skills.py`) are **proposals** a person completes (`driver.tested` never moves). Invariants: a product-lock bump carries the lock patched value-only **and the render fixtures regenerated**, because their manifests embed the three locks' digests; a failure is one `failed` row and the run continues; `--dry-run` writes nothing.
- **The release note's section** (`python3 -m tools.pinwatch.bumped [--since <tag>] [--root]`, run in the cycle's worktree at the release after the version bump, never a `gideon` command; `tools/pinwatch/bumped.py` and `tests/test_pinwatch_bumped.py`; slice-0 ticket 14): one line per product-lock pin moved since the previous user-facing tag (`--since` naming one instead), or the one sentence that no pin moved — the text `docs/release-notes/TEMPLATE.md` takes whole under `## What was bumped`, held to the generator's exported grammar by `tests/test_release_notes.py`. Invariants: the skill record excluded; two runs over one tree byte-identical; a refusal prints its fix with nothing on stdout.
- **The court map generator** (`python3 -m tools.courtmap --csv <path>`, the dev seat, by hand; `tools/courtmap/` and `tests/test_courtmap.py`; slice-2 ticket 03): CourtListener's bulk `courts` CSV, fetched once by hand from `https://com-courtlistener-storage.s3-us-west-2.amazonaws.com/bulk-data/courts-YYYY-MM-DD.csv.bz2` and never committed, joined to the hand table `geography.yaml` — `states`, `federal` (`scotus`, the circuits, the districts), `state_courts`, `unplaced`, `corrections` — into `courts.yaml`, one line per id, sorted. Invariants: the tool never fetches; the date comes from the file name and the hash from the compressed bytes; the placement sections are exclusive and `corrections` orthogonal to them; a state-coded row the table does not place is refused, so an upstream addition is a loud failure at the next regeneration; the statute's counts are refused when wrong; the written text is loaded back through `host/courts.py` before it is written; `--check` writes nothing and is red when the committed map differs.
- **The gate** (`python3 -m tools.gate`, any checkout's root, CI's one step; `tools/gate.py` and `tests/test_gate.py`; workflow ticket 42): ruff, mypy, then `pytest -x` over the paths given or the suite less the `slow` mark, `--all` (CI) including it; stops at the first failure with its code; one line; the tools found beside the interpreter, then `.venv/bin`, then `PATH`.
