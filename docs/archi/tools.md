## Tooling on the box

The build tool, pin watch, acceptance harness, turn harness, and evidence redaction run with system Python and `python3-yaml`, importing `gideon.host`, `gideon.guardrail`, and `gideon.api.stamp` — whose own test holds it to the standard library for this reader — and nothing heavier; the classifier strips the label's tail from that import, and the turn harness still loads two Functions by path, release content and never modules: under `--probe-inlet` the guardrail's for the session refusal and the branch gate's for the branch refusal. Browser mode alone runs from the dev venv: `tools/turns/chromium.py` imports Playwright inside its launch function. The gate runs from the dev venv on the standard library and its sibling `tools/mask.py` alone, never on box units. **The mask** needs `sudo`, util-linux (`unshare`, `setpriv`, `mount`), and `ip`, all of the base image, and leaves no footprint: the namespace ends with its process, so nothing shared with Gideon Transcribe is touched and two sessions' masked gates are independent. The acceptance harness also needs the `kvm` target state; it and the turn harness run as root through `sudo` and hand output back through `tools/ownership.py`.

## Footprints

**`/root/.config/gideon-turns/`** is the turn harness's browser-mode footprint, development-only and never product state: the test account's password file (root-owned 0600, typed by a CSA), the headless shell, and the browser's own `HOME` with the NSS store `--trust-ca` fills from `/etc/gideon/ca.pem`; removed with `sudo rm -rf` of that directory and `pip uninstall playwright`.

On the build box: `/etc/sudoers.d/gideon-acceptance` (the runner's one line) and `/data/acceptance/<name>/` (one acceptance run's disks, under `disk-layout`'s managed directory; the teardown row reports its allocated size).

## Commands

- **The build tool** (`python3 -m tools.imagebuild`, a CSA on the box, never CI; `tools/imagebuild/` and `tests/test_imagebuild.py`; ADR-0032): a built pin's Dockerfile built from the mirrored base by digest, the **smoke command** (`SMOKE`) run *before* `docker push`, the pushed digest and `inputs_digest` recorded in the lock value-only and the render fixtures regenerated. `gideon`'s smoke also refuses unless the Postgres driver imports on the binary libpq implementation and its two distributions report the same version ([`api.md`](api.md) has why). `--check` proves the registry's image (present, pulls, labels equal the lock's inputs, smoke) and is what the contract module calls.
- **The acceptance harness** (`sudo python3 -m tools.acceptance <ref>`, the build box only; `tools/acceptance/` and `tests/test_acceptance.py`; ADR-0035): `run.STAGES` — `preconditions` → `image` → `seed` → `services` → `boot` → `clone` → `provision` → `reboot` → `site` → `provision-2` → `authorize` → `preflight` → `install` → `alerts` → `probe` → `rehearse` → `restore` → `verify` → `teardown` — one `StageResult` row each, teardown in a `finally` unless `--keep`. The VM is a no-GPU host with its own office services, cloning the box's checkout at any ref it resolves, a staged index included (`docs/agents/on-box-proofs.md` §5). Invariants: every transcript reaches `--out` only through `vm.redact`; the rehearsal's tag is made in a worktree of the mirror, the box's checkout never touched; the `install` stage requires the transcript's `engine-verify` phase row to be exactly the no-GPU skip row (`install.ENGINE_VERIFY_SKIPPED_DETAIL`), any other row red. **The full restore** (`--full-restore`; `tools/acceptance/fullrestore.py`; slice-0 ticket 20): `run.FULL_RESTORE_STAGES` — `preconditions` → `set` → the shared `image` … `preflight` → `apply` → `snapshot` → `restore` → `counts` → `decrypt` → `reinstall` → `apply-2` → `health` → `preflight-2` → `mode` → `users` → `backup` → `audit` → `drill` → `teardown`. Invariants: the `set` stage takes the product's staging selection and requires, before anything boots, the box identity's recipient among its manifest's and the manifest's `gideon_ids` record, so the form runs only over a set the release's tree made — a change to the manifest is proven after a `backup run` from that tree, never before; the snapshot on the VM's loopback target has the shape `backup push` writes; the stack is left running, the `restore` stage requiring the product's fresh-stack row (`restore.FRESH_STACK_SKIPPED_DETAIL`) and a `files` row carrying `restore.REOWN_MAPPED_DETAIL`, so the transcript shows the map ran and `preflight-2` that it sufficed; the box identity is named by path in the `age` argv alone and the plaintext tarball flows box `age` → SSH → VM `tar`, never through Python; the VM's site material is re-installed after the decrypt and before `apply-2`; transcripts are redacted with the VM's site and the box's.
- **The turn harness** (`sudo python3 -m tools.turns <cases>`, the box only; `tools/turns/` and `tests/test_turns.py`; slice-1 ticket 35): rows `preconditions` → `signin` → one per case (`<id>`, `<id>#<n>` under `--repeat`, `<id>@<k>` under `--concurrent`) → `summary` → `cleanup` → `record` (with `--out`). Per case a **managed turn** through the frontend's own chat path as the eval identity — one engine call, the managed turn and the chat finder of [`engine-frontend.md`](engine-frontend.md) — the stored answer read back and judged by the guardrail's judge, `gideon/guardrail.py` (`classify.py`) against the case's expectation and checks, the `withheld` and `sources` checks among them; `--stream` replays the turn on the raw streaming route with every released prefix judged, that chat alone deleted in a `finally`, a turn with none identified reported unverified; `--concurrent N` signs in N sessions and runs the set in each at once, the guard counting the turns N times; `--unfiltered` (slice-1 ticket 76, general-turn ticket 05) asks `gideon-generator` for each prompt bare through `engine.call_engine` with the engine's own key, so the answer arrives past every judge, and judges it offline (`classify.offline_judgement`) with no expectation applied, raw hits in the record alone; no chat can exist on the engine's side, so nothing is watched or deleted and no live outlet writes an `eval`-source trip row for it; `--case <id>` narrows any mode's retained set; the modes' refusals of one another are `cli.py`'s, made before sign-in. Invariants: the password read from its file and the session token held in memory; no prompt, answer, or secret in any row; the seed read directly (positives `refused`, controls `recorded` — counted, never gated), a case another names by `supersedes:` retired, in a cases file too; more than `SMOKE_TURNS` engine calls during office hours in the site's timezone refuses without `--force` (§18.5); the prompt tagged `[turn harness <sentinel> <case id>]` at its end; `--out` records handed back to the `sudo` caller. Exit 0 iff every case met its expectation, cleanup was verified, and the record was written. General's smoke set, `eval/seed/general/smoke.yaml`, is its pass/fail set, `load.yaml` timing turns and grading nothing (slice-1 ticket 39). The classes of `classify.KINDS`, the expectations each passes, and the decline form's length bound, a release constant, are `classify.py`'s; a stored replacement may carry the cancel's released prefix before its refusal ([`engine-frontend.md`](engine-frontend.md)'s shape, slice-1 ticket 52), the prefix judged for a leak first; for the `guardrails` suite the controls' `declined` count is slice 2's `false-refusal` (§18.3; the qualifiers are ticket 38's ruling). **The browser mode** (`sudo .venv/bin/python -m tools.turns --browser`; `tools/turns/{browser,chromium}.py` and `tests/test_turns_browser.py`; slice-1 ticket 36) is the same loop behind a second turn driver: rows `preconditions` → `trust-ca` (when flagged) → `browser` → `signin` → `observe` → the case rows → `inlet-bare`, `inlet-chat-id`, and `inlet-base-model` under `--probe-inlet` (the replies held to the gate texts `classify.load_gate_texts` reads from the two Functions, a failed read a failed `preconditions` row) → `summary` → `cleanup` → `requests` → `record`. The guard counts each browser turn as `BROWSER_ENGINE_CALLS_PER_TURN` engine calls. A frame observer judges every painted frame of the answer with the same judge, and the row's `live` field names what a seat saw, every state but clean red; a painted answer ending in a refusal is a replacement, its refusal and its end timed on the page's own clock, their difference the cancel's cost. Invariants: every pause is the page's own, never a Python sleep; every request routed through one allowlist, any other host aborted and logged; `--stream` refused; the API mode untouched. `docs/research/owui-browser-surface-playwright.md` holds the page's and Playwright's facts; a frontend pin bump re-runs both modes on `eval/seed/general/frontend-bump.yaml` before its merge. **The service door** (`sudo python3 -m tools.turns --service`; `tools/turns/{door,doorclient}.py` and `tests/test_turns_door.py`; general-turn ticket 05) is the third driver and the first that reaches no frontend: rows `preconditions` → `door` → the case rows → `summary` → `record`, with no `signin` and no `cleanup`, because no chat can exist. Each case is one `POST /v1/chat/completions` to `gideon-api` under the connection's key, made by a standard-library client `docker compose exec -T` runs inside the service's own container — `engine.call_engine`'s shape — which reads the key from its Compose mount and takes the identity headers and the body on stdin; the key never enters the harness's process, an argument, a row, or a record. The harness is the frontend's adapter here (`docs/frontend-contract.md` §2 rows 4–6): it sends General's rendered instruction as the system message and the generator's served name as the model id, so a row means what it means in the two frontend modes, and `--no-instruction` sends the user message alone; it names itself the eval identity in row 5's forwarded headers and sends no user or chat id, which only the frontend's database holds. `--stream` makes that one call streamed, every released prefix judged by `classify.stream_verdict` under the shared `STREAM_LEAK_FAILS`; either way the guard counts one engine call per case × repeat × session. A searched case and a `sources` expectation, both reads of the frontend's own record, and the other modes' flags are refused before the first exec. The `withheld` check means here what it means on a stored chat.
- **The evidence redaction** (`python3 -m tools.redact --site <file>`, stdin to stdout, the box, as the session's user or under `sudo`; `tools/redact/core.py` and `tests/test_redact.py`; slice-1 ticket 55): `redact(text, site)`, the acceptance harness's `vm.redact` and the sink's redactor the same function. Invariants: the secret masking (the print-once line, the age identity, any age secret key token); the marked leaves of `FIELD_REGISTRY` (`office_value`) the one list, each value replaced by its site-key placeholder; a value equal to its registry default, an empty value, and a loopback or unspecified address never matched; whole tokens, longest first, never inside a placeholder already present; a text passed twice unchanged; a stored message redacted decoded and re-serialized only when changed; the command's one refusal the loader's, exit 1 with each fix and nothing on stdout; under `sudo` the checkout's bytecode caches handed back.
- **The pin watch** (`python3 -m tools.pinwatch`, never a `gideon` command; `tools/pinwatch/` and `tests/test_pinwatch.py`; ADR-0031, ADR-0033, ADR-0041): reads the four records from `origin/main` (the three product locks, the provenance line of `docs/agents/tooling.md`) and the `pin-watch/*` branches and pull requests, judges each pin of `pin_registry` by its branch's state, and opens or updates one bump pull request per pin. **A model pin** (`hub.py`, slice-0 ticket 14) follows the Hub repository's default-branch head and regenerates the model's `files` block beside the value-only revision; `.hub <repo> [<revision>]` prints a candidate's `files:` block by hand. **A built pin's watched argument** is read at an apt index or, by `pypi.py` (general-turn ticket 10), at PyPI's Index API (PEP 691): the newest stable release above the value, a release passed over beside an unattributed file one `failed` row, never a silent skip; the facts are `docs/research/pypi-index-api-pin-watch.md`'s. **Every body ends with the research notes verified against the pin** (`notes.py`, workflow ticket 05), each note's front matter under `docs/research/` naming the pins it was verified against; `.notes` lists the join per pin offline. Images resolve to the **newest same-shape tag**, an unbroken tie one `failed` row proposing nothing (slice-1 ticket 15); a leading-component change, the driver branch, the minimums, a built pin's inputs, a model bump that moves a role's bytes while a memory row names the role (§7.6), and the Matt Pocock skills' pin (`skills.py`) are **proposals** a person completes (`driver.tested` never moves). Invariants: a product-lock bump carries the lock patched value-only **and the render fixtures regenerated**, because their manifests embed the three locks' digests; the one fetch completes a shallow checkout first, the commit count behind `completed` being true only over a whole history (standing ticket 19); a failure is one `failed` row and the run continues; `--dry-run` writes nothing.
- **The release note's section** (`python3 -m tools.pinwatch.bumped [--since <tag>] [--root]`, run in the cycle's worktree at the release after the version bump, never a `gideon` command; `tools/pinwatch/bumped.py` and `tests/test_pinwatch_bumped.py`; slice-0 ticket 14): one line per product-lock pin moved since the previous user-facing tag (`--since` naming one instead), or the one sentence that no pin moved — the text `docs/release-notes/TEMPLATE.md` takes whole under `## What was bumped`, held to the generator's exported grammar by `tests/test_release_notes.py`. Invariants: the skill record excluded; two runs over one tree byte-identical; a refusal prints its fix with nothing on stdout.
- **The court map generator** (`python3 -m tools.courtmap --csv <path>`, the dev seat, by hand; `tools/courtmap/` and `tests/test_courtmap.py`; slice-2 ticket 03): CourtListener's bulk `courts` CSV, fetched once by hand from the address the package docstring names and never committed, joined to the hand table `geography.yaml` into `courts.yaml`, one line per id, sorted. Invariants: the tool never fetches; the date comes from the file name and the hash from the compressed bytes; the placement sections are exclusive and `corrections` orthogonal to them; a state-coded row the table does not place is refused, so an upstream addition is a loud failure at the next regeneration; the statute's counts are refused when wrong; the written text is loaded back through `host/courts.py` before it is written; `--check` writes nothing and is red when the committed map differs.
- **The gate** (`python3 -m tools.gate`, any checkout's root, CI's one step; `tools/gate.py` and `tests/test_gate.py`; workflow tickets 42 and 54): the environment comparison, then ruff, mypy, then `pytest -x` over the paths given or the suite less the `slow` mark, `--all` (CI) including it; stops at the first failure with its code; one summary line, its list led by `environment`; the tools found beside the interpreter, then `.venv/bin`, then `PATH`. **The comparison below** (workflow ticket 54) is the first child, run before the mask's first trial by the interpreter beside the tools and over the gate's own tree, so the pins are that tree's; no flag skips it, and its red runs nothing else. Tools in two directories or no interpreter beside them is the gate's own `environment:` refusal. **`--masked`** (workflow ticket 52, never the default) wraps the pytest step alone in `tools/mask.py`'s namespaces — ruff and mypy read nothing of the box — the gate process staying outside so it knows the state it reports; the trial runs twice, before ruff and again immediately before the wrapped step, so a lapsed `sudo` credential is a mask refusal and never a pytest red. Either summary line closes on the state the gate observed; a refusal at either trial, or a wrapped step exiting one of the mask's own codes, is red at `mask` and never at `pytest`. What a test may reach under it is [`tests.md`](tests.md)'s rule.
- **The environment comparison** (`python3 -m tools.environment [--pins-only]`, or the file by path under `-P` as the gate and the export check run it; `tools/environment.py` and `tests/test_environment.py`; workflow ticket 54): the running interpreter's installed distributions against the working directory's `requirements-dev.txt`, equal when every pin is installed at its version, every installed distribution is a pin, in the pins' requirement closure, or one of the installer's own, and the environment's own `pip check` is clean. Invariants: it is run **by the interpreter being judged**, reads no network, and takes the environment and the installer as one injectable seam each; the closure over-approximates by platform alone; an unreadable pin file is exit **2**, the environment unread, under a fix that repairs the file and never a rebuild, where an environment that differs is exit **1**, one line per package under one fix chosen by whether the interpreter's prefix is a symlink — through a link, never a command that would clear the tree it points at. Its grammar is the module docstring's.
- **The mask** (`python3 -m tools.mask -- <command>`, or the file by path over any tree; `tools/mask.py` and `tests/test_mask.py`; workflow ticket 52): the command run in a private mount and network namespace where every listed path reads as empty and loopback is the only interface ([`tests.md`](tests.md) names the paths), then dropped to the caller's identity with no new privileges under a named environment allowlist. Invariants: the root stage is one fixed text over util-linux and `ip` alone, the listed paths and the command its positional arguments, so no file of the checkout runs as root; the allowlist's values are read before `sudo` is reached, so `HOME` is never root's and no other environment name enters an argv (§16); the state is **observed**, never claimed or marked, so no listed path present proceeds and says so and a run already inside one wraps nothing; the drop is tried over `true` before it is used, and every setup failure is one line and `EX_OSERR`, so pytest's own codes can never read as the mask's; the refusals — as root, a tool missing, the trial failed, the working directory, executable, or `TMPDIR` under a listed path — each print their fix before any tool runs, never a prompt (ADR-0035) and never a skip.

## Tests

- `test_turns_browser.py` — beside the browser mode's own tests, the AST tripwire holding every `tools/turns` module but `chromium.py` to the standard library.
- `test_turns_door.py` — the in-container client over a loopback fake service, the door's driver over a fake `Host`, the refusal matrix before the first exec, the key and the forwarded header values absent from every row and record, and the AST tripwire holding `doorclient.py` to the standard library alone; its served name comes from the committed `config/site.example.yaml`, never the box's own file ([`tests.md`](tests.md)'s rule, held by the mask).

- `test_courtmap.py` — the join over a fictitious fixture CSV and table, each refusal with its fix, the hand table's strict loading, the writer's byte-stable round trip, `--check`, and the committed table and map coherent with each other without the CSV.
- `test_imagebuild.py`, `test_acceptance.py`, `test_smtpsink.py`, `test_pinwatch.py`, `test_pinwatch_pypi.py`, `test_pinwatch_bumped.py`, `test_turns.py` — the per-command modules of [`tests.md`](tests.md)'s pattern.
