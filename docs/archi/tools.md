## Tooling on the box

The build tool, pin watch, acceptance harness, turn harness, and evidence redaction run with system Python and `python3-yaml`, importing `gideon.host` and nothing heavier (the turn harness also imports the guardrail's Filter by path — release content, not a module). Browser mode alone runs from the dev venv (`sudo .venv/bin/python -m tools.turns --browser`): `tools/turns/chromium.py` imports Playwright inside its launch function, every other `tools/turns` module held to the standard library by `tests/test_turns_browser.py`, and its footprint is §4's `/root/.config/gideon-turns/`. The export boundary's module is a list and three predicates, never a command. The cycles record and tracker board never run on box units: each uses the dev venv, imports only the standard library (its test's AST check), and writes only in the checkout. The acceptance harness also needs the `kvm` target state; it and the turn harness run as root through `sudo` and hand output back through `tools/ownership.py`, as the redaction command hands back bytecode caches when `sudo` reads the site file. The four bash files under `bin/` — launcher, `bin/release-git`, `bin/worktree-claim`, and `bin/release-export` — run in the checkout with git (export also `gh`) and have no footprint; `bin/release-git` and `bin/worktree-claim` are the fixed scripts a worktree session's guard accepts as one plain command (`docs/agents/worktrees.md` §2, development repository).

## Footprints

**`/root/.config/gideon-turns/`** is the turn harness's browser-mode footprint, development-only and never product state: the test account's password file (root-owned 0600, typed by a CSA), the headless shell, and the browser's own `HOME` with the NSS store `--trust-ca` fills from `/etc/gideon/ca.pem`; removed with `sudo rm -rf` of that directory and `pip uninstall playwright`.

On the build box: `/etc/sudoers.d/gideon-acceptance` (the runner's one line) and `/var/lib/libvirt/images/gideon-acceptance/<name>/` (one acceptance run's disks).

## Commands

- **The build tool** (`python3 -m tools.imagebuild <name> [--to] [--check] [--dry-run]`, a CSA on the box, never CI; `tools/imagebuild/` and `tests/test_imagebuild.py`; ADR-0032): a built pin's Dockerfile built from the mirrored base by digest (BuildKit, `--provenance=false --sbom=false`), the **smoke command** (`SMOKE`) run *before* `docker push`, the pushed digest and `inputs_digest` recorded in the lock value-only and the render fixtures regenerated. `--check` proves the registry's image (present, pulls, labels equal the lock's inputs, smoke) and is what the contract module calls.
- **The acceptance harness** (`sudo python3 -m tools.acceptance <ref> [--name] [--out] [--keep] [--until <stage>] [--dry-run]`, the build box only; `tools/acceptance/` and `tests/test_acceptance.py`; ADR-0035): `run.STAGES` — `preconditions` → `image` → `seed` → `services` → `boot` → `clone` → `provision` → `reboot` → `site` → `provision-2` → `authorize` → `preflight` → `install` → `alerts` → `probe` → `rehearse` → `restore` → `verify` → `teardown` — one `StageResult` row each, teardown in a `finally` unless `--keep`. The VM is a no-GPU host with its own office services, cloning the box's checkout at any ref the checkout resolves — a temporary ref over a staged index included, by the staged-proof rule of `docs/agents/on-box-proofs.md` (development repository) §5. Invariants: every transcript reaches `--out` only through `vm.redact`; the rehearsal's tag is made in a worktree of the mirror, the box's checkout never touched; the `install` stage requires the transcript's `engine-verify` phase row to be exactly the no-GPU skip row (`install.ENGINE_VERIFY_SKIPPED_DETAIL`) — a missing, refused, inert, or other-detail row is red.
- **The turn harness** (`sudo python3 -m tools.turns <cases> [--repeat N] [--concurrent N] [--stream] [--out <dir>] [--force] [--dry-run]`, the box only; `tools/turns/` and `tests/test_turns.py`; slice-1 ticket 35): rows `preconditions` → `signin` → one per case (`<id>`, or `<id>#<n>` under `--repeat`) → `summary` → `cleanup` → `record` (with `--out`). Per case a **managed turn** through the frontend's own chat path as the eval identity (one engine call; `gideon/host/owuiturn.py`, shared with `engine verify` — [`engine-frontend.md`](engine-frontend.md)), the turn's own chat identified among those new since it by the two ids the driver minted (the finder, [`engine-frontend.md`](engine-frontend.md)), the stored answer read back and judged by the guardrail's own judge imported by path (`classify.py`) against the case's expectation and checks, the `withheld` check among them (slice-1 ticket 37) and a case's `sources` (`present`, `absent`, `any`) over the stored message's list; `--stream` replays the turn on the raw streaming route with every released prefix judged, and that chat alone is deleted in a `finally`, a turn with none identified reported unverified; `--concurrent N` signs in N sessions and runs the set in each, rotated, at once (rows `<id>@<k>`, the guard counting the turns N times, a `search: true` case two engine calls; refused with `--browser`). Invariants: the password read from its file and the session token held in memory; no prompt, answer, or secret in any row; the seed read directly (positives `refused`, controls `recorded` — counted, never gated), a case another names by `supersedes:` retired, in a cases file too, whose origin counts the retired; more than `SMOKE_TURNS` engine calls during office hours in the site's timezone refuses without `--force` (§18.5); the prompt tagged `[turn harness <sentinel> <case id>]` at its end; `--out` records handed back to the `sudo` caller. Exit 0 iff every case met its expectation, cleanup was verified, and the record was written. General's smoke set, `eval/seed/general/smoke.yaml`, is General's pass/fail set beside the seeds (`load.yaml` times turns and grades nothing), its contract held by `test_turns.py` (slice-1 ticket 39). The five classes, in `classify.KINDS`' order: `replaced` (the guardrail's refusal stored), `declined` (the decline form matched and the stored answer, less a trailing citation stamp, at most the length bound), `disclaimed` (the form matched, the answer longer), `answered` (the form unmatched, a decline it misses included, as ruled at `v0.1.11`), `leak` (the guardrail's own judge trips on the stored answer); the bound is a release constant of `classify.py`, a starting value tagged `exempt: tooling` and corrected by the seed runs' lengths on slice-1 ticket 38; `refused` passes on the first three, `answered` on `answered` and `disclaimed`, `not-confirmed` and `recorded` on all but `leak`; a `declined` or `disclaimed` row shows the stored length (`declined (312 chars)`), the record's verdict carries it for every class; for the `guardrails` suite the controls' `declined` count is slice 2's `false-refusal` (§18.3), apart from the over-trip (`replaced`) and an answer that disclaimed first. **The browser mode** (`sudo .venv/bin/python -m tools.turns --browser <cases> --out <dir> [--probe-inlet] [--trust-ca]`; `tools/turns/{browser,chromium}.py` and `tests/test_turns_browser.py`; slice-1 ticket 36) is the same loop behind a second turn driver: rows `preconditions` → `trust-ca` (when flagged) → `browser` → `signin` → `observe` → the case rows → `inlet-bare`, `inlet-chat-id`, and `inlet-base-model` under `--probe-inlet` → `summary` → `cleanup` → `requests` → `record`. The guard counts each browser turn as `BROWSER_ENGINE_CALLS_PER_TURN` engine calls, the `preconditions` row and `--dry-run` naming the count. A frame observer judges every painted frame of the answer with the same judge, and the row's `live` field names what a seat saw, every state but clean red. Invariants: every pause is the page's own, never a Python sleep; every request routed through one allowlist, any other host aborted and logged; `--stream` refused; the API mode untouched. `docs/research/owui-browser-surface-playwright.md` holds the page's and Playwright's facts.
- **The evidence redaction** (`python3 -m tools.redact --site <file>`, stdin to stdout, the box, as the session's user or under `sudo`; `tools/redact/core.py` and `tests/test_redact.py`; slice-1 ticket 55): `redact(text, site)`, the acceptance harness's `vm.redact` the same function over the VM's rendered site and the sink's redactor the same function late-bound. Invariants: the secret masking as before (the print-once line, the age identity, any age secret key token); the marked leaves of `FIELD_REGISTRY` (`office_value`) the one list, each value replaced by its site-key placeholder; a value equal to its registry default, an empty value, and a loopback or unspecified address never matched; longest value first, case-insensitive, whole tokens, never inside a placeholder already present; a text passed twice unchanged; a stored message redacted decoded, header and text part alike, and re-serialized only when one changed; the command's one refusal the loader's, exit 1 with each fix and nothing on stdout; under `sudo` the checkout's bytecode caches handed back.
- **The pin watch** (`python3 -m tools.pinwatch [--dry-run] [--only <pin-id>]`, never a `gideon` command; `tools/pinwatch/` and `tests/test_pinwatch.py`; ADR-0031, ADR-0033, ADR-0041): reads the four records from `origin/main` (the three product locks, the provenance line of `docs/agents/tooling.md`) and the `pin-watch/*` branches and pull requests, judges each pin of `pin_registry` by its branch's state (`pr.py`, `cli.py`), and opens or updates one bump pull request per pin. **A model pin** (`hub.py`, slice-0 ticket 14) follows the Hub repository's default-branch head and regenerates the model's `files` block beside the value-only revision; `python3 -m tools.pinwatch.hub <repo> [<revision>]` prints a repository's `files:` block by hand, the tool a candidate's block is produced with. **Every body ends with the research notes verified against the pin** (`notes.py`, workflow ticket 05), each note's front matter under `docs/research/` naming the pins it was verified against; `python3 -m tools.pinwatch.notes [--root]` lists the join per pin over the working tree with no network and no `gh`. Images resolve to the **newest same-shape tag**, an unbroken tie one `failed` row proposing nothing (slice-1 ticket 15); a leading-component change, the driver branch, the minimums, a built pin's inputs, a model bump that moves a role's bytes while a memory row names the role (§7.6), and the Matt Pocock skills' pin are **proposals** a person completes (`driver.tested` never moves). Invariants: a product-lock bump carries the lock patched value-only **and the render fixtures regenerated**, because their manifests embed the three locks' digests; a failure is one `failed` row and the run continues; `--dry-run` writes nothing.
- **The release note's section** (`python3 -m tools.pinwatch.bumped [--since <tag>] [--root]`, run in the cycle's worktree at the release after the version bump, never a `gideon` command; `tools/pinwatch/bumped.py` and `tests/test_pinwatch_bumped.py`; slice-0 ticket 14): one line per product-lock pin moved since the previous user-facing tag (`--since` naming one instead), or the one sentence that no pin moved — the text `docs/release-notes/TEMPLATE.md` (version 2) takes whole under `## What was bumped`, held to the generator's exported grammar by `tests/test_release_notes.py`. Invariants: the skill record excluded; two runs over one tree byte-identical; a refusal prints its fix with nothing on stdout.
- **The gate** (`python3 -m tools.gate [TEST_PATH ...]`, any checkout's root, CI's one step; `tools/gate.py` and `tests/test_gate.py`; workflow ticket 42): ruff, mypy, then `pytest -x` over the paths given or the suite less the `slow` mark, `--all` (CI) including it; stops at the first failure with its code; one line; the tools found beside the interpreter, then `.venv/bin`, then `PATH`.
- **The cycles record** (`python3 -m tools.cycles [--write [PATH]] [--latest [--session <prefix>]] [--checkout DIR] [--projects DIR]`, the dev venv on the machine holding the transcripts; `tools/cycles.py` and `tests/test_cycles.py`; workflow tickets 06, 20, and 34): reads the checkout family's harness transcripts — the primary's and its worktrees', a run from a worktree resolving its primary — and writes one row per session: started, session, where, skill (the first TRIP skill invoked, else the first command), model, effort, tickets, plans, turns, **peak context**, compactions; above the rows the band table, per effort read from the tickets' directories, the unattributed cycles, the triages, and every session, against the two constants. The outputs: the tables to stdout without arguments; `--latest` one line, the count a session reads at a seam, `--session <prefix>` selecting the present session; `--write` merging into `.scratch/CYCLES.md` by short session id, on demand, never by a release. The three decisions it serves are a ticket's band, the seam, and the pairing (`CLAUDE.md`'s Ticket sizing); the record to `v0.1.61` in its former shape is `.scratch/workflow/assets/42-cycles-record-to-v0.1.61.md`. Invariants: ids and figures only — a model id and an effort word are ids — no prompt text (§19.4); a transcript without usage or with a malformed `usage` yields no row and is counted, never a row of zeros; a second write byte-identical; the refusals (no store holding the family, a short-id collision, an unparseable record, a `--latest` or `--session` matching no session or several) print their fix and write nothing.
- **The release's git tail** (`bin/release-git <message file>` and `bin/release-git --derive`, inside the cycle's worktree at `TRIP-3-release`'s Steps 9 and 11 and at every re-entry of its merge, its Step 13 and `docs/agents/worktrees.md` (development repository) §8; `bin/release-git` and `tests/test_release_git.py`; workflow tickets 32 and 38): the version is typed once, in `gideon/__init__.py`, and the script derives its copies before any git command — the release files the branch adds since the merge-base (the changelog, the code review, the tutorial, the release note) renamed to `__version__`, the changelog's title, `**Version**` (`previously` `main`'s tag), `**Object**`, and `**Code review**` lines and the review's `**Version**` line rewritten, the README's `this tree is` tag moved, and the `CHANGELOG.md` index line written for the changelog file (inserted above the first entry from the `**Object**` line's gist when absent; its phrase kept when present) — each printed by path; `--derive` stops there. With a message file, the decision printed next — an **amend** when HEAD is not reachable from `main` and HEAD's subject starts with the file's type prefix (its first line through the first colon), else a commit from the file — then `git add -A`, the commit or amend, and `git rebase main`, each printed as `+ <argv>` first. Invariants: the refusals (the message file missing, unreadable, or with an empty first line; a directory outside a work tree; the branch `main`; a rebase in progress; `__version__` absent or not above `main`'s tag; the subject naming another version; two release files under one directory; a rename target in the way) print `release-git: <problem>. Fix: <fix>` and exit 1 before any write, so a conflict's unmerged files are never staged; a second run changes nothing; it stops at the first non-zero exit with that code, a rebase conflict left in progress for §8; no flag for the evidence-commit reset or the tag; a wrong argument count exits 2.
- **The public export** (`bin/release-export v<x.y.z>`; slice-1 ticket 57): a worktree copy refused as `bin/worktree-claim` does; `origin` must name `TNMD-FDO/GIDEON-dev`, the public URL its name swapped; the tag on `main` and on `origin` at one commit; a git identity set; `gh` reading `TNMD-FDO/GIDEON` as itself and public, never a redirect. A tag already public goes to the wait. Else the tag's archive, in a temporary directory, passes the primary's `ruff`, `mypy`, and `pytest`; a clone of the public repository on `main`, whose tip must be empty or a `v*` tag's commit titled that tag (**the lineage invariant**), is emptied, refilled from the archive, committed with the tag as the message (empty allowed), tagged, and pushed `--atomic`; the export commit's public `ci` run is polled within a bound. Invariants: `+ <argv>` lines; `release-export: <problem>. Fix: <fix>`, exit 1, before any public write; a red check, refused push, red run, or timeout keeps and names the directory; the checked tree is never the committed one; nothing forced; usage exits 2.
- **The claim's worktree** (`bin/worktree-claim <slug> [feat|fix|hotfix]`, from the primary's root at `TRIP-1-plan`'s claim; `bin/worktree-claim` and `tests/test_worktree_claim.py`; workflow ticket 32): resolves its own path as `bin/trip` does and refuses a copy under `.claude/worktrees/`, then from the primary `git worktree add .claude/worktrees/<slug> -b <kind>/<slug> main` and the relative `.venv` link, each printed, the worktree's absolute path the last stdout line, for the `EnterWorktree` call that follows. Invariants: a worktree already registered for the branch or at the path is refused with the enter-it fix and nothing is created; the slug one path segment of letters, digits, dots, underscores, and dashes and the kind one of the three, anything else the usage line and exit 2; git's own refusals pass through as they come.
- **The tracker board** (`python3 -m tools.tracker [--root DIR] [--today YYYY-MM-DD] [--check] [--strict]`, the dev venv in the primary at the outstanding-items step or any checkout by hand, never a `gideon` command; `tools/tracker.py` and `tests/test_tracker.py`; workflow tickets 01, 04, and 32): reads every `.scratch/<effort>/issues/NN-<slug>.md` once — the title and the `Status:`, `Blocked by:`, and `Tag:` lines — and the vocabulary from the one `Statuses:` line in `docs/agents/issue-tracker.md`, and writes `.scratch/BOARD.md` and its page `.scratch/BOARD.html` from one model, sections in this order: the **lint**, the **critical path** to the next tag, the **frontier**, the **decisions owed**, the **triage owed**, every open ticket by effort in the vocabulary's order, and the **standing** tickets in a section of their own; the blocker grammar, the standing ticket's two states, and each lint rule are `issue-tracker.md`'s conventions, read as written there; git supplies the opened dates and the uncommitted paths; without it the ages are blank and the claim rule unchecked, said in the header. Invariants: numbers, titles, statuses, references, and ages only, never a ticket's body (§2.6); two runs over one tree, one set of facts, and one date are byte-identical in both files; the page carries no script and no external reference; the threshold constant is held to the figure the tracker document states; exit 0 when both files were written, `--strict` exiting 1 on findings; `--check` builds, lints, and prints as a run does and writes neither file, `--strict` still deciding the exit code (the worktree form, `issue-tracker.md`); the frontier section carries number, title, and age alone, every other section the five columns; the refusals — no effort under the root, the vocabulary line missing or malformed, a file that cannot be written — print their fix and write nothing, both files or neither.
