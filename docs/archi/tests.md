# The test suite — architecture leaf

**Read this when** working on repo-wide test contracts, test organization, or the contract tier; the owning modules are the tripwires under `tests/`, the per-command test modules, and `tests/contract/`. The map is [`../ARCHI.md`](../ARCHI.md); its §8 table names every command's leaf.

## The tripwires

A tripwire holds a repo-wide contract; a subsystem's own modules are listed in its leaf.

- `test_cli_surface.py` — the §20.2 surface; `STUBS` shrinks as commands land.
- `test_host_import_boundary.py` — the seam (§9), AST-level: the entry chain, the host subtree, and the shared modules.
- `test_service_import_boundary.py` — the mounted `gideon/api/` source set's AST boundary: stdlib, image dependencies, or declared modules only; module-level `gideon` imports; inert parent initializer.
- `test_guardrail_equality.py` — until general-turn ticket 09 deletes it with the Function: `gideon/guardrail.py`'s top-level statements equal the guardrail Function's less its named Function-only set, compared as syntax trees with neither file imported, no name bound twice in either, and the held list of files under `tools/`, `tests/`, and `gideon/` that name the Function's path.
- `test_lock_coupling.py` — no module under `tests/` embeds a value the pin watch can move, whole-token, comments included: the three locks' values and the skills' record when present.
- `test_toolchain_pins.py` — the copies no install reads: `pin-watch.yml`'s PyYAML install line and the Playwright constant `tools/turns/chromium.py` names, held to `requirements-dev.txt`, and that file's own copy of the `gideon` image's ten build arguments, held to `images.lock` by normalized project name; the module states no version. The ruff, mypy, and pytest pins have no copy: CI installs from the file.
- `test_evidence_hygiene.py` — every text asset under `.scratch/` free of a complete age secret key and of a print-once line carrying a value other than `<redacted>`.
- `test_office_values.py` — the whole tree free of office values by a rule that names none (slice-1 ticket 54): every dotted token judged on its final label — under a public suffix its registrable domain must be on the allowlist seeded from `config/egress.yaml` and the documentation hosts the tree cites, the public-suffix set derived from that allowlist; under a private-use suffix it is a finding unless a reserved documentation name covers it; in a hostname position (a URL authority, a mail domain, an `ssh` target, a `DC=` chain, a site key the registry marks as an office value) it is judged whatever its suffix; every RFC 1918 literal a finding except libvirt's bridge range, a Docker pool address on an access-log line, and the three range definitions in Markdown prose; a DN of two or more `DC=` components must reverse into a documentation name; Python sources read through literals and comments; the walk an `rglob` from the root skipping `.git`, `.venv`, the caches, other cycles' worktrees, and the vendored skill folders `skills-lock.json` names; the placeholder vocabulary (`<key>`, `<key[i]>`, `<address in lan_cidrs[i]>`, `<redacted>`) never judged; a workflow's expression over the Actions event context (`github.event.…`, under `.github/workflows/` alone) never a hostname; the spec's example twin held byte-equal to `config/site.example.yaml` while it exists; a file-count floor; every finding with path, line, and fix.
- `test_research_notes.py` — every note under `docs/research/` opens with front matter naming the pins it was verified against, each id in the vocabulary derived from the records (the pin watch's registry, `models.lock`'s reference profile, `requirements-dev.txt`), a version per item, a count floor; no lock value stated (workflow ticket 05).
- `test_archi_budget.py` — the architecture memory's contract: the map, every leaf, `CLAUDE.md`, and every document under `docs/agents/` under their caps; caps and warnings read from `docs/ARCHI-rules.md`'s one `Budgets:` line, each warning below its cap; the map's §2 rows and the leaves under `docs/archi/` matching; every relative link and anchor in those files, `CONTEXT.md`, and the rules resolving, with excluded targets skipped except the test's own `CLAUDE.md`, `CONTEXT.md`, and `docs/agents/` documents; an excluded leaf is exempt from the §2 index when a `_Leaf_` link in `CONTEXT.md` routes to it, and a §2 row indexing one is a finding.
- `test_release_notes.py` — the release-note contract (§21): the template's version and headings; every note held to the template version it names; a note required for the current version from `0.2.0`; its template case skips when the template is absent from the export.
- `test_release_records.py` — the release's two derived records: the root `CHANGELOG.md` index over `docs/2-changelog/` (slice-1 ticket 61) — every release-shaped file has exactly one line; every line in the fixed shape, its target existing and its link-text version the filename's; newest first by version tuple; each date equal to the target's title date; the preamble naming `## Breaking` and `upgrade`; each rule fired on a seeded tree — and the README's status paragraph saying "this tree is" the tag of `gideon.__version__` exactly once (imported, never restated; slice-1 ticket 60), the two facts `bin/release-git` derives at a release.

## One module per command and seam

- One module per command and seam (`test_apply`, `test_restore`, `test_upgrade`, `test_weights`, `test_acceptance`, `test_pinwatch`, `test_turns`, …) asserting stage order, every refusal with its fix, exact argv, idempotence, and the negative facts (no password in argv, a failed smoke pushing nothing, verify refusing before `down`, teardown or deletion on every path, nothing of a new tree imported by `upgrade`). Network clients are proven over a loopback `http.server` or socket; the two harnesses over an in-memory frontend and, for the browser mode, a fake page.

## The contract tier

- **The contract tier** (`tests/contract/`; self-hosted CI only, `python3 -m unittest` with the system Python; no `test_` prefix, so the hosted pytest never collects it): `built_images.py` runs the build tool's `--check` for every built pin against the loopback registry; `owui_apply_manifest.py` brings up a throwaway Postgres + frontend pair on loopback from the mirrored digests, redirects the secrets module's directory to the stack's own (the harness's one seam), never touches `/etc/gideon`, and proves the apply manifest is desired state: every hand edit through the frontend's own routes (a stray Function or preset, either model record, a group's permission leaf, the guardrail's Function edited, toggled, or deleted) undone by the next push with the stray reported and a further push a no-op; the eval identity's base listing refused by role; store convergence idempotent, the audit role unable to read; and the environment-borne facts edited through the panel's own config routes back at the rendered values after the frontend restarts — the one reversion an environment value has, which apply performs only when a frontend-owned file changed. `search_sentinel.py` (slice-1 ticket 16) brings up a throwaway Postgres + frontend + SearXNG + stub project (`gideon-ci-sentinel`; `sentinel/compose.yaml` and `sentinel/stub.py` beside it, the stub a standard-library script under the frontend's own image standing in for the engine, for SearXNG's engines — the generic JSON engine for results and the shipped Bing module repointed for the network warning, both over plain HTTP, the pages under a dotted alias the loader's validator accepts — and for the frontend's SearXNG stand-in), derives the frontend's environment and its command from the render by an explicit key list and a shell-joined constant (the log posture and the task toggles among them, so the files handler runs in CI as it does on the box) so a raised rendered level is red — the frontend's image policy among the keys, one test reading the page's `Content-Security-Policy` header through the stack's port against the rendered value (slice-1 ticket 72) — and proves the search path leaves no query text: five ordered runs, each with a fresh sentinel and one managed turn as the eval identity through the managed-turn finder — the happy path, SearXNG's engine answering an HTTP error, the frontend's SearXNG call answering a non-2xx (hits in the frontend's journal alone and only in the residual's shape), and two controls that must find the sentinel (SearXNG over a WARNING logging file, the frontend at DEBUG) — over every container's journal and the audit file, counts and names only. Its stub and classifier have hosted tests (`test_sentinel_stub.py`, `test_sentinel_classifier.py`); the stub writes each request line before its first response byte, and the hosted test reads the line through redirected stdout the instant the response is read while a record taken at the response's start holds that order (slice-1 ticket 77). On the box both run under `sudo` with bytecode writing off; locally they need Docker access. Heavier tiers (the full `gideon-ci` stack, eval suites, build gates — §18) are product features of slices 2–3.
