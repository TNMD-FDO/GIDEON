## Commands

- **`alerts test`** (§19.5, ADR-0034; `alerts.py` over `grafana.py`): `preconditions` → `grafana` → `send` (as the break-glass administrator: the `page` receiver read back and refused unless its one email integration matches the site file, then tested) → `audit` (always after `send`: one `alerts_test` row with the recipient count, relay, outcome, and SMTP reply code — never an address).
- **`users reconcile [--now]`** (§4.1, §19.4; `users.py`): enumerates each group's direct members through `ldapsearch`, joins frontend users by casefolded `userPrincipalName` (ADR-0030; no fallback), skips the two machine identities, and computes corrections: in the users group → `admin` iff in the admins group else `user`; outside it → `pending`; an inconsistent member is an `inconsistency` line, never a refusal (preflight is the gate). The bare form prints `would` lines and writes nothing; `--now` writes the membership snapshots, then per correction an intent row, the role update, and an applied row, under one `run_id`. `audit.py` is the writer: one `psql` transaction per batch as `gideon_audit`, ids and identifiers only.
- **`tls reload`** (§1.6; `tls.py`): `validate_material` through `openssl` **before** touching Caddy (an encrypted key refuses instead of prompting), then `stack.force_recreate(caddy)` (a file secret is a bind mount — a replaced key reaches only a new container), then `probe_ingress` (the served leaf's fingerprint against the file's; a failed handshake is retried, a mismatch never).
- **`registry mirror [--to]`** (§2.4; `registry.py`): each lock reference probed and copied when absent with `skopeo` by digest (TLS verification off iff plain); `mirrored/present/failed` rows. A built pin gives two rows: its **base**, ensured under the base's tag even for an unbuilt pin, then its built digest — `present`, or `failed` naming the build command (the registry receives a built image from a build and nothing else).

## Release constants

The alert thresholds and the engine rule's pending period (`render/grafana.py`), the engine's scrape identity (`render/engine.py`), the §4.2 permission set, and the reconcile and LDAP bounds (`users.py`, `ldap.py`) are release constants owned by [`render-apply.md`](render-apply.md). The two GPU-host rules and the two GPU-host scrape jobs are their own templates or blocks, rendered as the empty string under the no-GPU marker; the host-unit rule is rendered as the empty string unless the build-box marker is present, and the node exporter's pattern follows the same host mode; the search probe's job and rule are the same under `web.search` off; "Target down"'s exclusion of the engine job is one text on every host. A probe pages through its own `probe_success` rule, because "Target down" reads a scrape's `up`, which the blackbox exporter keeps at 1 while its probe fails. Grafana's file provisioning deletes no rule without an explicit entry, so a rollback to a release before a rule leaves it provisioned and inert in Grafana's derived state. A rule over several series is one rule and one alert instance per series, the series' label reaching the summary through Grafana's own template, whose dollar the release template doubles because `substitute_template` is strict; and such a rule, unlike an engine-only one, comes back from a rollback provisioned and *evaluating* rather than inert, since its series exist on every host (slice-1 ticket 74). The Overview board's two trip panels read `guardrail_trips` through the rows datasource — the users' daily count by pattern id over the panel's own 30-day range, and the eval identity's last trip's age, which every `engine verify` refreshes — so the writer's health is a panel and never a log line; the writer itself is [`engine-frontend.md`](engine-frontend.md)'s. Its container-memory panel draws each container's cAdvisor limit (`container_spec_memory_limit_bytes`, filtered to a positive value, since cAdvisor reports 0 for an unlimited container) as a dashed series beside its working set, so use reads against budget per container — E9's instrument for the profile's memory table (slice-1 ticket 19).
