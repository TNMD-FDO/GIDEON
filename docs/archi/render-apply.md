## Commands

- **`render [--diff]`** (§3.5, `render/`): `render_all(inputs)` is pure and touches no `Host`; `RenderInputs` carries the site, the locks, the selected profile, the host facts, the no-GPU marker, the build-box marker, the templates, the release string, the declared `secrets` (read for the `env_file` only), and the checkout, and the manifest's `inputs` block records their digests. **The marker governs the engine**: with it absent, the profile's generator becomes the engine service, and the frontend's connection, the two model records, and the engine's scrape job, rule, and board panels render with it — each constructed only under the marker's absence, never built then deleted; the drill's frontend is always disconnected. **The `gideon-ci` sibling's document** (`render/ci.py`, the drill's pattern) reuses `compose.py`'s builders: its `gideon-api`'s engine URL is the relay's, and the one service joining production's network, the relay, bears no name in `service_names`, so production's DNS is unchanged. **The build-box marker governs the host-unit rule and the node exporter's unit pattern**: both are constructed only under it, while an undeclared host collects its GIDEON units alone. **The site's `web.search` governs the search rig**: on, the `searxng` service, its three files, the frontend's search block, and the probe and its rule render ([`stack.md`](stack.md)); off, `ENABLE_WEB_SEARCH=false` renders alone, the three files are stale, and the departed service is left to orphan removal — never in the drill. **Every rendered service carries `mem_limit`** from its row in the profile's memory table ([`host.md`](host.md)), the table held to the stack's services both ways before the marker and the site settle the host's, so one lock is complete on every host or refused on every host; the drill's two take their namesakes' rows. An `Artifact` carries its path, mode, owners (the services that mount it), templates, `secret` flag, `applies(inputs)`, and a pure `emit(inputs)`; `compose.yaml` is a Python structure serialized by the deterministic `yamlout.dump`. `render_to_disk` — the one path `render` and `apply` share — classifies each file `new/changed/unchanged/stale/foreign`, refuses on a foreign file, writes atomically, removes stale files, and writes the manifest last. **The recreate rule** (`recreate_judgment`) is judged against `applied.yaml` alone, with three owners per service — the rendered files that mount it, its own `compose.yaml` block, and the top-level sections jointly (`compose_digests`) — and names every service when the record predates the map, the top-level digest moved, or the whole file moved with every digest equal; each reason is kept for apply's rows, the union intersected with the running set, every service before the first verified apply; a malformed record refuses.
- **`apply`** (§3.5, `apply.py`), in order: preconditions → **secrets** (`ensure_generated`; a break-glass password printed exactly once, on the run that created it) → render → registry → pull → **models** (`weights.pull_profile`, before anything restarts) → **recreate** (the judgment's members within `STORE_SERVICES` force-recreated, the row grouping them by reason — `first apply`, `changed rendered files`, `changed compose block`, `changed compose top-level`) → **stores** (`stores.converge`: roles and databases absent-only, existing roles never altered; the forward-only migration runner, one transaction per `migrations/NNNN_*.sql`; the pgBackRest stanza and `check`) → **start** (the judgment's other members the same way, then `up -d --remove-orphans`; the frontend never starts against an uninitialized database) → **apply-manifest** (`owui.wait_ready`, then `owui.bootstrap`: keys minted absent-only, groups converged by name with LDAP-owned memberships untouched, Functions and models synced desired-state and **read back** row by row, then the live model listing read, each listed manifest model held to its attachment key) → verify (every service but the engine within the default bound, then the engine alone within what remains of `ENGINE_READY_SECONDS`; `compose ps` equal to `service_names(inputs)`, every healthcheck healthy, the ingress probe, the frontend's `/ready`, Grafana's health) → **timers** (the units converged against `applied.yaml`) → record (`applied.yaml`). Every Compose invocation goes through `stack.compose_argv`/`exec_argv`; `stack.logs_fix` is the one operator fix for a misbehaving service. The stages from `secrets` through `record` are `converge`, the callable `run_apply` and `secrets rotate` share.
- **The API render** (`render/api.py`, `compose.py`, `command.py`) on a GPU host mounts the applying checkout's `gideon/` tree read-only at `/opt/gideon-src/gideon` and labels the block with the digest of `API_SOURCES`; the loader records that digest in the manifest input, and a moved digest is a changed compose block under the recreate rule. The `gideon_api_key` registry entry is generated and mounted beside the engine key; the block has no published port or service dependency, so the service is reached only on the Compose network.
- **`secrets rotate <name>`** (§1.7, §4.4; `rotate.py`): pre-run refusals on stderr before any row, write, or Compose call — an unknown name, a supplied name (its replacement path), a `role`, `account`, or `seeded` entry (its second home and the by-hand route) — then `preconditions` (apply's Compose check; the rendered tree and `applied.yaml` present; the recreate judgment against the record strictly empty, since a pending change cannot be attributed to one secret) → `plan` (the class, each mount consumer with its unavailability, each carrier the converge recreates; a `rewrite` secret nothing on this host mounts or carries is one row and exit 0 with nothing written) → `rotate` (`secrets.rotate_generated`, or a minted key's file removed) → `recreate` (`apply.force_recreate_services` over the mounts, each once) → `converge`. Invariants: a service recreated at most once; exactly the consumers; the value in no row, refusal, argv, environment, or written file but the secret's own and the secret-flagged artifacts that declare it; a failure past the write finished by `apply`, then a fresh rotation where a mount consumer was not reached.
- **`models pull`** (§5.4, §2.4; `weights.py`): the selected profile's models converged into the hub-cache tree — every pinned path classified against disk, a mismatch re-fetched and reported, a `foreign` snapshot entry the lock does not name refused and never deleted, each blob checked before it is renamed into place; rows `fetched`/`present`/`failed` per model, a fetch the lock rejects naming repin-or-republish, every host a fetch traverses held to the `install-upgrade` group ([`host.md`](host.md)). **The pull record** (`gideon/pulls.yaml`: claim, current, previous, retiring) is walked in atomic writes under a claim, `retiring` holding exactly the references leaving the named slots, so the pinned set and the newest previous complete set stay for rollback. Runs on a no-GPU host too (the marker governs serving, ADR-0035).

## Configuration and the rendered tree

- **Secrets are files** (§1.7): `gideon/host/secrets.py` is the one module that names `/etc/gideon/secrets/` (every other module calls `secret_path()`) and holds `SECRET_REGISTRY`: the password-kind secrets apply generates absent-only (the two break-glass passwords as `print_once`), the two API keys the apply-manifest stage mints absent-only, and SearXNG's signing key; supplied secrets (the LDAP bind password, the TLS key, the SMTP password, the proxy credentials) are never generated, `SUPPLIED_REGISTRY` naming each one's replacement path, and `read_secret` returns a `missing` flag so a caller can name the command that creates a generated one. `select_directory(path)` is the one sanctioned move of every reader and fix text off that directory, called once per process by `tools.cistack` and `tools.turns --stack ci` (the sibling's own directory, production's engine key alone mounted from here). Every secret file is `root:gideon` 0440; unprivileged containers read through `group_add`; the engine's key is read inside its container from the Compose secret mount by a fail-closed entrypoint, its homes the two mounts alone since general-turn ticket 09 took it off the frontend; the frontend's rendered env file carries `gideon_api_key` in its place (§1.7's exception), the connection's own bearer to `gideon-api`; the audit role's password reaches `gideon-api`'s container alone as a Compose secret mount, the service the guardrail trip's one writer (ADR-0039 superseded by ADR-0045). Every entry carries a **rotation class** — `rewrite` (the file the value's only home; rewritten in place), `remint` (the two minted keys; removed and re-minted), `role`, `account`, `seeded` (a second home the file does not own; refused) — `ROTATABLE_NAMES` the first two. The **consumer map** (`render/consumers.py`) derives, for every secret, the services that mount it (the Compose blocks' `secrets:` lists) and those that carry it (each secret-flagged artifact's `secret_names(inputs)`, held equal to what it reads), so `secrets rotate` and render cannot disagree. Beside them: `/etc/gideon/backup_age_recipient` (public; the decrypting identity lives only in the office password manager) and the keyed **secrets fingerprint** (a hash over the secret files keyed by the session key's digest, carried in every backup manifest, so a restore can say whether the secrets on disk are the set's without giving a human-chosen password anything to test against).
- The engine key has two Compose mount consumers on a GPU host, `gideon-generator` and `gideon-api`, and no carrier. The generated `gideon_api_key` has `gideon-api` as its mount consumer and `open-webui/env` as its carrier, which is why `secrets rotate gideon_api_key` recreates the service and the frontend and `secrets rotate engine_api_key` no longer touches the frontend. Both are read through the service group from the mounted files.
- **`/etc/gideon/rendered/`** (§3.2) holds the artifacts `ARTIFACTS` registers — `compose.yaml`, the Caddyfile, the Prometheus and blackbox configs, Grafana's LDAP, provisioning, and boards (the GPU-host jobs, rules, and panels marker-governed blocks), `pgbackrest.conf`, the systemd units (`gideon-backup` runs `backup run` then `backup push`, the drill and the quarterly `gideon-backup-verify` `After=` it; every `OnCalendar` zoned; every Compose service carries `TZ`), **`open-webui/env`** (the §1.7 `env_file` exception — the LDAP bind password, the database URL, the break-glass password, and on a GPU host the connection's key, `gideon_api_key`; 0600, flagged `secret`, never printed by `render --diff`), the three SearXNG files present only while `web.search` is on — **`searxng/settings.yml`** (the pinned image's defaults made rendered facts, the site's engines kept and re-enabled by name), **`searxng/env`** (the same exception: the signing key and, under a proxy, its URL with the credentials), and `searxng/logging.json` (granian's loggers as shipped and `searx.network` at ERROR) — and `open-webui/manifest.yaml` (the apply manifest: the groups, the two identities, the branch gate's one Function row on every host since general-turn ticket 09, with its whole file as its `content`, and on a GPU host the two model records, General's `meta.filterIds` rendered as an empty list — the key kept, so the push overwrites a live attachment under either merge or replace semantics and the read-back's stale-key check stays meaningful). Beside them: `manifest.yaml` (every render: file sha256/mode/owners, the per-block and top-level Compose digests, the inputs' digests) and `applied.yaml` (the same shape, written by apply only after verify — the record the recreate rule is judged against). The TLS key, the frontend's session key, and the Postgres superuser password reach containers as paths (`*_FILE`), never through `env`.

## Release constants by module

**Release artifacts that are not site keys** (ADR-0028) are constants in the module named; a reader opens the module for the name and value.

- `compose/open-webui/permissions.yaml` — the §4.2 permission set, rendered as the frontend's env defaults and each group's manifest permissions (binding every `user`-role account, bypassed by the frontend's admins by design).
- `render/owui.py` — the API-key endpoint allowlist; the two machine identities, their group, and the eval identity's password name; the readiness bounds; the frontend's connection facts and frontend-wide switches, the search dialog's text (ADR-0043) and the image policy among them (`Content-Security-Policy: img-src 'self' data: blob:`, set by the pinned frontend's own security-headers middleware on every response, so the citation UI's favicons never leave the workstation — slice-1 ticket 72; no other directive); the two model records, General's texts from `compose/open-webui/general.yaml` with `$office_name` the one placeholder; the search connection's reminder, result count, and domain filter, the page loader's agent and its bound; the branch gate's identity and General's empty attachment list.
- `render/compose.py` — the store tier; the engine's healthcheck, entrypoint, and access-log exclusions (slice-1 ticket 51); the frontend's command, its access line off (slice-1 ticket 69; the drill's frontend shares it); the memory-limit helper; the project and network names the sibling derives production's network from.
- `render/ci.py` — the `gideon-ci` sibling's project, root, secrets directory, loopback port, the relay's name, source, and memory limit, and the wipe list.
- `render/engine.py` — the engine's identity (service name, port, secret name, scrape job name, metrics target), shared by the service, the connection, the Prometheus configuration, and the engine rule, so `owui.py` never imports `compose.py`.
- `render/api.py` — the API service's identity, port, route, mount, source, and probe constants, shared by Compose, Prometheus, and Grafana.
- `render/searxng.py` — the search service's identity, the settings document's pinned defaults, and the logging document's logger and level; `render/proxy.py` — the one proxy helper both env files use; `host/site.py` — the six engine names and the bare-domain grammar ([`host.md`](host.md)).
- `render/systemd.py` — the four timer calendars, each zoned to the office; `render/grafana.py` — the alert thresholds.
- `apply.py`, `users.py`, `ldap.py`, `weights.py` — the timeout bounds.
