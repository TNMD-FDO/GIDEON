# The eval harness — architecture leaf

**Read this when** implementing `gideon eval run`, `gideon eval reference`, the eval set's cases, its loader, a frozen slice, the slice registry, the quiet window, the run record, or a reference file; the slices' runners and measures, with `gideon/extraction/` and `tools/variants/`, are [`eval-slices.md`](eval-slices.md)'s. The map is [`../ARCHI.md`](../ARCHI.md); its §8 table names every command's leaf.

## Commands

- **`eval run --slice <name> [--set <dir>] [--ranked <file>]`** (§18.6, §20.2; `evaluation/command.py` over the modules above, `_guarded` behind `cli.py`): `load` → `run` → `record` → `gate`, with `preconditions` after `load` for a slice whose registry entry reaches the engine and **`ranked`** after `load` for one whose entry takes a ranked list; the gate's verdict is the exit code, and a slice `slices.py`'s registry does not name refuses. `load` reads the court map and the set (the release's `eval/sets/eval-v1/` unless `--set` names another), prints the set's identity, counts, and digest, and on any finding prints them all and refuses. `ranked`: the missing and the stray `--ranked` are each a failed row with the command that fixes it; the file is read through `ranked.py` against the slice's active ids, every finding printed before the refusing row; the lists reach the runner on the run context, and the file's SHA-256 and the definition id the run row's `overrides`. `preconditions` stops at the first refusal, each printing its fix: root, the no-GPU marker (a refusal, not `engine verify`'s skip, since nothing here is gated on by install), the site file, **the quiet window** (the fix naming the next opening and that `--force` lands with slice-2 ticket 16), the engine's target through [`engine-frontend.md`](engine-frontend.md)'s shared helper, and — unless `--set` was given — everything `record` can refuse on that does not need the run: the git provenance and the writer role's connection probe. Its guarantee is exactly that and no wider: the probe proves the role connects, not that the insert will succeed, so a write that fails after the run is still reported at `record`. `run` evaluates the slice's active cases through its registered runner — the spec's `repeats` and `judge_prompt` copied into the run context, so a runner declares neither — and prints its report; where the slice lists any case whose shape takes a sign-off, its detail ends `, N unsigned excluded`, and a result naming any unsigned case of the set fails the row by id before `record`, so a runner that reached past the loader's selection cannot put one in a gate's count. For a slice whose spec compares (ruling 5 of slice-2 ticket 06), between `run` and `record` the slice's reference is read from the release checkout — whatever `--set` names, so a planted regression is provable — and compared with the run's per-case verdicts folded over repeats; the block prints one `reference: <outcome>` line from the closed vocabulary, the reference's tag and version, and one line of ids per non-empty list. `record` writes one run row and one result row per active case in one transaction as `gideon_eval`, receiving the whole gate's verdict: it is skipped, without failing the command, for a set outside the release (`--set`) and for an unreachable database, and refuses when the site file, the git provenance, or the write itself fails. The run row carries the release's and the set's identity, `stack=production`, `kind=manual`, the checkout's `git_sha` and `git_dirty` — both null only where the checkout root has no `.git` — the verdict, and a ranked run's `overrides`, which is why `eval reference` refuses a run with overrides: a run over an arbitrary ranked file must never become a release's reference. `gate` is two functions read by the tripwire, each against its own attribute list: the slice's own gate reads the slice result's verdict and the spec's three texts and nothing else, and the reference gate reads beyond them the comparison alone; the composed row carries both halves and the fix of whichever failed, the bounds' first when both do. `--decision` and `--force` refuse as not implemented (slice-2 ticket 16). Invariants: rows are insert-only and content-free but for the judge's reason (ADR-0048), and written after the run and before the gate's row; a run of the release's own set is recorded whatever its verdict; **the judge grades and never gates** — the slice's verdict is one code-computed bool, a score and everything derived from it live in `judge`, and no `metrics` key at any depth names a judge fact (ADR-0023); a comparing run prints exactly one `reference:` line and one that stops earlier prints none, so its absence reads as a stop, while a non-comparing slice prints none at all; a refusal fails the gate *after* `record`, since the first run of a new set version is the one its reference is written from; no reference for the slice leaves the slice's own gate deciding alone and the exit code unchanged, and staleness never touches it.
- **`eval reference --run <run id>`** (§18.6, ruling (a) of slice-2 ticket 05; `evaluation/reference_command.py`, `_guarded` behind `cli.py`): `load` → `read` → `check` → `write`, stopping at the first refusal, every refusal printing its fix. `read` is one statement as the metrics role over the Postgres container's socket. `check` is the Inventory row's conditions, and beyond them refuses a recorded run whose results name an unsigned case, by id, so none reaches a written reference whatever produced the run; its regression refusal names repairing the case or superseding it, and the deliberate, diff-visible act that accepts a loss — removing every reference file of the slice — and a malformed current reference refuses the write with the restore-or-remove fix. Invariants: nothing is written to Postgres; the run and the write may be in different checkouts, the run's any clean one at the tag and the write's the development checkout whose committed set has the same digest; a list with no evaluated case still gets its file, so the partition is total; the write is idempotent, reporting `unchanged` for equal bytes, and repairs an interrupted ownership hand-back on every run.

## Release constants by module

- `gideon/evaluation/evalset.py` — the eval set version and its root, the shape registry, and the id, cluster, role, query-type, and variant-axis patterns; a set version is never edited, a later version is a new directory.
- `gideon/evaluation/signoffs.py` — the sign-offs file's relative name under a set root and the line's ordered key tuple; a key is never renamed, and the source-id and attorney-role patterns it validates against are `judgments.py`'s, imported rather than restated.
- `gideon/evaluation/reference.py` — the format number, the file's key vocabulary, the two verdict words, the closed outcome vocabulary the release's check reads, and the path rule; the format number moves only when the file's shape does, and a landed reference is re-recorded whole, never edited.
- `gideon/evaluation/slices.py` — the slice registry and its spec's fields; a slice naming a prompt the judge's registry does not hold, or keeping a reference while its spec does not compare, is a test failure.
- `gideon/evaluation/window.py` — §18.5's quiet-window hours and its weekend days.
- `gideon/evaluation/turns/run.py` — `TURN_TIMEOUT_SECONDS`, `SMOKE_TURNS` (the daytime handful), `BROWSER_ENGINE_CALLS_PER_TURN`, `STREAM_LEAK_FAILS`, and `LIVE_POLL_SECONDS`.
- `gideon/evaluation/turns/chromium.py` — `PLAYWRIGHT_VERSION`, held to `requirements-dev.txt` by `test_toolchain_pins.py`, and the browser-mode footprint's paths under `/root/.config/gideon-turns/`.
- `gideon/evaluation/turns/classify.py` — `DECLINE_MAX_CHARS`, the decline form's length bound.
- `gideon/evaluation/record.py` — the writer role and the reader role, the database, and the Postgres service name, each equal to [`stack.md`](stack.md)'s; the run row's `kind` and `stack` vocabularies are `migrations/0004_eval_runs.sql`'s checks.
