# The eval harness — architecture leaf

**Read this when** implementing `gideon eval run`, `gideon eval reference`, the extraction grammar, its measure, the eval set's cases, a frozen slice, a reference file, or the judge; the owning modules are `gideon/extraction/` (`contract.py`, `grammar.py`, `scoring.py`), `gideon/evaluation/` (`evalset.py`, `results.py`, `slices.py`, `extraction_slice.py`, `judge.py`, `judge_slice.py`, `window.py`, `record.py`, `reference.py`, `reference_command.py`, `command.py`), `tools/variants/`, and the directories `eval/sets/eval-v1/` and `eval/reference/`, each in the Inventory with its tests. The map is [`../ARCHI.md`](../ARCHI.md); its §8 table names every command's leaf.

## Commands

- **`eval run --slice <name> [--set <dir>]`** (§18.6; `evaluation/command.py` over the modules above, `_guarded` behind `cli.py`): `load` → `run` → `record` → `gate` for an engine-free slice, with a `preconditions` stage between `load` and `run` for one whose registry entry reaches the engine; the gate's verdict is the exit code. The slice is looked up in `slices.py`'s registry, an unregistered name refusing; the spec's `repeats` and `judge_prompt` are copied into the run context, so a runner declares neither. `preconditions` stops at the first refusal, each printing its fix: root, the no-GPU marker (a refusal, not `engine verify`'s skip, since nothing here is gated on by install), the site file, **the quiet window** (outside it, the local time and weekday, the fix naming the next opening and that `--force` lands with slice-2 ticket 16), the engine's target through [`engine-frontend.md`](engine-frontend.md)'s shared helper, and — unless `--set` was given — everything `record` can refuse on that does not need the run: the git provenance and the writer role's connection probe. Its guarantee is exactly that and no wider: the probe proves the role connects, not that the insert will succeed, so a write that fails after the run is still reported at `record`. `load` reads the court map and the set (the release's `eval/sets/eval-v1/` unless `--set` names another), prints the version, the case count, the slice's count, and the digest, and on any finding prints them all and refuses. `run` evaluates the slice's active cases through its registered runner and prints the scorer's report. `record` writes one run row and one result row per active case in one transaction as `gideon_eval`: it is skipped, without failing the command, for a set outside the release (`--set`) and for an unreachable database (the probe's problem and "rows were not written" in the row), and refuses when the site file, the git provenance, or the write itself fails. The run row carries the product version, the set version, the hardware profile, `stack=production`, `kind=manual`, the slice, the spec's `repeats`, the checkout's `git_sha` and `git_dirty` — both read under a `safe.directory` grant, both null only where the checkout root has no `.git` — the set digest, and the verdict; each result row carries its `repeat`, its judge field or SQL `NULL`, and a latency that is `NULL` where the grading's request never returned. `--decision` and `--force` refuse as not implemented (slice-2 ticket 16). For a slice whose spec compares (ruling 5 of slice-2 ticket 06), between `run` and `record` the slice's reference is read from the release checkout — whatever `--set` names, so a planted regression is provable — and compared with the run's per-case verdicts folded over repeats; the block prints one `reference: <outcome>` line from the closed vocabulary, the reference's tag and version, and one line of ids per non-empty list. `record` then receives the whole gate's verdict, and the composed gate row carries both halves and the fix of whichever failed, the bounds' first when both do. The `gate` stage is two functions read by the tripwire, each against its own attribute list: the slice's own gate reads the slice result's verdict and the spec's three texts and nothing else, and the reference gate reads beyond them the comparison alone. Invariants: rows are insert-only and content-free but for the judge's reason (ADR-0048), and written after the run and before the gate's row; a run of the release's own set is recorded whatever its verdict; **the judge grades and never gates** — the slice's verdict is one code-computed bool, a score and everything derived from it live in `judge`, and no `metrics` key at any depth names a judge fact (ADR-0023); a comparing run prints exactly one `reference:` line and one that stops earlier prints none, so its absence reads as a stop, while a non-comparing slice prints none at all; a refusal fails the gate *after* `record`, since the first run of a new set version is the one its reference is written from; no reference for the slice leaves the slice's own gate deciding alone and the exit code unchanged, and staleness never touches it.
- **`eval reference --run <run id>`** (§18.6, ruling (a) of slice-2 ticket 05; `evaluation/reference_command.py`, `_guarded` behind `cli.py`): `load` → `read` → `check` → `write`, stopping at the first refusal, every refusal printing its fix. `read` is one statement as the metrics role over the Postgres container's socket. `check` is the Inventory row's conditions; its regression refusal names repairing the case or superseding it, and the deliberate, diff-visible act that accepts a loss — removing every reference file of the slice — and a malformed current reference refuses the write with the restore-or-remove fix, never the writer's own line. Invariants: nothing is written to Postgres; the run and the write may be in different checkouts, the run's any clean one at the tag and the write's the development checkout whose committed set has the same digest; a list with no evaluated case still gets its file, so the partition is total; the write is idempotent, reporting `unchanged` for equal bytes, and repairs an interrupted ownership hand-back on every run.
- **`python3 -m tools.variants <parents> <variants> [--series <file>] [--series-file <file>] [--sheet | --write --reviewer <id> --on <date>]`** (§18.2; a development tool, never shipped and never imported by `gideon/`): with neither mode it *checks* — every committed variant re-derived from its parent line by line, a missing pair the exit code. `--sheet` prints the pairs for the human read; `--write` appends them, and only then, carrying the reviewer id and date it is given. Invariants: an axis edit is applied to the labelled objects alone and a variant that cannot preserve its parent's labels is refused rather than written; the ids come from the whole series, which `series.txt` beside the cases names, and a `--write` whose manifest names a file it cannot see refuses rather than mint an id twice.

## Release constants by module

- `gideon/extraction/contract.py` — the type vocabulary and its keyed and section-like subsets; a type is never renamed.
- `gideon/extraction/grammar.py` — the grammar's version, the pattern registry, the bare-section cue list, and the appendix compilations' table; a pattern whose behaviour changes takes its next `@N`, and the version moves with any pattern.
- `gideon/extraction/scoring.py` — the gate's two bounds (§11.2).
- `gideon/evaluation/evalset.py` — the eval set version and its root, the shape registry, and the id, cluster, role, query-type, and variant-axis patterns; a set version is never edited, a later version is a new directory.
- `gideon/evaluation/judgments.py` — the judgments file's relative name under a set root, the line's ordered key tuple, the grade scale's bounds, and the attorney-role pattern (a subset of `evalset.py`'s role pattern); a key is never renamed and a landed grade never edited.
- `tools/variants/axes.py` — the axis registry, each axis versioned `<name>@<N>`, and the types an axis respells; an axis whose edit changes takes its next `@N`, and a committed variant keeps the version it was written under.
- `gideon/evaluation/reference.py` — the format number, the file's key vocabulary, the two verdict words, the closed outcome vocabulary the release's check reads, and the `eval/reference/<slice>/<list>.json` path rule; the format number moves only when the file's shape does, and a landed reference is re-recorded whole, never edited.
- `gideon/evaluation/judge.py` — the closed failure-mode vocabulary, the verdict schema and its reason bound, the token reserve and the request bound (ADR-0017 starting values, sized from the engine's structured check), the prompt registry keyed `name@N`, and each registered version's pinned digest; a prompt whose text or schema changes takes its next `@N` and a new digest, and an edit under the same id is red.
- `gideon/evaluation/slices.py` — the slice registry and its spec's fields; a slice naming a prompt the judge's registry does not hold, or keeping a reference while its spec does not compare, is a test failure.
- `gideon/evaluation/window.py` — §18.5's quiet-window hours and its weekend days.
- `gideon/evaluation/record.py` — the writer role and the reader role, the database, and the Postgres service name, each equal to [`stack.md`](stack.md)'s; the run row's `kind` vocabulary (`smoke`, `nightly`, `weekly-off`, `decision`, `candidate`, `engine-verify`, `manual`) and its `stack` vocabulary (`production`, `ci`).
