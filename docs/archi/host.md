## Commands

- **`host provision`** (§1.5, `provision.py`): a `Step` declares `name`, `summary`, `needs_site`, `requires`, `gpu_host_only`, and `build_box_only`, a `check() -> CheckResult` (a `Disposition` `converged/drift/unfixable/pending-input/reboot-required`, detail, fix, `halts_run`), and an `apply()` that may return an **announcement** printed once after the `applied` row. The runner applies only on `drift` and re-checks; outcomes `ok/applied/would-apply/blocked/reboot-required/skipped/failed`; a failed prerequisite skips its dependants; `needs_site` steps are `blocked` without a site file; exit 0 iff nothing `failed`; `--no-gpu` and `--build-box` declare the mode before any step. No step touches `subprocess` or the filesystem — everything goes through `Host`, which is what lets tests replay ticket 28's recorded baseline. The `docker-engine` step owns two files, `/etc/docker/daemon.json` and `/etc/containerd/config.toml`, each compared whole and rewritten on drift, containerd restarted before Docker when its file changed; a populated package-default root beside an empty desired root is `unfixable` in check and a refusal in apply, both naming the move, so provision never abandons a store (ADR-0040) — presence read from the snapshotter's `snapshots` and the content store's `blobs/sha256` directories, never from the metadata database containerd creates at every start; the desired text's configuration version is the installed containerd's own (4 at `v0.1.61`, where ADR-0040 wrote 3). A populated store moves once, by hand, in an announced window, by the stages of `.scratch/slice-1/assets/73-store-move.sh` — survey, stop, copy, verify, provision, check, accept, remove, with rollback beside them, each refused without the previous stage's stamp — the transcript `73-on-box.txt` beside it.
- **`preflight`** (§1.5, `preflight.py`): check-only, never halts; refuses outright without root, the locks, the egress allowlist, the court map, or a valid site file. Phase A reuses `provision.check_step` over `STEPS` — converged → `pass`, else `refuse` with the step's own fix (total convergence, ticket 02 ruling 1), a `gpu_host_only` step `skipped` on a no-GPU host and a `build_box_only` step `skipped` on a host that is not the build box. Phase B walks `CHECKS`, each a `PreflightCheck` returning a `CheckReport` with `Severity` `pass/warn/refuse/inert` — `inert` for judgments whose data has not shipped, and no registered check returns it since `v0.2.5`; `hardware-profile` and `data-volume` judge the selected profile's `requires` block as minimums and are `pass — skipped` rows on a no-GPU host (ADR-0035). Exit 0 iff no `refuse`.

## The locks

Repo root; edited by people or the pin watch's bump pull requests only; their comments stay true for any value, and no pin value is restated here or in any test module.

- `host.lock` (`host/lock.py`) pins `os_lts`, `kernel_tested`, the driver branch and its on-box-converged `tested` version, the Docker/Compose/toolkit minimums, the registry image digest (ADR-0029), the GH-runner release, the acceptance-VM image, and the reference box's controller/VD facts.
- `images.lock` (`host/images.py`) pins the Compose images in two kinds. A **mirrored** pin records the upstream tag and the OCI index digest it resolved to (SearXNG's tag is a date and a commit hash, the pin watch's second tag shape — [`tools.md`](tools.md)). A **built** pin (`postgres`, `gideon`) records the Dockerfile directory, the mirrored base and its digest, the build arguments with the upstream each is watched at — an apt index and package, or a PyPI project by its PEP 503 normalized name alone (`pypi_project`), one kind per entry — `inputs_digest` (sha256 over those inputs and the Dockerfile bytes, recomputed by a hosted test so an un-rebuilt bump is red), and the pushed `digest` — `unbuilt` until the first build, a state the committed lock refuses.
- `models.lock` (`host/models.py`) pins the hardware profiles (§1.1) and names the `reference` build: per profile a `requires` block preflight checks as minimums and the model set — each model by Hugging Face repo, revision, and every regular file's digest and size, its GPU index, and the `serve` baseline render emits. The pin watch ([`tools.md`](tools.md), slice-0 ticket 14) patches every scalar above a model's `files` value-only and regenerates `files` whole from the Hub's listing at the new revision; a bump that changes a role's total bytes while a memory row names the role is a proposal. The **memory table** (§7.6, slice-1 ticket 19): one row per Compose service the stack knows on any host, keyed by the service's name under `SERVICE_NAME`'s grammar, each a whole number of decimal gigabytes (`GIGABYTE` the one unit) and, on a service that loads a model, the role it depends on — the subject of the pin watch's size-change rule — validated collect-all like `requires`, its errors naming this leaf as every lock refusal does; render is its one consumer ([`render-apply.md`](render-apply.md)); the figures are E9's starting values, each row's basis and the measure's query in the lock's comment, which also records that the kernel keeps a cgroup limit in whole pages. The chunk guards (§7.7) arrive with `index build` (slice-1 ticket 58).

## Configuration

- **The site model** (`gideon/host/site.py`): `FIELD_REGISTRY` declares every leaf once, required or defaulted. `load_site()` returns a fully-defaulted `SiteConfig` or a collect-all list of `SiteError`s whose refusals end in their fix. The three group leaves accept a CN or a full DN; `site.group_name()` recovers the CN the frontend matches `memberOf` against. A leaf whose value is an office value — a machine, a network, a directory object, a mailbox, an account — carries `office_value` on its `FieldSpec`, the one list the evidence redaction ([`tools.md`](tools.md)) and the office-values tripwire read; `load_site_text()` runs the same chain over a rendered document's text. `web.engines` is held to the six names of `site.WEB_ENGINE_VALUES` (each the pinned SearXNG's engine name; a repeated name, and an empty list while `web.search` is on, refused) and `web.domain_filter` to bare lowercase domain names (`site.DOMAIN_NAME`; a leading `!`, a scheme, or a dotted address refused, since the frontend reads those as a block rule or a network), the schema carrying both as the items' enum and pattern (slice-1 ticket 15). The same registry generates `config/site.schema.json` (§3.4) via `site_schema.py`; a drift test pins the bytes. Cross-artifact checks live in preflight: `hardware_profile` is selected from `models.lock` by `models.select_profile`, the one rule preflight and render share, and `jurisdiction` is held to `courts.yaml`: every id resolves at its leaf's level (`circuit` → `circuit`, `districts` → `district`, `states` → `state_supreme`, a state expanding by its USPS code to its `state_supreme` and `state_appellate` courts), an absent id refused with the nearest of that level and a wrong level refused naming both; the rules over a corpus lockfile's `courts[]` wait behind `JurisdictionCheck`'s `lockfile_courts` seam for slice 3's first lockfile.
- **Host state that is not configuration** (ADR-0028, ADR-0035): `/etc/gideon/no-gpu` and `/etc/gideon/build-box`, the exclusive host modes read through `host/nogpu.py` by every later command — no site key and no flag on any command but `host provision --no-gpu` or `host provision --build-box`; and `/etc/gideon/backup_age_identity`, the box's own backup identity, minted once and never printed, excluded from every set beside the markers (ADR-0042). The plain-registry rule is the other keyless fact: `images.is_plain_registry` names loopback and the libvirt bridge (`LIBVIRT_BRIDGE_CIDR`, its one home) as the two plain-HTTP registries, and every TLS-verify switch in the code follows it.
- **The other committed artifacts**: `config/egress.yaml` (§2.3, `host/egress.py`) — allowlist groups, `image-build` probed by the build tool and never by preflight, since an office never builds; its image-build hosts include PyPI's `pypi.org` and `files.pythonhosted.org` beside the apt hosts; `models pull` holds every host a fetch traverses to the `install-upgrade` group and prints an uncovered one; `images.lock` (§2.2, `host/images.py`), whose built pins are the only place a build input lives — a build argument is release content and an image label, so the loader refuses one named like a secret; `models.lock` (§1.1, §2.2, `host/models.py`) — the hardware profiles and their model pins (§4's list), the one place a model fact lives, a serve `env` name refused the same way; `courts.yaml` (§2.2, §8.6, `host/courts.py`) — generated by [`tools.md`](tools.md)'s court map generator and never hand-edited, its `source` block the CSV's file, date, hash, and per-level counts; the loader owns the closed vocabularies (`LEVELS`, `CIRCUITS`, `STATES`), and its every refusal says to restore the file from the release checkout, never to regenerate it on a box.
