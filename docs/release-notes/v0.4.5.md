# GIDEON v0.4.5

Template: 5

## What is new

Nothing in this release changes what users see. It continues the Legal chat's
answer service, which only the project's own evaluation can call so far.

The service now declines a question when it finds nothing that supports an
answer, and the decision is made by the service's own code before the model is
asked anything. Every passage it found is scored for how well it matches the
question, and passages that score below a fixed level are set aside unless the
question cited them by name. When no passage remains, the service sends a fixed
notice as its whole reply: it says that nothing in GIDEON's corpus supports an
answer, names the case law it searched and its date, names any court the
question asked about that the corpus does not hold, and suggests rephrasing.
No model writes or alters that notice. When only one or two passages remain,
the service still answers, and the model is told that its support is thin. The
reply and the service's own record of the question both state which of the
three cases applied. The level that decides this is a starting value, which a
later evaluation will tune.

Every question the service admits now leaves a row in the audit log once its
reply has been sent. The row names who asked, in which chat, over which
knowledge bases, which passages were returned by their identifiers, and how the
question ended, and it holds no question or answer text. A new host command
reads the audit log by knowledge base, by user, or by chat over a span of
office time, so whether GIDEON showed anyone a given document can be answered
from identifiers alone.

The project's evaluation can now send its questions to an index that has been
built but is not yet in use, and the two research suites now carry a pass mark.
With these, the evaluation compared passages cut to two different lengths and
read whole answers for the first time. The comparison did not favour the
shorter cut, so the current length stays and the trial index of shorter
passages was removed.

The upgrade adds no database change and no setting, and the office has nothing
to change.

## Trial profile

The trial profile `1x32v-120d` is for a one-card office. It needs one card with
32 GB of memory, either an NVIDIA RTX PRO 4500 Blackwell or an NVIDIA GeForce
RTX 5090, plus 120 GB of host memory and 600 GB of data storage. How the
GeForce RTX 5090's driver behaves and how containers reach it have not yet been
checked. The profile serves the generator `google/gemma-4-12B-it-qat-w4a16-ct`
and the embedder `Qwen/Qwen3-Embedding-0.6B`, whose vectors are their own space,
`qwen3-embedding-0-6b-1024-bf16`, never the reference's. The generator reads up
to 262,144 tokens and the embedder up to 4,096. The embedder shares the
generator's card, and no card memory is set aside for another application. Its
corpus line covers the Supreme Court alone.

The profile was evaluated on the project's own card, capped to the trial's
share of memory: `general-smoke` run `27b852e5-46d3-41b8-a01d-90871b49a680`,
`judge-triples` run `9bd08f25-3d99-4ad1-9bfe-7d47bf4937f8`, and `guardrails`
run `a8c9fae2-01fc-42eb-8333-dc2ca169ede4`, each passing. Neither admitted card
has been evaluated yet. This profile's quality claim rests on these runs, never
on the reference's. No office installs it before v1.0.0.
