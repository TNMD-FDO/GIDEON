# GIDEON v0.4.4

## What is new

Nothing in this release changes what users see. It continues the Legal chat's
answer service, which only the project's own evaluation can call so far.

The service now chooses which passages the model reads, and in what order.
Every passage the question cited by name is kept. Beside those, twenty more are
picked by how well they match the question, with five places held for the
courts whose decisions bind the office and no more than three passages from any
one document. The chosen passages are put in order by match and by the weight
their court carries, and the set is kept within a fixed reading length by
dropping whole passages from the bottom. The written instructions the model
will answer from, and the file that records every setting that shapes an
answer, are built and tested; the live service starts using those instructions
in a later release.

The service can now admit a signed-in user, not only the evaluation's own
account. It checks the user's sign-in with the chat server on every request,
and checks again that the user may read each knowledge base the request names.
Any doubt refuses the question. A refused request that names a knowledge base
is written to the audit log before the refusal is sent. The sign-in itself is
never stored or written to any log.

The service now reports five timing measures for monitoring: how long the
search takes, how long the service takes up to re-scoring, how many requests
wait for re-scoring, the time to the answer's first paragraph, and the time to
the whole answer. It also counts questions by how they ended. The project's
evaluation gains two research suites that send each test question through the
whole service and grade the passages it found and used.

The upgrade adds no database change and no setting, and the office has nothing
to change.

## Trial profile

The trial profile `1x32v-120d` is for a one-card office. It needs one card with
32 GB of memory, either an NVIDIA RTX PRO 4500 Blackwell or an NVIDIA GeForce
RTX 5090, plus 120 GB of host memory and 600 GB of data storage. How the
GeForce RTX 5090's driver behaves and how containers reach it have not yet been
checked. The profile serves the generator `google/gemma-4-12B-it-qat-w4a16-ct`
and the embedder `Qwen/Qwen3-Embedding-0.6B`, whose vectors are their own space,
`qwen3-embedding-0-6b-1024-bf16`, never the reference's. The generator reads up
to 262,144 tokens and the embedder up to 4,096. The embedder shares the
generator's card, and no card memory is set aside for another application. Its
corpus line covers the Supreme Court alone.

The profile was evaluated on the project's own card, capped to the trial's
share of memory: `general-smoke` run `27b852e5-46d3-41b8-a01d-90871b49a680`,
`judge-triples` run `9bd08f25-3d99-4ad1-9bfe-7d47bf4937f8`, and `guardrails`
run `a8c9fae2-01fc-42eb-8333-dc2ca169ede4`, each passing. Neither admitted card
has been evaluated yet. This profile's quality claim rests on these runs, never
on the reference's. No office installs it before v1.0.0.
