# GIDEON v0.4.3

## What is new

Nothing in this release changes what users see. It extends the Legal chat's
search, which only the project's own evaluation can call so far. Besides the
searches over all installed case law, the search now runs one more that is
limited to the courts whose decisions bind the office: the Supreme Court, the
home circuit, and the home districts and states named in the site file. The
best twenty passages from that search keep places in the candidate list, so
binding law is not crowded out by persuasive law. Every candidate passage is
labelled with the weight its court carries for the office, such as the home
circuit's published opinions or persuasive authority from elsewhere. The label
is worked out from the court and the opinion's published status each time, and
neither search index stores it. When a question names a court, every search is
limited to that court, and a named court whose decisions are not installed is
reported as not in the corpus. The court is recognised by matching the names
the server's court list holds, so no model decides the scope. A reranker then
re-scores the top forty candidates, together with every passage placed at the
top because the question cited it, so the most relevant passages are read
first.

Each question the search accepts now writes one record of how it was handled:
its timings, the passages found and their order, the passages used for the
answer, and the versions in use. The record holds none of the question's or
the answer's text. The evaluation can now read a whole answer from the search,
not only the passages it found.

The upgrade adds this record's database table and gives the search a file of
court names that the server's setup writes from the installed case law.
Nothing new needs downloading, and the office has nothing to change.

## Trial profile

The trial profile `1x32v-120d` is for a one-card office. It needs one card with
32 GB of memory, either an NVIDIA RTX PRO 4500 Blackwell or an NVIDIA GeForce
RTX 5090, plus 120 GB of host memory and 600 GB of data storage. How the
GeForce RTX 5090's driver behaves and how containers reach it have not yet been
checked. The profile serves the generator `google/gemma-4-12B-it-qat-w4a16-ct`
and the embedder `Qwen/Qwen3-Embedding-0.6B`, whose vectors are their own space,
`qwen3-embedding-0-6b-1024-bf16`, never the reference's. The generator reads up
to 262,144 tokens and the embedder up to 4,096. The embedder shares the
generator's card, and no card memory is set aside for another application. Its
corpus line covers the Supreme Court alone.

The profile was evaluated on the project's own card, capped to the trial's
share of memory: `general-smoke` run `27b852e5-46d3-41b8-a01d-90871b49a680`,
`judge-triples` run `9bd08f25-3d99-4ad1-9bfe-7d47bf4937f8`, and `guardrails`
run `a8c9fae2-01fc-42eb-8333-dc2ca169ede4`, each passing. Neither admitted card
has been evaluated yet. This profile's quality claim rests on these runs, never
on the reference's. No office installs it before v1.0.0.
