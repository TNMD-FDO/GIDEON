# The judge's reason is the one model-written text an eval result row carries

ADR-0027 makes a kept event content-free — ids, codes, and figures, never a user's words — while [21] item 16 puts the judge's `reason` in `eval_results.judge`, and slice-2 ticket 06 is the cycle where the two meet. The maintainer's ruling at its claim: **the reason is stored** (ruling (c)), and the exception is drawn as narrowly as it can be. The reason is about an evaluation case, never a user's turn: an eval case is committed, invented or harvested text that no person typed into the product, and the row that carries a grading of one is written only by `gideon_eval` from `eval run`. It is bounded by the verdict's schema before code ever sees it and whitespace-collapsed to one line by code, so it cannot grow into a transcript. Everything else stays as ADR-0027 has it: a refusal, a progress line, a report, a finding, and every `repr` — including those of the grading and of both result types, which redact it — carry lengths and digests and never the text, and the committed on-box transcript proves the round trip by length and SHA-256 prefix alone.

**Rejected:** dropping the reason and keeping the score — ADR-0023 makes the judge a grader whose number no gate reads, so a score with no reason is a number nobody can audit, and the synthesis panel's whole job is to read the reasons beside the answers; storing it outside Postgres, in a file beside the run — a second store for one field, with its own retention, ownership, and export question, to avoid a column the migration has held since `0004`; hashing or truncating it in the row — an unreadable reason is the same as no reason for the panel, and the schema's bound already does the sizing; widening ADR-0027 to "model-written text is content-free enough" — the rule's value is that it is absolute for user-facing tables, and the narrow carve-out here names the table, the writer, and the subject rather than softening the rule.

**Consequences:** `eval_results` is the one kept-event table whose rows are not wholly content-free, and its leaf ([`../archi/eval.md`](../archi/eval.md)) says so in those words; the recorder's `psql` binding had to become backslash-safe in the same cycle, since the reason is the first value a row has carried that can hold a backslash or a non-ASCII character; the metrics role's read of a recorded run selects neither `metrics` nor `judge`, so the ordinary read-back path still cannot print one; and a later table that wants model-written text — slice 4's `turn_log` among them — does not inherit this, but argues its own case against ADR-0027 as this one did.
