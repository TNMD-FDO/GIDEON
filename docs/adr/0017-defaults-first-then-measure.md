# Defaults first, then measure: a starting value is an upstream default or a cited research finding; every decision names the metric that judges it or the reason it has none; every LLM-touching piece has an `off` state that is its eval baseline

Tickets 10, 13, and 14 each restated a posture inherited from the ticket before, and it drifted a little each time; this records it once, for every remaining ticket on the greenfield map and for the spec that collapses it. A figure a decision ships with is a **starting value**: it comes from the upstream default of the model, engine, or pinned image, or from a cited research note, and is corrected on the 1 % sample or the first full generation — never by argument in the ticket. Every decision ends with exactly one tag naming its judge: `E-nn` (a configuration experiment, registered in ticket 21 and judged by the eval set), `M-nn` (a runtime measure, registered in ticket 22 and observed on the running box), or `exempt: <reason>` (an exempt decision that neither can judge). A decision without a tag is not resolved; the gate applies at resolve time and again when the spec is generated. Every LLM-touching piece has an `off` state, and `off` is the eval baseline it is judged against. Three words that had blurred into one slogan mean three things: *evaluatable* — the eval set judges it; *measurable* — a runtime measure judges it; *testable* — a test at a code seam in CI. The map binds the first two; testability arrives with the spec and its tickets, because a map produces decisions, not code. Greenfield-spec map, Aug 2026.

**Rejected:** shipping a figure because it seemed right, or because experience or an uncited benchmark said so — unfalsifiable on this corpus and this box, and the first thing a later CSA would "fix" without knowing why; shipping research-note recommendations as final rather than as starting values — the same problem one step removed; binding testability from the map — demands something the map cannot deliver; retro-sweeping tickets 02–09 for untagged figures — the spec reads every decision anyway and is the right place to catch a stray; carrying a one-line pointer to this ADR in each ticket — the restatement this ADR exists to stop, only shorter.

**Consequences:** a corrected starting value is a configuration change gated by the eval set, never an edit to the resolved ticket, which stays as history; ticket 21 owns the E-register and ticket 22 the M-register (ticket 12's E9 — RSS budgets and lexical p95 — is by this definition a runtime measure and may be reclassified at spec time); a future ticket carries no restatement of this posture — criterion 5 in the map's Notes is the inheritance and the tags on each decision are the evidence; the rule is this effort's, recorded in the map, not a repo-wide tracker convention; the first release may be less tuned than judgment could have made it, paid back by every later change being an eval win rather than an opinion.
