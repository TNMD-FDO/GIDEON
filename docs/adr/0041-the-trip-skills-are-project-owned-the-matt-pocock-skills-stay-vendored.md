# The TRIP skills are project-owned, forked from TRIP-workflow v2.8.0; the Matt Pocock skills stay vendored under the pin watch

ADR-0033 treated the fourteen TRIP-workflow skills as upstream files: GIDEON's rules confined to marked `GIDEON:begin` blocks under a byte ceiling and to TRIP-init's slots, a tripwire hashing every non-slot skill around its blocks and holding a block table, a provenance line, and a routing line, a six-step three-way merge per upgrade, and a pin proposing each upstream release. The lifecycle audit of 2026-09-12 (`.scratch/workflow/assets/42-lifecycle-audit.md`, finding S2) found the premise gone: the three skills carrying every customisation were among the five slot skills the hash rule skipped, at about twice their pristine size (`TRIP-1-plan` 23,089 bytes against 11,580, `TRIP-3-release` 19,649 against 6,597); the skills were edited on twelve days in three weeks and upgraded twice, each upgrade a manual merge; the TRIP pin never proposed anything; the ceiling made the pointer documents that then needed budgets and compactions; and five open tickets existed only to keep the vendoring honest. **The decision: the TRIP and Codex skills are project-owned — forked from `PiLastDigit/TRIP-workflow` v2.8.0, the pristine bytes the `vendor:` commits in this repository's history, edited like any document, their block markers, ceiling, table, routing line, upgrade recipe, tripwire rules, and pin removed, `docs/agents/tooling.md` §2 naming the fork's tag; when upstream publishes a release its diff is read and what helps is taken by hand as a docs commit. The twenty-five Matt Pocock skills stay vendored as ADR-0033 left them: unmodified, in `skills-lock.json`, refreshed whole by the CLI and proven against a clone, watched by the `skills.matt-pocock` pin, held to the lock by the tripwire's remaining rules.** This supersedes ADR-0033's TRIP half; its Matt Pocock half and its completion rule stand. Workflow ticket 42, Sept 2026.

**Rejected:** keeping the blocks and extending the hash rule to the slot skills with a slot-filled baseline (workflow ticket 41 — every rule change would still touch a block, a table row, and a document, and the drift the hash would measure is the intended state); shrinking the blocks to pointers (workflow ticket 39 — the pointer documents are what the ceiling created); a pin on the fork's upstream with no merge behind it (a proposal nobody completes is the notice ADR-0031 rejected); forking the Matt Pocock skills too (they are unmodified, the CLI refreshes them for nothing, and the clone check costs one command).

**Consequences:** `tests/test_skills_vendored.py` hashes the lock's entries whole and reads no table or routing line; the `Routing:` line and the two later skills' `model:` and `effort:` frontmatter leave, the launcher's table being the pairing's one home; the pin watch reads four records and carries one skill pin, whose proposal is green from the start as before; standing ticket 19 observes the Matt Pocock proposal alone; workflow tickets 36, 39, and 41 lose their block halves; a rule for a TRIP phase is written in the skill and described nowhere else (`docs/ARCHI-rules.md`'s one-home list), its detail in a document under `docs/agents/` the skill points at; and the next upstream release is a reading, not a merge.
