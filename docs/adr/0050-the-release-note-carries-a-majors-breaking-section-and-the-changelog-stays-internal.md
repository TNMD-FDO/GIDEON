# The release note carries a major's Breaking section, and the changelog stays internal

The changelog under `docs/2-changelog/` is the engineering record of the product's development, and slice-1 ticket 87 ruled it internal: the public export omits it. Until then `gideon upgrade` read a major's `## Breaking` section from the target tag's changelog (spec §2.1, greenfield [05] item 7), so omitting the directory would have made a public clone cross a major in silence. The decision, ruled at ticket 87's triage and landed in `v0.2.34`: **the release note is the one document `upgrade` reads a major's `## Breaking` section from.** The section is optional at a minor or patch and required in a major's note (`vX.0.0`, X ≥ 1), held by the note contract before the tag. It is written for the office's CSA who reads it at the `version` stage. At a cross, `upgrade` prints, from the target tag's tree, the section of every crossed major's note and of the target's own note. The root `CHANGELOG.md` stays public: its lines link the release note from `v0.2.0` and name the tag as text below it. The spec is not edited; the dated comment on greenfield [05] records that its "CHANGELOG's Breaking section" is superseded.

**Rejected:** keeping a fallback reader for the changelog at a tag without a note, because a lower tag refuses before the reader runs, so from a 0.2.x box every major-cross target is `v1.0.0` or later and carries a note; the fallback could never run and would keep an omitted path named in the product package. Also rejected: exporting the changelog, because it cites tickets, `.scratch/`, and the agent documents, and the public tree should not read as the development record.

**Consequences:** a major's release note is no longer optional user-facing prose alone; it is an operator contract the note test enforces. The release tooling (`bin/release-git`) refuses to write the index line when the release's note is absent.
