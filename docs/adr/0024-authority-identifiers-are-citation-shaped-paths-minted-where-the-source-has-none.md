# Authority identifiers are citation-shaped paths, minted by GIDEON where the source has no stable one

Every authority needs one permanent key that ties its versions together across instruments, that the `authority_version(id, date?)` tool takes, and that an exact object extracted from a question resolves to; it must survive every amendment and every change in how the source publishes. Where the source already publishes such a key GIDEON adopts it — the USLM identifier path (`/us/usc/t18/s3583`, `/us/usc/t18a/courtRules/Crim/rule41`, `/us/usc/t18a/pl/96/456/s4`) is stable across release points. Where it does not, GIDEON **mints a citation-shaped path** of its own — `ussg/2B1.1`, `cfr/21/1308.11`, `rules/2254/rule6` — because the sources' own ids are positional (govinfo's `NODE="21:9.0.1.1.9.0.29.4"` can shift when a section is inserted ahead of it), date-templated (the eCFR API's `/on/2026-08-24/title-21/section-1308.11` names a snapshot, not the section), regenerated on every publication (USLM's `id` GUID), or absent (the Sentencing Commission's HTML and the uscourts.gov PDFs). The citation is the one name every source, every court, and every attorney already agree on, so a key derived from it is stable by construction and legible in a log. Greenfield-spec tickets 19 and 25, Aug 2026.

**Rejected:** source ids as keys (three schemes for one concept, one of them unstable, one of them dated); opaque surrogate keys (a UUID per authority hides the very identity a citation renderer and a log reader need, and still requires a citation-shaped lookup table beside it).

**Consequences:** every source id is kept as an attribute on the document for traceability, never as the key; the citation renderer derives the rendered form from the key plus a small per-source prefix table (`courtRules/<Set>` → `Fed. R. Crim. P.` …, `cfr/<t>/<s>` → `<t> C.F.R. § <s>`), so a source changing its id scheme never touches the record; a section that is renumbered gets a new key and a `successor_id`, exactly as a consolidated guideline does.
