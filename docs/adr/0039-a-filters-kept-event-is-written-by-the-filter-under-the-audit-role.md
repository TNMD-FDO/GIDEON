# A Filter's kept event is written by the Filter itself, under the audit role, over the Compose network

**Superseded 2026-09-22 at `v0.2.29`** by [ADR-0045](0045-gideon-owns-generals-turn-and-the-frontend-is-its-client.md), as this decision's own rejected alternative foresaw ("when the `/turn` service owns a turn it may take the write over, and that would be a supersession of this decision, not an edit of it"). General's API service writes the guardrail trip's row and holds the audit role's secret; the frontend is no longer that password's consumer, so a rotation of it no longer recreates the frontend, and the Filter's one non-standard-library import left the frontend with the Filter. The row, the table, the `source` word, the silent failure, and the detector stand. The decision's text below is unedited, the record of what ran until this tag.

ADR-0027 makes a guardrail trip a kept event — a content-free row in the record, never a log line — and in this slice no GIDEON service runs beside the frontend, so the only process that sees a trip is the arithmetic guardrail's Filter inside Open WebUI's container. The Filter therefore writes the row itself: the inlet stashes the branch and a one-word source (`eval` for the eval identity, else `user`) on the request's state, the stream hook records at the trip and the outlet only for a trip of its own judgement, and `record_trip` builds the five-column row and hands it to a daemon thread that opens one connection through the pinned image's own Postgres driver (`psycopg` 3, a main dependency of Open WebUI v0.11.3) as `gideon_audit`, the INSERT-only role, with the password read from a Compose secret mount, ensures the month's partition, and inserts — every failure at every step dropped, nothing logged. The table is `guardrail_trips`, its own migration in the audit log's partition shape, because the audit log's required columns (a run id, the product release) are facts a Filter inside the frontend cannot honestly supply. Slice-1 ticket 11, Sept 2026.

**Rejected:** a structured journal line promoted to rows when a service lands (ADR-0027 says a log line is never the place a fact of record lives, and the ticket's own criterion forbids any log, journal, or audit file carrying the trip); the frontend's own database session (it is bound to the `openwebui` database as the schema-owning role, so the row would land in the wrong database under a role that could edit it, and Postgres has no cross-database write); an HTTP call to a GIDEON service (none exists before slice 4; when the `/turn` service owns a turn it may take the write over, and that would be a supersession of this decision, not an edit of it); the audit log with a new `kind` (placeholders in required columns); a user id on the row for filtering the eval identity's deliberate trips (a per-person record, which [07] item 13 rules out — the source word answers the same need).

**Consequences:** the Filter holds one non-standard-library import, lazy and guarded inside the writer, and its hygiene test states that exception by name — module-level imports stay stdlib, so the file still loads by path in the tests and inside the container without a requirements line; the frontend becomes a consumer of the audit role's password through its Compose `secrets:` list, so a rotation of that password recreates the frontend, and the apply that added the mount recreated every service once because the top-level secrets map moved; the write runs off the event loop thread, so the stream hook never waits on the database and a failed write never blocks or alters the refusal; a failed write is silent by design, and the detector is the Overview board's age of the eval identity's last deliberate trip, which every `engine verify` (install, upgrade, rollback) refreshes — not a log line; the record is made in the stream hook at the trip, so a Stop before the outlet loses nothing and each trip is one row on the browser path and the API path alike (ticket 52's ruling (d), landed here); the eval identity is one account for every session on the box, and two proofs making turns at once share the frontend's chat listing (the proof rules' §3).
