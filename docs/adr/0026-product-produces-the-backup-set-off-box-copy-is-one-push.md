# The product produces the backup set; the off-box copy is one push to a site-chosen target

GIDEON's backup is a product command, not a site's backup tool pointed at the server. `gideon backup run` produces one consistent backup set in `/data/backup-staging` — the content-addressed store first, then Postgres through pgBackRest with continuous WAL archiving, then configuration, the release registry, and Open WebUI's uploads, under one manifest — and `gideon backup push` copies that directory to a site-chosen SSH target with a single `rsync`, keeping dated hard-linked snapshots there. The product owns consistency, ordering, the manifest, the restore, and the drill; the only thing that differs per office is where the push lands. Nothing is encrypted client-side — the target's at-rest protection is the site's — and no monthly tier exists: 7 days local, 30 nightly off-box. Greenfield-spec ticket 22, Aug 2026.

**Rejected:** running the office NAS's own agent on the server (Synology Active Backup for Business — block-level, crash-consistent, Ubuntu ≤ 24.04 / kernel ≤ 6.14 officially; the community-patched agent that builds on newer kernels puts a one-maintainer snapshot kernel module on the box that holds every matter and re-breaks on kernel security updates); moving the OS pin to 24.04 to stay inside the agent's support (a shorter OS life, HWE kernel drift reproducing the same problem, a two-tool restore path, and the building office running a backup path the product never ships); restic (encrypts unconditionally, so the office's "no client-side encryption" ruling excludes it) and borg (no SFTP or S3 backend); `pg_dumpall` (no point-in-time recovery, slow replay at 150 GB).

**Consequences:** a receiving office needs an SSH-reachable path and nothing else, and can put the NAS-side versioning of its choice behind it — TNMD's Synology steps (a plain rsync account, snapshots of the share) ship as guidance, never as a requirement; the drill restores from the staging directory and the off-box check verifies the remote copy separately, so a NAS that quietly stopped receiving is found on the drill's interval rather than during a disaster; the off-box copy is reachable from the server, so a compromised server can reach it — NAS-side snapshots are the recommended answer; the vector index is not in the set, so total-loss recovery of Research costs a rebuild whose measured time (M24) decides whether a weekly Qdrant snapshot joins the push.
