# New upstream versions are noticed by a pin watch in hosted CI; the box never phones home and an upgrade is always a release

Every component a release runs is pinned by digest or version in a lock file (`images.lock`, `host.lock`, `models.lock`, the corpus lockfiles), and spec §2.1–2.2 make an upgrade an explicit tagged release that install and upgrade pull byte-for-byte. What the spec never assigned was the *noticing*: how a CSA learns that Open WebUI, vLLM, Caddy, Postgres, or a driver has a new version. The first frontend release answered it by accident — Open WebUI's built-in update check put a "new version available" banner in front of every user, an egress to GitHub from the box outside the §2.3 allowlist and a nudge to upgrade outside the release discipline — and v0.0.11 turned it off. **The decision: a pin watch runs in hosted CI, off the box, compares every pin's upstream source against its latest published version, and opens one pull request per bump carrying the new tag and digest; the pull request runs the hosted checks, a merge runs the box's mirror and contract jobs, and a human tags the release.** Components never check for their own updates, on the box or in the images, and users are never told a newer version exists. Slice-0 ticket 05 (the banner) and ticket 10 (the watch), Sep 2026.

**Rejected:** the components' own update checks (the wrong audience, an unlisted egress, and an invitation to upgrade one container by hand); Dependabot (it does not read the lock files' shape); a human "check the release pages monthly" line in the calendar (the one mechanism guaranteed to lapse); auto-merging bump pull requests (a bump is a release decision with a contract suite and a release note behind it — §17.5 runs the Open WebUI contract suite on every frontend pin bump for exactly this reason).

**Consequences:** the watch is a repository concern (a Renovate configuration with custom managers for the lock files, or a scheduled workflow) and adds nothing to the product or the box; every bump is visible as a pull request with its CI verdict before anyone decides; the box's egress stays the versioned allowlist; the operational calendar (§19.6) gains "review open bump pull requests" beside the weekly corpus upstream watch, which stays a separate, on-box job with a different subject.
