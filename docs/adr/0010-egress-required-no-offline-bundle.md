# Egress required at install and upgrade; no offline bundle

GIDEON's "fully local" promise is that client and case data never leave the box — not that the box never reaches the internet. A release is a git tag plus lockfiles, and every byte it pins (container images, model weights, corpus source files) is fetched from the network at install, at every upgrade, and at every corpus install, verified against the lockfiles; preflight probes a versioned egress allowlist and refuses to proceed if any required host is unreachable. The air-gap bundle planned in ticket 05 is withdrawn: maintaining a 100 GB+ per-release artifact on the office file share is a cost TNMD will not carry, and the intent is that receiving offices rebuild from the upstream sources every release pins rather than receive a copy of what is on TNMD's server. Offices whose servers have no egress are unsupported.

**Consequences:** every image in `images.lock` — GIDEON-built and upstream alike, the latter mirrored by digest — is served from one **release registry** the project controls (the loopback registry before 1.0, public GHCR under the office organization from 1.0), so an office allowlists one image host and no supported tag can be broken by an upstream retag, deletion, or pull limit. Models and corpus files come from their upstream sources at the pinned revision or date; TNMD keeps a **source archive** of those upstream files as insurance and, if an upstream disappears, republishes them under the office organization and repins the next patch release — never a second install path. The office proxy, where one exists, is a single optional `egress_proxy` setting rendered into every component that downloads. The release acceptance test is a clean-VM install with real downloads on every tag. Greenfield-spec ticket 29, Aug 2026; supersedes the bundle decisions of ticket 05.
