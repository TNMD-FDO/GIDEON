# Case law is acquired only from whole-database bulk snapshots; freshness is a labelled, measured lag

GIDEON's case law comes from CourtListener's quarterly whole-database dump and from nothing else. Every corpus lockfile pins one dump by URL, sha256, and size; a refresh is a full local diff of the new dump against the record (new, changed by text hash, gone, unchanged), never a stream of increments. The corpus is therefore up to about four months behind the courts at every promote, and the product says so everywhere it matters: the retrieval provenance line, the abstention notice, and the Research preset's coverage line all carry the lockfile date, and a cited case newer than the snapshot is reported as an out-of-corpus object rather than filled from memory. The lag is measured — post-snapshot demand, the count of exact objects users cite that postdate the live snapshot — and that measure, not an argument, is what would justify a between-dump path. Greenfield-spec ticket 18, Aug 2026.

**Rejected:** the CourtListener REST API as an acquisition or incremental path — it requires authentication, is throttled at 5 per minute, 50 per hour, and 125 per day, exposes deletions and merges only as a redirect on re-fetching a known id, and offers no feed of changes, so a delta consumer would carry a second acquisition model, its own reconciliation logic, and a corpus whose bytes cannot be pinned or rebuilt elsewhere; court-website scrapers, for the same reasons and one more parser per court.

**Consequences:** the only way to be fresher is a new dump, so the quarterly cut is the corpus's heartbeat and the eval triple names it; a receiving office rebuilds exactly the same corpus from the same pinned dump; the recorded escape hatch is an append-only slip path for the home courts alone (authenticated token, `date_created` cursor within the daily budget, layered on the quarterly snapshot, reconciled by the next dump), built only if post-snapshot demand shows users need it; the source archive keeps every pinned dump because CourtListener's retention of old dumps is observed, not promised.
