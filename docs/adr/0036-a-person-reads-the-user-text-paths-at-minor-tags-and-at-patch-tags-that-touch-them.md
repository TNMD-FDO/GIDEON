# Agent-written code is read by a person on the paths that carry user text, at minor tags and at patch tags that touch them; everywhere else the proof and the two-model review are the check

Every line of GIDEON is written by an agent — 40,106 across `gideon` and `tools` at `v0.1.28`, delegated to Codex batch by batch — and read before it ships by two other agents and a proof: the requesting Claude session's delta review of each batch (`TRIP-2-implement` §3), which fixes directly and leaves no record; the Codex code review of the whole diff, a second model of the implementer's vendor, whose synthesis is promoted to `docs/3-code-review/` at the release; the testing gate and CI; the on-box proof and its transcript; the acceptance run at minor tags (ADR-0035); and, from slice 2, the eval gates and the synthesis panel, an attorney reading a sample of graded answers each release (ADR-0023). A person is in the cycle at the triage ruling, the plan's approval (a plan carries no code), the on-box proof, and the commit and push questions, and at none of them reads the diff. Workflow ticket 13 asked whether that is a posture or a property nobody chose. The evidence, read at its triage: of the 44 promoted reviews, 23 returned at least one behavioural defect the delta review had passed — eleven security-relevant, a secret in process arguments three times among them — and 18 were clean; and three defects both agent reads passed were found on the box (`v0.1.6`'s key in argv, `v0.1.9`'s base-model read grant, `v0.1.27`'s stale attachment). Each layer keeps finding what the layer before it left, and none reads the user's sentence as a user would. The decision: from `v0.2.0`, **a person reads the diff of the paths that carry user text or a refusal** — the Filter sources under the compose tree, the frontend's render and record modules (the preset, its prompt, the abstention notice), the release note, and the tests holding their seeds — at every minor tag, over the change since the previous minor tag, and at a patch or hotfix tag whose diff touches those paths, over the change since the previous tag. The read is those paths' diff and never the whole release's: a person reading a large diff of unfamiliar agent-written code catches style and shape more reliably than defects, and the read's value is what the text says to the user. The changelog entry records what the read found, or that it found nothing; a read not made holds the tag, as an unwritten release note does (spec §21; the `user-facing-tag-check` block). Everywhere else the check is the layers above, unchanged. The residual, named: a patch tag outside those paths reaches TNMD's users with no human read of its code; a hotfix carries no second-model review (ten of 54 tags through `v0.1.28`, 14 to 212 changed lines each); the delta review's catches are unrecorded, the implementation thread's state holding its last turn alone; the reader is the person who directed the sessions, a second human look and not an independent one until `v1.0.0` opens the repository; and the code review reads no test for its quality ("Do not review test code quality", upstream's prompt), so a tests batch the implementation thread authors under `TRIP-2-implement`'s `testing-gate-delegated` block is read for quality by the delta review alone, against the plan's Test Impact — the door stays open per cycle, that residual with it. Workflow ticket 13, Sept 2026.

**Rejected:** the status quo recorded as the decision (no layer reads user text as a user, and a reviewer of a public 1.0 would ask who reads the diff and find no answer); a person reading every release's diff (54 tags in eight days, a median of 622 changed lines per tag across `gideon`, `tools`, and `tests` and a maximum of 9,763 — the cadence ADR-0035 already declined a by-hand pass for); the whole diff at user-facing tags (24,767 insertions across the 0.1 series against 2,396 changed lines over the four user-text files; a read bounded by the paths is a read that is made); closing ticket 08's door and returning test authoring to the requester (the safeguards held at `v0.1.22`, and the cost is the requester's context every cycle); a second-model review added to the hotfix skill (the skill stays pristine and a rule for it is CLAUDE.md's; the read above covers a hotfix on the user-text paths, and the rest is the residual).

**Consequences:** `TRIP-3-release`'s `user-facing-tag-check` block carries the read as a summary and a pointer to this record, within workflow ticket 11's ceiling; CLAUDE.md's hotfix rule extends it to a hotfix tag, the line in its changelog entry beside the Window answer; `docs/agents/onboarding.md` (workflow ticket 14) states the posture as a rule; the path set is named by mechanism, so a module that renders user text joins the read when its plan's Files list says it does; a finding the read makes is fixed before the tag or recorded on the ticket as a review finding is; the delta review's missing record and the hotfix's missing review are observations for the outstanding-items step, not this record's to fix.
