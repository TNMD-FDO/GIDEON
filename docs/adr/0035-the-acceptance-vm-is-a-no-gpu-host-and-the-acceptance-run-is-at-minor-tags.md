# The acceptance VM is a no-GPU host, and the acceptance run is at minor tags

Spec §2.5 and [29] item 12 want the receiving-office sequence proven on a clean KVM virtual machine on the build box, in a `--no-gpu` mode, with real downloads; §22.1 makes "two CSAs can deploy, back up, restore, and roll back" the slice's done-when. When slice-0 ticket 08 planned that run, three things had no home in the code: nothing could run without a GPU (render refused without `nvidia-smi`, the GPU exporter and its scrape job were unconditional, preflight refused without the pinned driver), nothing recorded a mode for the later commands to inherit, and the build box's three roles (`kvm`, `registry`, `gh-runner`) sat in every host's target state though none can converge inside a VM on the box's own bridge. The decision: the no-GPU declaration is **host state**, written once by `host provision --no-gpu` (refused when an NVIDIA device is present — a broken driver must refuse, never degrade) into `/etc/gideon/no-gpu`, which every later command reads through one module; the five GPU-host-only steps — the driver, the toolkit, and the three build-box roles — are skipped together under it, and the engine's exporter, scrape job, board, and drift rule are not rendered; the marker is excluded from every backup set so a restore never moves it between hosts. The acceptance harness is repository tooling over the same seam (`python3 -m tools.acceptance <ref>`), the VM its no-GPU host, and the harness's pass at a **minor tag** — by TRIP-3 against the local tag before the push, then by a tag-triggered self-hosted job — is the proof of §22.1, superseding both §2.5's "every tag" (a run per patch tag is not sustainable at the current cadence) and §22.1's by-hand pass (a CSA with other duties cannot spend hours per incremental version); the ticket records both rulings as supersessions. Slice-0 ticket 08, `F_0.1.0`, Sept 2026.

**Rejected:** a site key for the host's role (ADR-0028 forbids product behaviour in the site file, and the record is what the later commands need, not the operator's intent); a `--no-gpu` flag on provision, preflight, and install each (three places to forget one, and `upgrade`'s children could inherit nothing); converging the build-box roles inside the VM (nested libvirt on the box's bridge subnet, a runner token per run, and a registry the VM has no reason to serve — how a receiving office's host declares it is not the build box at 1.0 is ticket 21); a by-hand two-CSA pass per tag as the done-when; a harness that pulls the release from GitHub (the VM would hold a credential; a bare mirror of the box's checkout, copied into the image, proves unpushed candidates too).

**Consequences:** a GPU host without a driver refuses render and apply naming both ways out (`host provision --only nvidia-driver`, or `--no-gpu` on a host without a GPU); leaving the mode is removing the marker and re-provisioning, after which the next apply renders the removed files as new — a mode change moves through the existing stale-and-new classification, never a special path; the run itself found and fixed six defects the box had hidden (the firewall's `DOCKER-USER` scope, empty apt lists on a fresh image, strict X.509 for the throwaway CA, apply judging every lock pin, the restore's empty-root verify, and a restore following the wrong timeline after two promotions), which is the argument for running it: at every minor tag, unattended, in about six minutes on TNMD's box; the clean-VM full restore stays a follow-on (ticket 20), and the tag-triggered job's trust is a repository ruleset on `v*` tags, not anything in the tag's tree.
**Amended 2026-09-16 (`v0.1.68`, slice-0 ticket 21):** the five host steps no longer share the no-GPU gate: `nvidia-driver` and `nvidia-toolkit` are GPU-host-only, while `kvm`, `registry`, and `gh-runner` are build-box-only and converge only on the host declared with `host provision --build-box` into `/etc/gideon/build-box`; a receiving office declares neither, and no site key replaces the host state. The build-box marker is absent-only, exclusive with `/etc/gideon/no-gpu`, and excluded from every backup set. Leaving the mode is removing the marker, re-running provision, then applying; the KVM, registry, and runner units remain until removed by hand. The decision itself is unchanged.
