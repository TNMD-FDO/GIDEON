# Site configuration states the office's facts and policies, never the product's behaviour

The distribution promise is "edit one file, run one script," and the draft addendum read that as a tuning surface: it exposed the abstention floor, the hierarchy weights, model names, and branch toggles in the site file so a receiving office could adjust GIDEON to taste. Every retrieval, generation, and citation ticket then ruled the opposite, one knob at a time. The rule those rulings share: a site key exists only where TNMD cannot know the value for another office — its name, network, directory, home courts, backup target, alert routing — or where the office is entitled to a policy — chat retention, prompt logging, whether General may search the web. Anything that changes what an eval measures is a release artifact selected by the hardware profile, and an office that wants it different asks for a release. The site file therefore contains no path and no secret either: supplied files have fixed homes, and secrets are files named by convention. Greenfield-spec ticket 23, Aug 2026.

**Rejected:** exposing `retrieval.min_score` and `hierarchy_weights` as "the two knobs offices will want" (a site-tuned floor or weight is a configuration the eval never ran, so the release gates would certify something no office runs); model names resolving against `models.lock` (the hardware profile already selects the evaluated set, and a name is a substitution nobody evaluated); branch on/off toggles (a branch exists when its preset ships); path keys (a typed path is an error surface the fixed layout removes).

**Consequences:** the file is short — twelve required lines for an office that follows the runbook — and every line is checkable in preflight against something real (a directory bind, an SSH login, a court list, an SMTP relay); removing a key is a major version, so keys are added late and reluctantly; a request to "make X configurable" is answered by asking which office fact X is, and if it is none, by a release; the rendered configuration is a pure function of this file and the release, so two offices on the same tag with the same site file run byte-identical stacks.
