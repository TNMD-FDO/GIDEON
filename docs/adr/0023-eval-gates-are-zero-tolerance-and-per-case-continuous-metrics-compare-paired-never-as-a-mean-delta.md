# Eval gates are zero-tolerance categories and per-case regressions; continuous metrics compare paired against a reference run, never as a delta on a mean; the judge grades but never gates

The draft eval design gated merges on "recall@10 ≥ baseline − 2 % over a 20-question smoke set". Miller 2024 (arXiv:2411.00640) shows that at that sample size a 2-point delta is indistinguishable from run-to-run noise, that repeating cases buys at most a 2/3 variance reduction (mostly reached by K ≈ 4–6), and that the one large free win is paired per-case analysis; a delta-on-a-mean gate would therefore block and pass changes at random. GIDEON's gates are instead of two kinds. **Zero-tolerance categories** — citation precision 1.00, fabrication 0, pincite precision 1.00, `section-attribution`, `lookup` rank-1, `edition`, `treatment`, `unanswerable → none`, `deadline-trap` positives — are computed by code from the retrieval record and the rendered answer, hold on every repeat, and one failure blocks. **Per-case regressions** — no case that passed in the reference run may fail — catch what a mean hides. Continuous metrics (nDCG@10, recall@k, span grounding, false refusal, jurisdiction error, boilerplate saturation, latency) are **reported** on every run and **compared paired** (per-case differences, CLT standard error clustered by source document, 95 % CI) against the reference run or the `off` baseline: a release is blocked only when the CI lies wholly below zero, and a configuration experiment wins only when the CI excludes zero — so most experiments will end "no detectable difference, keep the default", which is ADR-0017's intent. The LLM judge scores synthesis quality, abstention wording, and premise correction with a reference answer in the prompt at temperature 0; it is never the source of a zero-tolerance number and is itself audited by an attorney panel every release. Greenfield-spec ticket 21, Aug 2026.

**Rejected:** the addendum's "− 2 % on 20 questions" gate (statistically empty); lowering the system-under-test's temperature to shrink variance (Miller: it moves the mean and can triple the irreducible term); a flat "run each case 3–5 times" rule (no primary source; K is the weak lever, n is the strong one); letting the judge gate anything (a model checking a model, self-preference bias when judge and generator are the same checkpoint); an eval framework (Inspect AI, promptfoo, DeepEval, RAGAS, lm-eval-harness — none lighter than a plain-Python harness for this job, and none ships a regression gate anyway).

**Consequences:** a smoke set stays small (≤ 15 min) because it carries only zero-tolerance cases and the regression list; decision runs need N = 5 repeats and a weekend window; growing the eval set is the way to make an experiment decidable, so a category whose CI is too wide grows in the next eval set version; a change that helps by a little will not be adopted, by design.
