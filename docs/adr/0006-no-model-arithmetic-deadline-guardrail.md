# No model arithmetic; filing deadlines hard-blocked in code

GIDEON never presents a number a language model computed: a result is either produced by deterministic code or not produced at all. The first and only code-enforced instance in v1 is the **deadline guardrail** — GIDEON never asserts or confirms a filing deadline (AEDPA §2244(d)/§2255(f), notice of appeal, cert, Speedy Trial, limitations on offenses, any other) on any branch, while answering *how* a limitations period works freely. Enforcement is a bounded-regex Filter on the model's output, run inside the token stream with a lag window so text renders live but a matched span never reaches the screen; on a hit the whole response is replaced by a fixed refusal that defers to a person. Other computations (Guidelines ranges, sentence credit, day-counts) are refused by instruction and checked by eval in v1, not by code, because no reliable detector exists for them.

**Rejected:** a deterministic deadline calculator. Its inputs — finality date, whether a state filing was "properly filed," which periods were pending, equitable tolling — are legal judgments, not facts; a calculator that takes them as parameters gives false precision with a machine's authority, which is worse than a model guessing because it looks trustworthy. Also rejected: a model classifier in the guardrail (a guardrail that can be talked around is a prompt, not code) and an inlet-side block (a request containing dates and deadline vocabulary is usually a legitimate doctrinal question; only the answer reveals a computation).

**Consequences:** guardrail patterns must be bounded (no unbounded gaps between a date and deadline language) so the lag window is sound; the serving engine connects to Open WebUI as a Chat Completions endpoint (Responses-API connections rebuild the message from full-text events and undo stream edits); the Filter keeps per-request state on `__metadata__`, never on the shared Filter instance; the refusal is a versioned product artifact with no site-config field; every trip is logged content-free (branch, timestamp, pattern id). Greenfield-spec ticket 07, Aug 2026.

**Amended 2026-09-10 (`v0.1.45`, slice-1 ticket 42; ticket 31's ruling of 2026-09-05):** the deadline guardrail is the rule's first code-enforced instance, not its only one. A Sentencing Guidelines range the model resolves — a level and a category to a months range, a range placed on the matter, or the user's figures affirmed — is arithmetic under the rule too, because a language model has no table, only a memory of one, and a cell it recalls on request is a lookup it cannot make with 100 % accuracy; the "no reliable detector" reason above is withdrawn for the range, whose bounded detector draws its line on the answer between a range resolved and a range restated, and stands for sentence credit and for sums of money, percentages, and quantities until their tickets rule (slice-1 tickets 70 and 33). The families are judged in order, each with its own pattern ids, seed, refusal, and pattern-set version, and every trip's row names its family. The decision itself is unchanged.

**Amended 2026-09-10 (`v0.1.55`, slice-1 ticket 70; ticket 32's ruling of 2026-09-09):** sentence credit is the rule's third code-enforced instance. A release date, a credit count, or a time to serve the model computes on a matter's facts — or a supplied release date or credit it affirms — is arithmetic under the rule too: the Bureau of Prisons' sentence computation is the only authority for when a person is released, and a date given wrong reaches a client as a promise. The "no reliable detector" reason above is withdrawn for sentence credit, whose bounded detector draws its line on the answer by tense and voice — a figure computed in the present, future, or conditional trips; an authority's past-tense fact, a statute's or the Bureau's rate or cap, a proposed term in advocacy, and the user's own figure under a governing construction or echoed with a determiner pass — and stands for sums of money, percentages, and quantities (slice-1 ticket 33's ruling). A family judged earlier may hand a shape to a later one by a bounded exclusion on its own patterns, never by a second judgement order, and a later family's confirmation context may displace an earlier one's; the deadline family gave up a sentence's expiry, the last day of a sentence, a credit-shaped day count, and a release-date confirmation this way, its patterns and its seed's verdicts unchanged. The decision itself is unchanged.

**Amended 2026-09-17 (`v<x.y.z>`, slice-1 ticket 52):** the consequence that a trip discards the rest of an answer the engine goes on generating is narrowed to the direct branch. On the browser path the stream hook now ends the turn from inside itself: on the first chunk after the trip's that still carries a generating choice, and only when the request's metadata carries the frontend's task id, the hook requests cancellation of the asyncio task it is running in — the frontend's own Stop path — and drops that chunk, so the engine's connection closes and it aborts the request at its next scheduler step. The stored and painted message is therefore what was released: the clean prefix, the separator, and the refusal. Prefix-then-refusal is doctrine, not a leak — the released prefix never held a matched span — and no event the hook can emit would make the stored message the refusal alone, so the outlet's whole replacement stands for a trip the outlet finds itself and for the direct branch, which generates to its end. The cost this removes is the whole remaining generation of an answer nobody sees, on the one shared generator (ADR-0009). The decision itself is unchanged.
