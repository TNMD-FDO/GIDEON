# The shared daemon's image store lives on the Docker volume: containerd's root is a setting the `docker-engine` step owns, and a populated store is moved by hand in an announced window, never by provision

Docker Engine 29 keeps images through the containerd image store: every image, layer, and build-cache entry lives under containerd's own root, which the package installs at `/var/lib/containerd`, and the daemon's `data-root` — the one storage value the `docker-engine` step writes into `daemon.json` — holds the daemon's metadata, networks, and volumes and nothing that grows with a pull or a build. The runbook's §1.4 layout gives every box a 600 GB logical volume mounted at `/var/lib/docker` for exactly that growth, and the `disk-layout` step asserts it as the installer's; on the box on 2026-09-09 that volume held 12 MB while the store held 160 GB of the 196 GB root filesystem, both projects' images and Transcribe's build cache, and a build filled the root filesystem with the journal, a plan review, and a worktree edit in it (slice-1 ticket 73). The decision: **containerd's root is a directory on the Docker volume, written by the `docker-engine` step into `/etc/containerd/config.toml` as it writes `daemon.json`** — configuration version 3, `root = "/var/lib/docker/containerd"`, the directory dockerd itself gives containerd's root when it supervises containerd, the CRI plugin disabled as the package ships it, the state directory untouched under `/run` — compared whole, rewritten on drift, containerd and then Docker restarted when it changed, the step requiring `disk-layout` as before so the volume is there. **Provision never abandons a populated store:** when the package-default root holds containerd's metadata database and the desired root holds none, the check is unfixable and the apply refuses, both naming the migration, because a daemon started over an empty root finds none of the snapshots its containers run on and every image of both projects is gone until re-pulled or rebuilt. A fresh host converges before its first image; a box with a store moves it once, by hand, in a maintenance window announced under the box ledger's §8 — both daemons stopped, the root copied with ownership, hard links, ACLs, device nodes, and extended attributes preserved (the overlay snapshotter's whiteouts are device nodes and its opaque markers `trusted.overlay.*` attributes), verified by a second pass, the file written by provision, both stacks back by their restart policies with their image and container lists unchanged, the old root removed. The volume sized for Docker then holds Docker's images, and the root filesystem holds the operating system. Slice-1 ticket 73, Sept 2026.

**Rejected:** a new logical volume from the OS volume group's unallocated space mounted at containerd's default root (no containerd setting to own, but the runbook's layout and the `disk-layout` step's reinstall posture change for every office, and the Docker volume stays empty); a bind mount in the `disk-layout` step's fstab block (a second mechanism, and a mount ordering, for a path one configuration line names); the classic overlay2 store under `data-root` (every image of both projects re-pulled or rebuilt for a store Docker 29 no longer defaults to, the acceptance VM's included); provision performing the migration itself (a stop of both projects' stacks and a copy of a hundred gigabytes inside a step that is otherwise idempotent and quick, run on a live box by a command whose other steps do not stop anything).

**Consequences:** the `docker-engine` step owns two files and restarts two daemons; the acceptance run at `v0.2.0` proves the fresh-host path; the box's move is the cycle's on-box step and precedes `v0.2.0`, since after it every Docker restart is a user-facing window; the box ledger's §2, §5, and §6 rows and its open item 3 change at that release with Transcribe's agreement; a page-class rule over the root filesystem and the Docker volume (slice-1 ticket 74) is the floor the ledger's 40 GB rule lacked; the glossary carries the term; a superseded pin's image stays in the store after a bump until something removes it, an observation the store's size now makes cheap.
